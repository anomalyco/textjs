# ▼ Text.js Architecture & Engineering Specification

**Text.js** (`textjs.org`) is **"The Console Framework for the Web"** — a React 19 & App Router web framework whose entire UI renders inside browser DevTools `console.log` statements via a custom React reconciler, Yoga WASM Flexbox layout, and Run-Length Encoded `%c` CSS framebuffers.

## Brand & Design Identity
- **Brand Mark:** `▼` (`U+25BC` BLACK DOWN-POINTING TRIANGLE) — an inverted play on Vercel's `▲`. Where traditional frameworks render *up* into the DOM, Text.js Inverted Architecture™ streams frames *down* (`▼`) into the DevTools Console drawer. Never use `▲` as the Text.js logo; always use `▼`.
- **Engine Name:** **Turbolog** (`▼ Text.js 0.4.0 (Turbolog)`).
- **JSX Casing:** **PascalCase** components (`<Box>`, `<Text>`, `<ScrollBox>`, `<Input>`, `<Textarea>`, `<Select>`, `<Tabs>`, `<Link>`, `<Code>`, `<Markdown>`, `<Diff>`, `<Modal>`, `<Spinner>`, `<AsciiFont>`, `<Spacer>`, `<Badge>`, `<Divider>`) matching Next.js / React conventions, backed by clean lowercase host intrinsic elements (`tx-box`, `tx-text`, `tx-raw-text`) inside the custom React reconciler.

## Non-Negotiable Rendering & Performance Contracts
1. **Strictly ONE `console.log` Call Per Dirty Frame, Appended (Zero-Flash Swap):**
   - Never log line-by-line (which creates ugly DevTools row borders, `(2)` repeat badges, and 30× CDP IPC overhead).
   - Every dirty frame emits **one** `console.log(formatString, ...cssArgs)` with rows joined by `\n`, appended below the previous frame. DevTools applies `console.clear()` synchronously but paints new messages on a 50ms throttle (`ConsoleView.viewportThrottler`), so clearing per frame flashes an empty console under load. Appending lets stick-to-bottom scrolling swap frames inside one paint.
   - A leading zero-width "curtain" span (`%c\u200b%c\n`, resetting `%c` to `""` before `\n`) applies `margin-top:100vh` once without repeating it onto row 0, and ends its own line so DevTools' right-floated source link (`VM12:1`) never narrows the frame's first row. Identical forced frames alternate a zero-width tail so DevTools never collapses them behind a repeat badge.
   - `console.clear()` runs only on the first frame, after `invalidate()`, and to release old frames (first frame after 1s idle once 100 frames are stacked, hard cap 300).
   - **Frame pacing & post-clear phase-lock avoidance:** emitted frames are ≥66ms apart (~15fps). Faster frames restart DevTools' 50ms `Throttler`, so they are dropped and add latency. After any frame that calls `console.clear()`, DevTools' synthetic `"Console was cleared"` row consumes the throttler's immediate slot and pushes the frame onto a 50ms timer (`lastCompleteTime ≈ t_emit + 52ms`); `ConsoleRenderer` waits ≥110ms once after a clear so subsequent frames satisfy `now - lastCompleteTime > 50ms` and lock onto DevTools' 0ms fast path (~10ms display lag instead of ~63ms). Discrete input still renders synchronously when the interval allows.
2. **Damage-Band Partial Repaint & Zero-Noop-Log Dirty Gate:**
   - `SceneNode` tracks row-level damage bands (`_damageLo`/`_damageHi`) across leaf text and style mutations, updating in-place row leaf widths without dirtying Yoga WASM when geometry cannot shift, and scissor-repainting only damaged row bands in `paintScene`.
   - `CellBuffer` caches per-row 32-bit FNV-1a hashes (`getRowHashes()`), re-hashing only rows written since the last frame and sharing cached hashes with `extractStyledFrame`.
   - If zero cells changed since the previous committed frame, **zero strings or arrays are allocated (`0 B/frame`), `console.clear()` is not called, and `console.log()` is not called**. Idle CPU and DevTools churn are strictly zero; `<Spinner>`, cursor blink, and scheduled frames pause while the page is unfocused or hidden (`document.visibilityState === "hidden"`).
3. **Row-Level RLE Caching, Zero-Phantom-Span Newlines & Precompiled Row Assembly:**
   - `CellBuffer` stores flat TypedArrays (`chars: Uint32Array` + grapheme overflow table for multi-codepoint emojis/ZWJ, `fg: Uint32Array` packed `0xRRGGBBAA`, `bg: Uint32Array` packed `0xRRGGBBAA`, `attrs: Uint16Array` bitmask).
   - Only rows whose hash changed since the last frame re-scan cells into RLE spans; interior row spans are pre-joined into reusable `midFormat`/`midArgs` fragments.
   - Adjacent spans across `\n` boundaries with identical styles merge into a single `%c` span. Unmerged `\n` row breaks reset `%c` to `""` so DevTools emits a plain text newline instead of splitting `"...\n"` into a phantom empty `contain: paint; display: inline-block` `<span>` `PaintLayer`.
   - CSS style strings are interned with integer `styleId`s and a 1,024-entry L1 TypedArray `(fg, bg, attrs)` cache so hot-path compilation allocates zero `BigInt` keys or repeated CSS strings.
   - **Longhand-only CSS:** DevTools copies every *longhand* of a `%c` style onto every line wrapper, so shorthands (`font:`, `margin:`, `padding:`, `text-decoration:`) cost ~33 properties per span. Spans use `font-family:"SF Mono",Menlo,Consolas,monospace` (dropping `ui-monospace`, which Blink does not implement) plus `font-size`/`line-height`/`margin-top`/`margin-bottom` and hex colors (`#rrggbbaa` when translucent).
4. **Chromium `ConsoleViewMessage.ts` Edge-Case Defenses:**
   - **Escape `%` as `%%`:** Every literal `%` in cell text must be escaped as `%%` in the `console.log` format string so user text like `"100%"` or `"%s"` never consumes a `%c` style argument.
   - **Suppress URL Auto-Linkifier Style Hijacking:** Chromium's `_applyForcedVisibleStyle` injects `!important` theme colors onto URLs inside `%c` spans. Insert `\u2060` (word joiner) after `://` (`https:\u2060//`), in `www.`, `data:` and `path:line` / `//host:port` (DevTools' `pathLineRegex`) unless the cell carries the `ALLOW_LINK` attribute flag.
   - **Seamless Multi-Row Background Fills:** Calibrate `font-family`, `font-size`, `line-height`, and `margin` on `%c` spans so `display: inline-block` spans across `<br>` lines have zero vertical pixel gaps between background colors.
   - **Unfocused / Hidden Freeze (Copy/Select Support):** When `document.hasFocus()` is `false` or the tab is hidden, freeze blinking cursors into a static tinted cell and stop `<Spinner>` timers so `console.log()` / `console.clear()` never fire while the user highlights and copies text inside DevTools Console.

## Monorepo Package Structure
- `packages/core` (`@textjs/core`): `CellBuffer`, `RGBA` alpha blending, `TextMeasure` (`Intl.Segmenter` + East Asian/Emoji width + LRU wrap cache), `Yoga` WASM layout tree (`pointScaleFactor = 1`, scissor culling, `zIndex`), `CssConsoleDriver`, `AnsiDriver`, `DomMirror` frame snapshotter, `InputEngine` (hidden `<textarea>` sink for keyboard, `⌘V` paste, IME, and `wheel` scroll forwarding), `ViewportController` (fixed + responsive docked DevTools sizing + `window.text` console REPL API).
- `packages/react` (`@textjs/react`): Custom React 19 reconciler (`react-reconciler@0.34.0`), `rAF` commit scheduler, dual styling (`props` + memoized `className` cell-Tailwind utilities + `ThemeProvider`), full PascalCase TUI component kit, hooks (`useInput`, `useFocus`, `useFocusManager`, `useViewport`, `useTheme`, `useConsoleStats`), and `<FocusPad />` DOM receiver (open-the-console / click-here / live states with per-app key hints).
- `packages/text` (`@textjs/next`): File-system `app/` Router (`layout.tsx`, `page.tsx`, `[param]/page.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx`, `api/*/route.ts`) synced with `window.location` / `history.pushState`, `text dev` / `text build` / `text start` CLI powered by Vite + React Fast Refresh, in-console `[▼]` DevTools inspector overlay (`Ctrl+\``), and in-console Redbox error boundary.
- `packages/create-text-app` (`create-text-app`): CLI project generator (`starter`, `dashboard`, `opencode` templates).
- `apps/opencode-console`: Connected OpenCode Lite TUI running in `console.log` against a local `opencode` server (with `opencode service status` auto-discovery proxy in local dev + rich interactive simulation fallback for static web previews).
- `apps/web`: Official `textjs.org` website — marketing landing page, live interactive real-DevTools `console.log` companion app when visitors press `⌘⌥J` (one view per page, no in-console navigation), full-screen focus-pad Playground (`/playground`, demo picker; `/showcase` redirects here) and OpenCode (`/opencode`) pages that render no TUI on the page, and full documentation (`/docs/...`).

## Console Sizing (`ViewportController`)
- **Responsive by default** for `text dev` apps and the site companion. The page can't read the console's size, only its own window: a docked panel shrinks `innerWidth` (side) or `innerHeight` (bottom) while `outer*` stays put. Page zoom scales `inner*` (CSS px) but not `outer*` (DIPs), so each dock hypothesis solves for one of Chrome's preset zoom levels and the best fit wins.
- **Measured constants** (real DevTools frontend, DevTools zoom 100%): frames wrap unless the console is ≥ 52–55px wider than the frame (`consolePaddingX = 56`, plus the page's classic-scrollbar width); vertical chrome is tab strip 27 + console toolbar 28 + prompt/padding ~47 (`consoleChromeY = 104`). The console toolbar wraps onto a 2nd row below ~545px and a 3rd below ~330px (+26px each). Row pitch is 14px.
- **Browser chrome height** (needed for bottom docks) is learned whenever DevTools isn't bottom-docked (`outerHeight - innerHeight`) and remembered in `localStorage` (`textjs:browser-chrome`); until then 120px is assumed (slightly over, so frames err a row short).
- **Not observable from the page:** undocked DevTools (separate window), DevTools' own zoom, the Console sidebar, and the Console opened as a drawer under another panel. These use the fallback size (`viewport.width × height`, default `120×36`) or a pinned size (`text.resize()`, or the pads' "Console size" control, persisted as `textjs:viewport`).
- Window resizes are debounced (100ms trailing); opening, closing or moving DevTools applies immediately. Resizing never clears the console (frames are appended).
