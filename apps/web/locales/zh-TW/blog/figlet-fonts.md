Text.js 0.3 新增了 `@textjs/font`，用來解析與渲染 FIGlet 字型。套件隨附 FIGlet 2.2.5 發行版中的 17 種字型，每種各自是一個 ES 模組，輸出與 `figlet` 2.2.5 二進位檔完全一致。

<!-- s:ffc9f0eae5 -->
為何選用 FIGlet

<!-- s:3ff2fd01df -->
`<AsciiFont>` 自 0.1 起就內建 `block` 和 `compact` 兩種字體樣式。FIGlet 自 1991 年起就是這類字體樣式的標準，已有數百種 `.flf` 字型。支援這個格式，就能將其中任何一種用於主控台應用程式。

<!-- s:7fdbff5714 -->
FIGlet 字型是一個純文字檔案。標頭列設定高度、硬空白字元與版面配置規則，接著將每個字元繪製成由多列組成的區塊，每列末尾都有結束標記。在預設版面配置中，FIGlet 將每個字元向左移動，直到碰到前一個字元，再依字型的合併規則，決定是否將兩個相接的子字元合而為一。

<!-- s:4c761bba4d -->
版面配置模式

<!-- s:3f1c38cf92 -->
`figlet` 有五種水平版面配置，`renderFiglet` 也透過 `layout` 接受相同的五種配置：

<!-- s:51f1b95b8f -->
| `layout` | `figlet` | 效果 |
| :-- | :-- | :-- |
| `"default"` | `-s` | 字型本身的版面配置，通常會合併相接字元 |
| `"full"` | `-W` | 完整寬度；字元不會相接 |
| `"fitted"` | `-k` | 字元彼此靠近，直到相接 |
| `"smushed"` | `-S` | 依字型規則合併相接字元 |
| `"universal"` | `-o` | 後面的字元覆蓋前面的字元 |

<!-- s:7a1307992e -->
-1 到 63 的數字代表原始 `-m` 版面配置模式：`-1` 為完整寬度，`0` 為緊密排列，`1` 到 `63` 則選擇合併規則。六種水平合併規則皆已實作：相同字元、底線、層級、相對配對、大 X 與硬空白。解析器也處理格式的其餘部分：註解列、以十進位、八進位和十六進位代碼標記的字元、缺字字形，以及 `ivrit` 等由右至左的字型。

<!-- s:0c920c94d3 -->
換行也遵循 FIGlet 的行為。`width` 會在單字邊界換行，當單字比行寬還長時，則在單字內換行，位置與 `figlet -w` 相同。`figlet -w 80` 最多輸出 79 欄，因此 `-w N` 對應到 `width: N - 1`。

儲存格網格上的字型

<!-- s:ede6764977 -->
每種隨附字型都使用可列印的 ASCII 或 Latin-1 字元繪製，因此在 Menlo 中，每個子字元剛好佔一個儲存格，並與網格對齊。`<FigletText>` 以儲存格為單位測量各列，因此字體能像其他 `<Text>` 一樣放入 flexbox 版面配置，並透過 `columns` 和 `align` 在其方框內換行與對齊。

<!-- s:3cedd51e92 -->
每種字型都是獨立模組，因此應用程式只會包含匯入的字型，且字型會在首次渲染時才解析，而非匯入時。`@textjs/font/all` 匯出所有字型，供字型展示頁使用。

授權

<!-- s:67e882f6b4 -->
隨附字型與 `figlet-2.2.5.tar.gz` 中的字型逐位元組相同，並依 FIGlet 的 BSD 3-Clause 授權條款散布。每種字型都在註解列中保留作者資訊，可透過 `font.comment` 取得。未取得再散布授權的熱門字型，例如 Doom、Larry 3D、ANSI Shadow 和 Calvin S，並未隨附。
