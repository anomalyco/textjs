在此之前，Text.js 應用程式在 `useInput` 中處理按鍵，再手動於 `<KeyHint>` 頁尾列出一次。`useKeymap` 用一個宣告取代這兩項工作。

<!-- s:8ec88859eb -->
按下 `j` 會執行 `next`。在 macOS 上，`<KeyHints>` 會在頁尾顯示 `j/↓ Next` 和 `⌃S Save`，因為這些綁定設定了 `hint`。`?` 會開啟說明畫面，列出全部四個綁定，歸在「導覽」群組下，而 `Ctrl+K` 會開啟可搜尋這些綁定的命令選單。

<!-- s:c7c1123a0d -->
按鍵語法

<!-- s:e9843726ad -->
| 語法 | 意義 |
| :-- | :-- |
| `ctrl+k` | 修飾鍵：`ctrl`、`alt`、`shift`、`meta` 和 `mod` |
| `mod+k` | `⌘` 或 `Ctrl`，依實際按住的鍵而定 |
| `j, down` | 替代按鍵 |
| `g g` | 按鍵序列，按鍵之間最多間隔 1 秒 |
| `G` | 大寫隱含 `Shift` |
| `?` | 可列印按鍵依字元比對 |

<!-- s:5d4b81956d -->
綁定可以是處理函式，也可以是帶有 `label`、`group`、`hint`、`command`、`disabled` 和 `noRepeat` 的物件。`command: false` 會讓有標籤的綁定不顯示在命令選單中。沒有標籤的綁定仍可運作，但不會出現在說明畫面或命令選單中。

<!-- s:7beff5bd29 -->
路由

<!-- s:5f000bf949 -->
每個按鍵對應會註冊一個 `useInput` 處理函式，因此既有的輸入規則仍適用。取得焦點的 `<Input>` 會優先處理按鍵，因為編輯器的監聽優先順序是 10，按鍵對應則是 0。比對成功的按鍵會停止傳播。開啟的 `<Modal>` 會停用外部的綁定，除非按鍵對應傳入 `global: true`。

<!-- s:a6076c8127 -->
序列在該處理函式內比對。啟動序列的按鍵會保留為待處理狀態，並停止傳播；如果下一個按鍵在超過 `sequenceTimeout`（預設為 1000 ms）後才到達，序列就會重設：

<!-- s:aa0a9c8615 -->
每個根節點各有一個登錄表

<!-- s:8a689d7ce6 -->
有標籤的綁定會發布到屬於主控台根節點的登錄表。`<KeyHelp>`、`<KeyHints>` 和 `<CommandPalette>` 會從中讀取資料，你自己的元件也可以透過 `useKeymapBindings()` 讀取。當互動視窗開啟時，登錄表只會回傳其中的綁定，因此說明畫面列出的都是當下可用的按鍵。

<!-- s:ab5f364d60 -->
按鍵對應通常以行內方式撰寫，每次渲染都會建立新物件。為了降低成本，按鍵對應只會在標籤的可見形式改變時重新發布標籤：

<!-- s:fa6b5ba7b8 -->
按鍵到達時，處理函式會從 ref 讀取，因此每次渲染產生的新閉包都不會過時。

<!-- s:1b173acf33 -->
說明畫面與命令選單

<!-- s:15201cd425 -->
按下 `?` 會開啟 `<KeyHelp>`，依群組列出所有目前有效且有標籤的綁定。`keys` 和 `title` 可變更觸發按鍵與標題。

<!-- s:8a5c3a3297 -->
按下 `Ctrl+K` 或 `Ctrl+P` 會開啟 `<CommandPalette>`。它會對你的 `commands` 和所有有標籤的綁定做模糊比對，並醒目標示符合的字母。它會先關閉再執行命令，因此命令可以開啟自己的互動視窗。

<!-- s:bea7ebdffb -->
`formatKeys` 會將綁定渲染為顯示格式。`formatKeys("ctrl+shift+p")` 在 macOS 上回傳 `⌃⇧P`，在其他平台回傳 `ctrl+shift+P`，而 `<Kbd>` 會以相同格式渲染單一按鍵。

<!-- s:d068dd2764 -->
`useKeymap`、`<KeyHelp>`、`<KeyHints>`、`<StatusBar>` 和 `<CommandPalette>` 隨 Text.js 1.0 提供。參考文件請見[鍵盤](/docs/keyboard)。
