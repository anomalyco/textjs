<!-- s:5b67b32177 -->
ルートハンドラーのレスポンスとデータをキャッシュし、タイマーまたはオンデマンドで再検証します。古いエントリーは即座に返され、その間に1つのバックグラウンド更新が実行されます。

<!-- s:be697310c8 -->
ルートハンドラー

<!-- s:e85fc29fe2 -->
`GET` ルートハンドラーはデフォルトで動的です。キャッシュを有効にするには、ルートセグメント設定を使います。

<!-- s:e4ccf65c67 -->
| エクスポート | 動作 |
| :-- | :-- |
| *（なし）* | リクエストごとに実行します |
| `dynamic = "force-static"` | 再検証されるまでキャッシュします |
| `revalidate = N` | キャッシュし、`N` 秒後に古い状態になります |
| `revalidate = 0` または `dynamic = "force-dynamic"` | リクエストごとに実行します |

<!-- s:274c053db6 -->
これ以外の `dynamic` の値は `TX031` で失敗します。Text.jsはハンドラーがリクエストを読み取ったことを検出できないため、Next.jsの `"error"` も含まれます。

<!-- s:0fae4045f6 -->
キャッシュされるハンドラーにはパス名ごとに1つのエントリーが割り当てられ、`request` はビルド時と同じ状態になります。クエリー文字列、ヘッダー、Cookie、本文はありません。これらは動的なハンドラーで読み取ってください。キャッシュされるのは `GET` と `HEAD` のみです。ステータスが `5xx` のレスポンス、`Set-Cookie` ヘッダーを持つレスポンス、`Cache-Control: private` / `no-store` を持つレスポンスは返されますが、保存されません。

<!-- s:b618d4732f -->
ヘッダー

<!-- s:c0a6cf7351 -->
キャッシュされたレスポンスには次のヘッダーが含まれます。

<!-- s:b5f8cfecb4 -->
| ヘッダー | 値 |
| :-- | :-- |
| `x-textjs-cache` | `MISS`、`HIT`、または `STALE` |
| `Cache-Control` | `s-maxage=N, stale-while-revalidate=<1 year − N>`、または `force-static` の場合は `s-maxage=31536000` |

<!-- s:c1fb73c64a -->
[ミドルウェア](/docs/middleware)がリクエストに対してCookieの設定、リライト、リクエストヘッダーの上書きをすると、生成されるヘッダーは `private, no-cache, no-store, max-age=0, must-revalidate` になります。そのため、共有キャッシュが訪問者ごとの判断を再利用することはありません。ハンドラーが設定した `Cache-Control` ヘッダーは保持されます。

<!-- s:ae27ba22c7 -->
`text dev` ではセグメント設定は適用されますが、何も保存されないため、リクエストごとにハンドラーが実行されます。

<!-- s:64841df645 -->
データキャッシュ

<!-- s:2187e2262b -->
任意の非同期関数をキャッシュするには、`@textjs/app/cache` の `unstable_cache` を使います。

<!-- s:4c26e099ff -->
キーは、キーの構成要素と引数を値に基づいてエンコードしたものです（引数の `undefined` と `null`、`Map`、`Set`、`Date`、`URL` はそれぞれ区別されます）。キーの構成要素を指定しない場合は、関数のソースと作成された場所で識別されます。リクエストごとやループ内で作成する場合など、関数がクロージャーで値を参照するときは必ずキーの構成要素を渡してください。結果はJSONにシリアライズされるため、呼び出しごとに新しいコピーが返されます（`Date` オブジェクトは文字列として返されます）。シリアライズできない結果は例外をスローします。`cache(fn, { key, tags, revalidate })` は同じ設定をオプションオブジェクトとして受け取ります。

<!-- s:608eee0e9b -->
キャッシュされたルートハンドラー内では、データエントリーのタグと最短の `revalidate` がルートに引き継がれます。`"posts"` を再検証すると、`/api/posts` も更新されます。`revalidate: 0` を指定したデータ呼び出しがあると、そのルートは動的になります。

<!-- s:5537f337ee -->
Stale-while-revalidate

<!-- s:7d23e84252 -->
エントリーが `revalidate` の期間を過ぎると、次のように動作します。

<!-- s:d4dd1966dd -->
1. 次のリクエストには古い値が即座に返されます（`STALE`）。
2. バックグラウンドで1つの更新が実行され、同時に届いたリクエストはその更新を共有します。
3. 更新が例外をスローすると、古い値が引き続き返され、エラーがログに記録されます。

<!-- s:e6db7819cc -->
VercelとCloudflareでは、バックグラウンド更新は `waitUntil()` に登録されます。1年を超えたエントリーは常にフォアグラウンドで再計算されます。

<!-- s:5854b096d2 -->
オンデマンド再検証

<!-- s:686aa7f2f3 -->
| 呼び出し | 無効化の対象と動作 |
| :-- | :-- |
| `revalidateTag("posts")` | `posts` タグが付いたすべてのエントリーを無効化し、次のリクエストで再計算します |
| `revalidateTag("posts", "max")` | 古い状態としてマークし、次のリクエストには更新中の古い値を返します |
| `revalidatePath("/api/feed")` | 指定したパスを無効化します |
| `revalidatePath("/api/posts/[id]")` | 動的ルートのすべてのパスを無効化します |
| `revalidatePath("/api", "layout")` | `/api` 配下のすべてを無効化します |

<!-- s:b132bd50eb -->
どちらもPromiseを返します。インメモリーストアでは即座に無効化されます。[カスタムストア](#custom-cache-stores)が非同期の場合は `await` してください。

<!-- s:2aab4b4d00 -->
カスタムキャッシュストア

<!-- s:7bee24a364 -->
デフォルトのストアは、サーバーインスタンスごとのインメモリーLRU（1,000エントリー、約50 MB）です。インスタンス間でキャッシュを共有するには、`CacheStore` をデフォルトエクスポートするモジュールを `cacheHandler` に指定します。

<!-- s:593c57fca5 -->
エントリーは通常のJSONです。代わりに `setCacheStore(store)` を使うと、実行時にストアを設定できます。

<!-- s:fe2404de51 -->
プラットフォームに関する注意事項

<!-- s:5418a08901 -->
- 各サーバーレスインスタンス（Vercel Functions、Cloudflare Isolates）は、それぞれ独自のインメモリーキャッシュを持ちます。`Cache-Control: s-maxage` を使うとプラットフォームのCDNでもレスポンスをキャッシュできますが、オンデマンド再検証ではCDNのキャッシュは削除されません。`revalidateTag` をすべてのインスタンスに反映する必要がある場合は、共有の `cacheHandler` を使ってください。
- Cloudflareでは `nodejs_compat` フラグが必要です（キャッシュが `AsyncLocalStorage` を使うためです）。[デプロイ](/docs/deploying)を参照してください。
