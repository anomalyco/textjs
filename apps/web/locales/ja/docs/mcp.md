<!-- s:c351b288ae -->
`text mcp` は `app/` ディレクトリーをヘッドレスでプロセス内実行し、[Model Context Protocol](https://modelcontextprotocol.io)経由で提供します。コーディングエージェントはDevToolsなしで利用できます。エージェントは画面遷移、キー入力、プレーンテキストでのフレームの読み取り、ルートハンドラーの呼び出しを実行します。

<!-- s:c66b3eaae7 -->
`text mcp` にはBunが必要です。Nodeで起動すると、`PATH` に `bun` があればBunで自身を再実行し、なければ `TX019` で失敗します。MCPクライアントが起動するため、手動で実行することはほとんどありません。

ツール

<!-- s:93ae76f73d -->
| ツール | 説明 |
| :-- | :-- |
| `list_routes` | `app/` 内のページとルートハンドラー、および現在の位置 |
| `navigate` | パスの追加や置換、または `back` / `forward` による移動 |
| `read_frame` | ルート、サイズ、フォーカス、カーソルを含むテキスト形式のフレーム。`styles: true` でスパンごとの色と属性を追加 |
| `press` | キーの組み合わせ：`"down"`、`"ctrl+k"`、`"shift+tab"`、`"tab tab enter"`、`"down*3"` |
| `type` | 1文字につき1キーでテキストを入力（最大2,000文字。それ以上は `paste` を使用）。`submit: true` で入力後にEnterを押下 |
| `paste` | `⌘V` と同様の1回の貼り付けイベント |
| `scroll` | `rows`（および `cols`）分のマウスホイールスクロール。`<ScrollBox>` はキーボードフォーカスがなくてもホイールでスクロール |
| `resize` | 列数と行数によるグリッドサイズの設定 |
| `inspect_tree` | 画面上の境界と、フォーカス可能なすべてのidを含むコンポーネントツリー |
| `find` | 各一致箇所の境界と、その位置にあるコンポーネント |
| `wait_for` | テキストの出現や消失、またはアプリのアイドル状態を待機 |
| `logs` | キャプチャーした `console.*` 出力とReactエラー |
| `fetch` | プロセス内での `route.ts` ハンドラーの呼び出し。ボディーは `maxBytes` まで、イベントストリームは `streamMs` の間読み取り、その後キャンセル |
| `reload` | ファイル編集後のアプリの再インポート |

フレームとアイドル状態

<!-- s:f2e8fe0f06 -->
どのツールもフレームを読み取る前に、アプリがアイドル状態になるまで待ちます。これは、フレームの予定がなく、処理中の `fetch` がなく、50msの間コミットもフレームもない状態です。そのため、エージェントが見るのは更新途中のフレームではなく、入力の結果です。

<!-- s:fbad6f5c1a -->
`<Spinner>` や1秒に1回更新されるチャートも、更新の合間はアイドル状態と見なされるため、アニメーションのあるページも読み取れます。50msより短い間隔でレンダリングするアプリは、アイドル状態になりません。読み取りは1.5秒で待機を打ち切り（`settleMs` で変更可能）、最新のフレームをフラッシュして `busy` とマークします。テキストを指定しない `wait_for` は、独自の `quietMs` でアイドル状態を待ち、アイドル状態にならなければエラーを返します。

<!-- s:c5250c2f7a -->
座標はゼロ始まりのセル単位で、`x` が列、`y` が行です。CJK文字や絵文字などの幅の広い文字は2列を使います。

<!-- s:7ff82431c5 -->
エラーとログ

<!-- s:6e07cf8702 -->
stdoutはプロトコルの通信に使います。アプリの `console.*` 出力、意図せず呼ばれた `process.stdout.write`、Reactエラーは代わりに `logs` に送られ、エージェントが `since` で新しいエントリーのみを要求できるよう番号が付けられます。前回の読み取り以降にエラーが記録されていれば、次のフレームヘッダーにその旨が表示されます。

<!-- s:9102068439 -->
失敗はツールエラーとして返され、クラッシュにはなりません。タイムアウトしたツールは次の呼び出しが実行される前にキャンセルされるため、遅い呼び出しが次の呼び出しのフレームに入力することはありません。Text.jsのコードが付いたエラーはそのコードを保持します。たとえば、不明なキーには `TX007` が付きます。アプリの読み込みに失敗すると、すべてのツールがその理由を説明します。ファイルを修正して `reload` を呼び出します。

動作の仕組み

<!-- s:7c71219a13 -->
`text mcp` は [`text run`](/docs/terminal) と同じ方法でアプリを実行します。すべてのルートモジュールを事前にインポートし、App Routerはメモリー上の履歴を使い、同一オリジンの `fetch("/api/…")` 呼び出しはプロセス内でハンドラーを実行します。フレームの出力先は、ターミナルではなくオフスクリーンのセルグリッドです。サーバーレンダリングされるページ（`export const runtime = "server"`）とその `async function` コンポーネントは、`text dev` と同様にプロセス内でレンダリングされ、解決後にフレームが読み取られます。

<!-- s:c965dcc0e4 -->
`reload` はアプリをアンマウントし、Bunのモジュールキャッシュからプロジェクトの全モジュール（`app/` 外のファイルを含む）を削除し、`app/` を再スキャンして現在の位置に再マウントします。

<!-- s:19d6f0da69 -->

制限

<!-- s:910af21777 -->
- アプリはブラウザーではなくBunで実行されます。`text run` と同様に、`window` と `document` は未定義です。
- 各サーバーは1つのグリッドで1つのアプリを実行します。各MCPクライアントがそれぞれサーバーを起動します。
- `text mcp` はアプリの独立したヘッドレスコピーを実行します。`text dev` で開いているブラウザータブには接続できません。
