middleware מריץ קוד לפני השלמת הבקשה. הוא יכול להפנות, לשכתב, להגדיר כותרות וקובצי Cookie, או להחזיר תגובה בעצמו.

<!-- s:895d99d1b5 -->
מוסכמות

<!-- s:9e6d75b727 -->
יש ליצור את `middleware.ts` בשורש הפרויקט (או בספרייה `src/`), לצד `app/`. יש לייצא פונקציית `middleware` (או ייצוא ברירת מחדל) ובאופן אופציונלי גם `config`.

<!-- s:a4d39cdaaf -->
middleware רץ לפני [מטפלי נתיבים](/docs/route-handlers), קבצים סטטיים ודפי מסוף, בעת הפעלת `text dev`, `text start` וכל [מתאם פריסה](/docs/deploying) לשרת. הוא משתמש ב-`Request` וב-`Response` של Web, כך שאותו קובץ רץ ב-Node, ב-Bun, ב-Vercel Edge וב-Cloudflare Workers.

<!-- s:dda0880da2 -->
התאמת נתיבים

<!-- s:1e1ec8c339 -->
ללא `config.matcher`, middleware רץ עבור כל בקשה. כללי ההתאמה משתמשים באותו תחביר כמו Next.js:

<!-- s:473d472bc8 -->
| כלל התאמה | התאמות |
| :-- | :-- |
| `/about` | `/about` וגם `/about/` |
| `/blog/:slug` | `/blog/hello` |
| `/docs/:path*` | `/docs`, `/docs/a/b` |
| `/a/:rest+` | `/a/b`, לא `/a` |
| `/user/:id(\\d+)` | `/user/42`, לא `/user/ada` |
| `/((?!api/).*)` | הכול מלבד `/api/*` |

<!-- s:256aeeefbc -->
יש להוסיף תנאים באמצעות `has` ו-`missing` (כותרת, קובץ Cookie, שאילתה או מארח):

<!-- s:d756420343 -->
כללי ההתאמה חלים על שם הנתיב ללא `basePath`. ב-`text dev`, בקשות המודולים של Vite עצמו (`/@vite/*`, קובצי מקור) לעולם אינן מפעילות middleware.

<!-- s:75cd7297e6 -->
כל מארח מחשב שם נתיב קנוני אחד לפני הפעלת middleware, ומשתמש בו להתאמה, ל-`request.nextUrl` ולחיפוש הנתיב, המטפל והקובץ. רצפי קידוד באחוזים מפוענחים והנתיב מקודד מחדש באופן שבו `new URL()` כותב אותו, מקטעי `.` ו-`..` נפתרים, ולוכסנים חוזרים וסופיים מוסרים. `/ad%6din//users/` מגיע ל-middleware בתור `/admin/users`, ואילו `/café` נשאר `/caf%C3%A9`. כלל התאמה שנכתב עם לוכסן סופי, כגון `/admin/`, מתאים ל-`/admin`. בקשות שהנתיב שלהן מכיל לוכסן או לוכסן הפוך מקודד (`%2F`, `%5C`), תו בקרה או קידוד אחוזים לא תקין מקבלות `400`. נתיבים רגישים לרישיות: `/Admin` אינו מתאים ל-`/admin`, וקבצים סטטיים מוגשים רק בשם המדויק שלהם.

<!-- s:3f5746eb4e -->
יש להתאים את כתובות ה-URL שבהן הקובץ מוגש, ולא רק את שם הקובץ שלו. Cloudflare Pages מגיש את `report.html` גם ב-`/report`, ולכן כלל התאמה עבור `/report.html` אינו מגן על `/report`. יש לציין את שניהם, `matcher: ["/report", "/report.html"]`, או לשמור קבצים מוגנים בספרייה ולהתאים אותה, למשל `/reports/:path*` עבור קבצים בספרייה `public/reports/`.

NextResponse

<!-- s:880215c229 -->
| API | השפעה |
| :-- | :-- |
| `NextResponse.next()` | המשך לנתיב |
| `NextResponse.redirect(url, status?)` | `307` כברירת מחדל; `url` חייב להיות מוחלט |
| `NextResponse.rewrite(url)` | הגשת נתיב אחר; מקורות חיצוניים מועברים דרך שרת מתווך |
| `NextResponse.json(body, init?)` | החזרת תגובה עם JSON |
| `new Response(...)` | החזרת תגובה עם כל תוכן |

<!-- s:a8292924c3 -->
כדי להמשיך ללא שינוי, אין להחזיר דבר. `next()` ו-`rewrite()` מקבלות `{ status }` לשינוי קוד המצב של התגובה הסופית. רק תגובות שנוצרו באמצעות `NextResponse.next()` / `NextResponse.rewrite()` מכוונות את הניתוב: כל `Response` אחר, כולל כזה שהוחזר מ-`fetch()`, נשלח ללקוח כפי שהוא, לאחר הסרת כותרות ה-`x-middleware-*` שלו.

<!-- s:583e778785 -->
`request.nextUrl` אינו כולל את `basePath` בתוך `pathname`, ואילו `href` ו-`toString()` שלו כוללים אותו. כדי להישאר בתוך האפליקציה, יש לשכפל אותו: `const url = request.nextUrl.clone(); url.pathname = "/login"; return NextResponse.redirect(url);`.

<!-- s:37748fa2c3 -->
יש להעביר את `request.headers` כדי לשנות את מה שהמטפלים בהמשך מקבלים, ואת `headers` כדי להוסיף כותרות תגובה:

<!-- s:60bf4677c2 -->
כותרות תגובה מ-middleware מתווספות לתגובה הסופית, אלא אם מטפל הנתיב מגדיר את אותה כותרת.

קובצי Cookie

<!-- s:5d3635224b -->
`request.cookies` קורא את הכותרת `Cookie`; `response.cookies` כותב את `Set-Cookie`.

<!-- s:4a7b6bbf62 -->
קובצי Cookie שמוגדרים בתגובת `next()` או `rewrite()` זמינים גם למטפל הנתיב באותה בקשה.

הערות

<!-- s:971c06c875 -->
- דפים עם רינדור בצד הלקוח מרונדרים בדפדפן, ולכן שכתוב לדף אחר משנה את הקובץ המוגש, ולא את הנתיב שאפליקציית המסוף מרנדרת. שכתובים למטפלי נתיבים, לקבצים סטטיים ולמקורות חיצוניים פועלים כמצופה.
- middleware יכול לקרוא את גוף הבקשה; מטפלי נתיבים עדיין מקבלים אותו. גוף הבקשות שכלל התאמה מחריג נשאר ללא שינוי.
- `request.url` מכיל תמיד את מקור השרת: יעדי בקשה כגון `//other.host/x` מנורמלים ללוכסן מוביל יחיד.
- [המתאם הסטטי](/docs/deploying#static) אינו יכול להריץ middleware.
