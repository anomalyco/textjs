`text mcp` מריץ את הספרייה `app/` ללא ממשק גרפי, בתוך התהליך, ומגיש אותה דרך [פרוטוקול Model Context](https://modelcontextprotocol.io) כדי שסוכני תכנות יוכלו להשתמש בה ללא DevTools. הסוכן מנווט, לוחץ על מקשים, קורא פריימים כטקסט רגיל וקורא למטפלי נתיבים.

<!-- s:c66b3eaae7 -->
`text mcp` דורש Bun. כשהוא מופעל עם Node, הוא מריץ את עצמו מחדש עם Bun אם `bun` נמצא ב-`PATH`, ואחרת נכשל עם `TX019`. לקוחות MCP מפעילים אותו, כך שלעיתים רחוקות יש צורך להריץ אותו ידנית.

פריימים ומצב סרק

<!-- s:f2e8fe0f06 -->
לפני שכלי כלשהו קורא פריים, הוא ממתין שהאפליקציה תעבור למצב סרק: אין פריים מתוזמן, אין `fetch` פעיל, ולא התרחש commit או פריים במשך 50 ms. כך הסוכן רואה את תוצאת הקלט שלו, ולא פריים באמצע עדכון.

<!-- s:fbad6f5c1a -->
רכיב `<Spinner>` או תרשים שמתעדכן פעם בשנייה עדיין נחשבים במצב סרק בין עדכונים, כך שדפים עם הנפשות נשארים קריאים. אפליקציה שמרנדרת בתדירות גבוהה מפעם בכל 50 ms לעולם אינה עוברת למצב סרק. פעולות הקריאה מפסיקות להמתין אחרי 1.5 שניות (`settleMs` משנה זאת), מוציאות את הפריים האחרון ומסמנות אותו כ-`busy`. `wait_for` ללא טקסט ממתין למצב סרק, עם `quietMs` משלו, ומחזיר שגיאה אם מצב הסרק אינו מגיע.

שגיאות ויומנים

<!-- s:6e07cf8702 -->
stdout מעביר את הפרוטוקול. פלט `console.*` של האפליקציה, קריאות מזדמנות ל-`process.stdout.write` ושגיאות React מועברים במקום זאת ל-`logs`, עם מספור שמאפשר לסוכן לבקש רק רשומות חדשות באמצעות `since`. אם נרשמו שגיאות מאז הקריאה האחרונה, כותרת הפריים הבא מציינת זאת.

<!-- s:9102068439 -->
כשלים מוחזרים כשגיאות כלי, ולעולם אינם גורמים לקריסה. כלי שחורג ממגבלת הזמן מבוטל לפני שהקריאה הבאה רצה, כך שקריאה איטית לעולם אינה מקלידה לתוך הפריים של הקריאה הבאה. שגיאות עם קוד Text.js שומרות עליו, למשל `TX007` למקש לא מוכר. אם טעינת האפליקציה נכשלת, כל כלי מסביר מדוע. יש לתקן את הקובץ ולקרוא ל-`reload`.

אופן הפעולה

<!-- s:7c71219a13 -->
`text mcp` מריץ את האפליקציה באותו אופן כמו [`text run`](/docs/terminal): כל מודול נתיב מיובא מראש, ה-App Router משתמש בהיסטוריה בזיכרון, וקריאות `fetch("/api/…")` לאותו מקור מריצות את המטפלים בתוך התהליך. הפריימים מועברים לרשת תאים מחוץ למסך במקום לטרמינל. דפים שמרונדרים בצד השרת (`export const runtime = "server"`) ורכיבי ה-`async function` שלהם מרונדרים בתוך התהליך, כמו ב-`text dev`, והפריים נקרא לאחר שהם מסיימים.

<!-- s:c965dcc0e4 -->
`reload` מסיר את האפליקציה מעץ הרכיבים, מנקה כל מודול של הפרויקט ממטמון המודולים של Bun (כולל קבצים מחוץ ל-`app/`), סורק שוב את `app/` ומרכיב מחדש במיקום הנוכחי.

מגבלות

<!-- s:910af21777 -->
- האפליקציה רצה ב-Bun, ולא בדפדפן. `window` ו-`document` אינם מוגדרים, כמו ב-`text run`.
- כל שרת מריץ אפליקציה אחת עם רשת אחת. כל לקוח MCP מפעיל שרת משלו.
- `text mcp` מריץ עותק משלו של האפליקציה ללא ממשק גרפי. הוא אינו יכול להתחבר לכרטיסיית דפדפן שפתוחה תחת `text dev`.
