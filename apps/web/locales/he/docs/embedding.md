<!-- s:7e7d3cb07e -->
`text build --embed` בונה את האפליקציה כך שאתר אחר יוכל להוסיף אותה באמצעות תגית סקריפט אחת, למשל עמוד שיווקי, אתר תיעוד, עמוד WordPress או Webflow, או אפליקציית React 18. מבקרים שפותחים את DevTools מקבלים את האפליקציה במסוף. מבקרים אחרים מורידים את `embed.js` (כ-3 kB עם gzip) ושום דבר נוסף, אלא אם יש בעמוד `<text-console>`.

<!-- s:2aa1d07d89 -->
הטמעות הן ניסיוניות. `text build --embed`, האפשרות `embed`, הרכיב `<text-console>` והייצואים של `@textjs/app/experimental` עשויים להשתנות בגרסת משנה. ראו [שינויים שוברי תאימות](/docs/support-policy#breaking-changes).

לבניית האפליקציה:

<!-- s:2198c52791 -->
יש להעלות את `dist/` לכל שירות אירוח סטטי או CDN, או להעתיק אותה לתיקייה `public/` של האתר, ואז להוסיף תגית אחת לעמודי האתר:

<!-- s:aa94ef1985 -->
`embed.js` טוען את הקבצים האחרים שלו ביחס לכתובת שלו, כך ש-`dist/` עובדת מכל נתיב או מקור. היא מכילה רק את `embed.js` ואת `assets/`, ללא `index.html` או `404.html` שעלולים להחליף את אלה של האתר עצמו. אפליקציה עם [נתיבים מרונדרים בצד השרת](#server-rendered-routes), מטפלי נתיב או middleware זקוקה לשרת במקום העלאה סטטית רגילה. המתאמים `vercel` ו-`cloudflare` מריצים מטפלי נתיב ו-middleware, ונתיבים מרונדרים בצד השרת דורשים `text start` או את המתאם `bun`.

<!-- s:5c139759a2 -->
כדי להראות למבקרים היכן האפליקציה נמצאת, יש להוסיף [`<text-console>`](#text-console) בכל מקום בעמוד. גם כל אלמנט עם `data-textjs-engage` מפעיל את האפליקציה בלחיצה:

<!-- s:6a70ec16e1 -->
כדי לנסות זאת מקומית, יש להריץ `text dev --embed`. הפקודה מגישה את `/embed.js` עם פריים ראשון חדש בכל בקשה, ועמוד תצוגה מקדימה ב-`/` (ב-`/__textjs/embed` עם `standalone`) שטוען אותו כפי שאתר אחר היה טוען אותו. גם אתר בפורט מקומי אחר יכול לטעון את `http://localhost:3000/embed.js`.

הגדרות

<!-- s:aa9630bf92 -->
`text build --embed` שקול ל-`embed: true` בקובץ `text.config.ts`. כדי לשנות את ברירות המחדל, יש להעביר אובייקט:

<!-- s:fbe8efc9f4 -->
| אפשרות | ברירת מחדל | תיאור |
| :-- | :-- | :-- |
| `initialPath` | `"/"` | הנתיב שבו המסוף נפתח. חייב להתחיל ב-`/` |
| `globalName` | `"text"` | השם הגלובלי שתחתיו האפליקציה מתקינה את ה-API שלה למסוף כשהיא מתחילה לפעול. `false` מונע התקנה של שם גלובלי |
| `initialClear` | `false` | ניקוי מסוף העמוד לפני הפריים הראשון. כברירת מחדל, מה שהעמוד רשם קודם נשאר מעל האפליקציה |
| `standalone` | `false` | בנייה גם של עמודי האפליקציה עצמה (`index.html`), כפי שעושה `text build` ללא `embed` |
| `allowOrigins` | `[]` | אתרים שהעמודים שלהם רשאים להריץ נתיבים מרונדרים בצד השרת משרת זה. ראו [נתיבים מרונדרים בצד השרת](#server-rendered-routes) |
| `credentials` | `false` | שליחת פרטי הזדהות של הדפדפן לשרת זה עם בקשות סשן חי מ-`allowOrigins`, במקום הסרת קובצי Cookie ו-`Authorization`. נדרשים מקורות מדויקים |

<!-- s:12a3d28167 -->
`viewport.width × viewport.height` (ברירת מחדל 120 × 36) הוא גודל הפריים הראשון. `title`,‏ `hints` ו-`action` הם ברירות המחדל של `<text-console>`. אין ב-`embed.js` פריים ראשון מרונדר מראש כאשר מוגדר `ppr: false`, או כאשר `middleware.ts` עשוי להתאים ל-`initialPath`, משום שכל אחד יכול להוריד את `embed.js`. תצוגת מראה נשארת ריקה עד שהאפליקציה מציירת.

אופן הפעולה

<!-- s:1fe89ec57c -->
- **שום דבר נוסף לא נטען עד [להבעת כוונה להשתמש במסוף](/docs/hooks-and-repl#loading-on-console-intent-experimental).** `embed.js` רושם למסוף את הפריים הראשון שרונדר מראש, ואז ממתין. האפליקציה נטענת כאשר DevTools מעוגן (בטעינה או מאוחר יותר), כאשר המבקר לוחץ בעמוד על קיצור מקשים של DevTools (F12, Ctrl+Shift+J, I, C או K, או ⌘⌥J, I, C או K ב-Mac), או כאשר הוא לוחץ על אלמנט `<text-console>` או `[data-textjs-engage]`. לאחר מכן, טעינות חוזרות באותה כרטיסייה מפעילות אותה מיד. DevTools בחלון משלו אינו משנה את גודל העמוד, ולכן מבקרים שפתחו אותו מתפריט רואים את הפריים הראשון עד שילחצו על אחד מהאלמנטים האלה.
- **במסכי מגע, האפליקציה אינה מופעלת.** במכשיר שתואם ל-`(hover: none) and (pointer: coarse)`,‏ `embed.js` אינו רושם דבר למסוף ואינו מוסיף מאזינים. הקובץ היחיד שהוא טוען הוא זה של `<text-console>`, לצורך תצוגת מראה.
- **הקשות מגיעות לאפליקציה רק לאחר שהמבקר מפעיל את האינטראקציה איתה.** לשם כך, יש ללחוץ על אלמנט `<text-console>` או `[data-textjs-engage]`, או ללחוץ על העמוד (לא על קישור, כפתור או שדה) כדי להחזיר את המיקוד מ-DevTools. הקלדה בשדות של העמוד עצמו או באלמנט `[data-textjs-bypass]` לעולם אינה מגיעה לאפליקציה, והגלגלת תמיד גוללת את העמוד.
- **כתובת העמוד, ההיסטוריה והכותרת שלו לעולם אינן משתנות.** נתיבים, `<Link>` ו-`useRouter()` מנווטים בתוך המסוף. באפליקציות שמרונדרות בצד הלקוח, כתובות מוחלטות נפתחות בכרטיסייה חדשה.
- **לאפליקציית Text.js בעמוד יש עדיפות.** כשהיא מתחילה לפעול, הטמעה פעילה מתנתקת מהעץ, מפסיקה לקרוא הקשות ומסירה את השם הגלובלי שלה. הטמעה שנטענת בזמן שאפליקציה אחרת מחזיקה במסוף רושמת אזהרה אחת ואינה מתחילה לפעול.
- **ההטמעה כוללת React 19 משלה.** אין בה `react-dom` או ייבואים ללא נתיב, ולכן גרסת React של העמוד, מפת ייבוא עבור `react` ו-React DevTools אינם משפיעים עליה.

`<text-console>`

<!-- s:7156621f10 -->
`embed.js` מגדיר את `<text-console>` וטוען את הקובץ שלו רק כשיש אלמנט כזה בעמוד. הוא משתמש ב-Shadow DOM, כך שה-CSS של העמוד אינו מגיע פנימה, ואין צורך לשנות מדיניות `style-src 'self'`.

<!-- s:9ceead3eca -->
ללא מאפיינים, זהו פס בן שורה אחת. הוא מציג את קיצור המקשים של הדפדפן לפתיחת המסוף, אחר כך מבקש לחיצה, ואז מציג את מקשי האפליקציה, שמוארים כשההקשות מגיעות לאפליקציה. ב-Safari, השלב הראשון מנחה להפעיל את "הצגת תכונות למפתחי אינטרנט" בהגדרות Safari.

<!-- s:899e0c7fe3 -->
עם `mirror`, הוא מציג את הפריים של האפליקציה בעמוד: את הפריים הראשון שרונדר מראש לפני שכל דבר אחר נטען, ואז את האפליקציה הפעילה. לחיצה עליו מפעילה את האפליקציה ושולחת אליה את הקשות המבקר, כך שהאפליקציה עובדת גם כש-DevTools סגור. `chrome` מצייר חלון DevTools סביב תצוגת המראה וכולל במשתמע את `mirror`.

<!-- s:fefcb3e495 -->
| מאפיין | תיאור |
| :-- | :-- |
| `mirror` | הצגת הפריימים של האפליקציה |
| `chrome` | הצגת הפריימים בחלון DevTools |
| `title` | כותרת הפס (ברירת מחדל: `title` בקובץ `text.config.ts`) |
| `hints` | המקשים להצגה, בתבנית `"← →:switch region, Enter:open"` (ברירת מחדל: `hints` בקובץ `text.config.ts`) |
| `action` | הפעולה הראשונה לביצוע, שמוצגת בתור "ללחוץ כאן ו…" (ברירת מחדל: `action` בקובץ `text.config.ts`, או לחיצה על המקש שברמז הראשון) |

<!-- s:392012169b -->
במסכי מגע, תצוגת מראה מציגה את הפריים הראשון בלי להפעיל את האפליקציה, והפס מוסתר. הטקסט של האלמנט הוא באנגלית.

שמירת מקום לאלמנט

<!-- s:0f4e2c234d -->
`text build --embed` מדפיס שורת CSS אחת עבור רשת האפליקציה. יש להדביק אותה בגיליון הסגנונות של העמוד. היא קובעת את הגודל של `<text-console>` לפני שקובץ האלמנט נטען, כך ששום דבר בעמוד אינו זז כשהקובץ מגיע. עבור רשת ברירת המחדל בגודל 120 × 36, השורה היא:

<!-- s:a2d2741417 -->
גובה הפס הוא 58 px. תצוגת מראה שומרת על יחס הממדים של הרשת, עד לרוחבה הטבעי (885 px ב-120 עמודות), ו-`chrome` מוסיף 43 px. הגודל אינו תלוי בגופנים. `reserveCss(cols, rows)` מתוך `@textjs/app/experimental` מחזירה את אותה שורה.

<!-- s:a1260c10c3 -->
תצוגת מראה בחלק הגלוי הראשוני היא בדרך כלל האלמנט הגדול ביותר בעמוד, ולכן היא קובעת את מדד Largest Contentful Paint‏ (LCP) של העמוד. הפריים הראשון שלה מצויר לאחר טעינת `embed.js` ואז קובץ האלמנט, בזה אחר זה. שאר העמוד מצויר כפי שהיה מצויר ללא ההטמעה. תצוגת מראה בהמשך העמוד אינה משפיעה על LCP. בעמוד עם סקריפטים נדחים משלו, כגון אפליקציית React,‏ `<script type="module" async src="…">` מריץ את `embed.js` בלי להמתין להם, כך שתצוגת מראה בחלק הגלוי הראשוני מצוירת מוקדם יותר.

כדי למרכז תצוגת מראה, יש להגדיר לה שוליים אוטומטיים בציר השורה:

ברירת המחדל היא עיצוב כהה. יש להגדיר `color-scheme: light` לצבעים בהירים, או להגדיר את שני הצבעים שמהם מעורבבים כל שאר הגוונים. `::part(frame)` מעצב את הפריים עצמו. `chrome` שומר על הרקע של DevTools עצמו.

נתיבים מרונדרים בצד השרת

<!-- s:eb293d9fb4 -->
כאשר `initialPath` הוא נתיב עם `export const runtime = "server"`,‏ `embed.js` טוען את נגן הפריימים במקום סביבת הריצה של הלקוח. הוא מזרים פריימים מהשרת שממנו הגיע `embed.js`, ולכן יש להריץ `text start` או את המתאם `bun`. מתאמים אחרים מכשילים את הבנייה. ראו [רינדור בצד השרת](/docs/server-rendering).

<!-- s:e2bdd4dbb7 -->
עמוד באתר אחר יכול לפתוח סשן חי רק כשהמקור שלו נמצא ב-`allowOrigins`:

<!-- s:6ec7048857 -->
- סשן משיב רק למקור שפתח אותו.
- כברירת מחדל, Text.js מסיר את קובצי ה-Cookie ואת הכותרת `Authorization` של סשנים מאתרים אחרים, כך ש-[middleware](/docs/middleware) רואה מבקר שאינו מחובר. `credentials: true` שומר אותם, ודורש מקורות מדויקים. הדפדפן שולח אותם כשהעמוד והשרת חולקים דומיין שניתן לרישום (`www.example.com` ו-`console.example.com`) וקובץ ה-Cookie חל על השרת (`Domain=example.com`, או שהוגדר ב-`console.example.com`). מאתרים אחרים הוא שולח רק קובצי Cookie שהוגדרו עם `SameSite=None; Secure`, ודפדפנים שחוסמים קובצי Cookie של צד שלישי אינם שולחים אף אחד מהם.
- סשן חי שולח בקשות קדם `OPTIONS` אל `/__textjs/live` מיד עם ההתחברות, ובכל התחברות מחדש. בקשות קדם אינן נושאות קובצי Cookie או `Authorization`, ולכן middleware שתואם לנתיב הזה חייב לאפשר לבקשות `OPTIONS` לעבור ללא כניסה לחשבון.
- מאחורי פרוקסי הפוך או CDN, יש להגדיר `server.trustProxy` (ראו [מאחורי פרוקסי](/docs/deploying#behind-a-proxy)). בלעדיו, לכל מבקר יש את כתובת הפרוקסי, ולכן כולם חולקים מגבלת סשנים אחת ללקוח.

<!-- s:f739524722 -->
`text dev` מקבל עמודים ב-`localhost`,‏ `127.0.0.1` ו-`[::1]` בכל פורט ללא `allowOrigins`, אלא אם הוגדר `credentials`.

<!-- s:d5df7bf60f -->
אירוח

<!-- s:4bef54c1c0 -->
`text start` והמתאמים `bun`,‏ `vercel` ו-`cloudflare` מגישים בניית הטמעה עם הכותרות האלה. המתאם `static` כותב אותן אל `_headers`, שאותו קוראים Cloudflare Pages ו-Netlify. בכל שירות אירוח אחר, כגון דלי אחסון או תיקיית `public/` של האתר עצמו, יש להגדיר אותן ידנית:

<!-- s:be81a4c5ec -->
| נתיב | כותרות |
| :-- | :-- |
| `/embed.js` | `Cache-Control: public, max-age=0, must-revalidate` |
| `/assets/*` | `Cache-Control: public, max-age=31536000, immutable` |
| שניהם, כשהאתר במקור אחר | `Access-Control-Allow-Origin: *` ו-`Cross-Origin-Resource-Policy: cross-origin` |

<!-- s:21eb7dc287 -->
דפדפנים מאחזרים סקריפטים מסוג מודול ו-WebAssembly באמצעות CORS, ולכן קבצים במקור אחר זקוקים ל-`Access-Control-Allow-Origin`. יש להגיש את `yoga-[hash].wasm` בתור `application/wasm`, כשהוא דחוס (ראו [WebAssembly](/docs/deploying#webassembly)).

פריסות

<!-- s:01b888e293 -->
`embed.js` עובר אימות מחדש בכל טעינת דף, כך שמבקרים חדשים מקבלים פריסה חדשה מיד. לשונית שטענה את `embed.js` הקודם עדיין מייבאת את קובצי הבנייה הקודמת כשהמבקר פותח את המסוף, אולי שעות לאחר מכן. יש להשאיר את `assets/` של הפריסה הקודמת זמין ברשת: להעתיק קבצים חדשים מעל הישנים במקום לסנכרן עם מחיקה, ולהסיר קבצים ישנים אחרי יום או יומיים. כדי לקבע בנייה, יש לשים את `assets/embed-[hash].js` שלה בתגית. גם הקבצים של אותה בנייה חייבים להישאר זמינים ברשת.

<!-- s:b748b07652 -->
כשהקבצים כבר אינם זמינים, `embed.js` רושם אזהרה אחת שמבקשת מהמבקר לטעון מחדש, ואינו מפעיל את האפליקציה או טוען מחדש את הדף בעצמו.

<!-- s:fce19037b3 -->
מדיניות אבטחת תוכן

<!-- s:de8e30a920 -->
`embed.js` אינו זקוק לסקריפטים או לסגנונות מוטבעים. יש להוסיף את הערכים הבאים למדיניות של הדף המארח, עם `'self'` במקום המקור כאשר `dist/` נמצא באותו מקור:

<!-- s:2da4077ce0 -->
| הנחיה | ערך | שימוש |
| :-- | :-- | :-- |
| `script-src` | `https://console.example.com` | `embed.js` ומקטעי הקוד שלו |
| `script-src` | `'wasm-unsafe-eval'` | Yoga, באפליקציות שמרונדרות בצד הלקוח |
| `connect-src` | `https://console.example.com` | `yoga-[hash].wasm`, וגם `/__textjs/live` לנתיבים שמרונדרים בצד השרת |
| `img-src` | `data:` | רק `<text-console mirror>` שהאפליקציה שלו מציירת `<Image>` או `<Pixels>` |

<!-- s:4ce5dcc4cb -->
טעינה עצמאית של האפליקציה

<!-- s:03e56a60b4 -->
`@textjs/app/experimental` מייצא את החלקים שמהם בנוי `embed.js`, עבור דפים שטוענים אפליקציה בדרך משלהם:

<!-- s:238cbf53ee -->
| ייצוא | תיאור |
| :-- | :-- |
| `startEmbed(paint, boot, src, element?)` | הפעולות של `embed.js`: רישום הפריים הראשון, המתנה לכוונה להשתמש במסוף ואז קריאה ל-`boot` |
| `bootEmbedClient(options)` | הפעלת אפליקציה שמרונדרת בצד הלקוח עם ניתוב בזיכרון וקלט מקלדת שמוגבל בהתאם למצב הדף |
| `bootEmbedPlayer(options)` | הפעלת נגן הפריימים לנתיב שמרונדר בצד השרת |
| `createHostInput(options)` | קלט מקלדת שפועל לפי הכללים שלעיל |
| `createTextConsoleMount(config)` | החזרת פונקציית `mount(element, shell?)` עבור `<text-console>` |
| `reserveCss(cols, rows)` | ה-CSS ששומר מקום ל-`<text-console>` |

<!-- s:f15b990353 -->
`ENGAGE_SELECTOR` ו-`BYPASS_SELECTOR` הם הבוררים של אלמנטים שמפעילים את האפליקציה ושל אלמנטים ששומרים את קלט המקשים שלהם לעצמם.
