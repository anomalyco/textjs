`<Image>`

<!-- s:35a4098e50 -->
המסופים של Chromium ושל Firefox מציירים את התמונה כספרייט פיקסלים. פיקסל ארט (256 צבעים או פחות, ללא פיקסלים שקופים חלקית) שומר על עד 8 × 16 פיקסלים לתא, ותצלומים על עד 4 × 8. Safari, טרמינלים, עותקי טקסט פשוט ודפים עם [`runtime = "server"`](/docs/server-rendering) מקבלים חצאי בלוקים `▀`: כל תא מכיל שני פיקסלים, העליון בצבע החזית והתחתון ברקע. יש להעביר `renderMode="halfblock"` כדי לצייר חצאי בלוקים בכל מקום, כפי שעשה `<Image>` בגרסה 1.3.

<!-- s:70bb4fc454 -->
| Prop | תיאור |
| :-- | :-- |
| `src` | כתובת URL של תמונה (בדפדפן בלבד) |
| `pixels` | נתוני RGBA גולמיים במבנה `{ width, height, data }`, 4 בתים לפיקסל לפי סדר השורות |
| `width` / `height` | רוחב בתאים, גובה בשורות. יש להעביר אחד מהם לשמירת יחס הממדים, או להשמיט את שניהם לקבלת 1 × 2 פיקסלים לתא (`src` משנה את הגודל עד ל-256 × 256 px לכל היותר) |
| `fit` | `contain` (ברירת מחדל), `cover` או `fill` |
| `alt` | טקסט שמוצג בזמן טעינת `src` או אם הטעינה נכשלת |
| `renderMode` | `auto` (ברירת מחדל: ספרייט כשיש תמיכה, חצאי בלוקים `▀` במקומות אחרים) או `halfblock` |

<!-- s:c106665c64 -->
`<Image>` מקבל גם מאפייני layout.

<!-- s:20dac26bff -->
`src` נטען דרך canvas, ולכן תמונות ממקור אחר דורשות CORS. `pixels` מקבל נתוני RGBA גולמיים בכל מקום, כולל בטרמינל.

<!-- s:4e3b06ef0e -->
תמונה מצוירת כחצאי בלוקים גם ב-Chromium וב-Firefox כשאי אפשר להציג אותה כספרייט אחד:

<!-- s:00d2e660eb -->
- שתי תמונות זו לצד זו באותן שורות, כמו בגלריה.
- תצלום עם טקסט לצידו. פיקסל ארט לצד טקסט נשאר ספרייט.
- תמונה שנחתכת באמצעות תיבה עם `overflow="hidden"`, או מוסתרת חלקית על ידי תיבה אחרת.
- פיקסלים שקופים מעל טקסט או מעל יותר מצבע רקע אחד.

`<Pixels>` (ניסיוני)

<!-- s:71eeeca05d -->
`@textjs/react/experimental` מייצא את `<Pixels>` למאגרי פריימים חיים בפורמט `0xRRGGBBAA`, כגון משחקים, אמולטורים ווידאו. יש לכתוב פיקסלים ארוזים ישירות לתוך `source.data` ולהגדיל את `frame` לציור מחדש.

<!-- s:2d12b69e81 -->
| Prop | תיאור |
| :-- | :-- |
| `source` | `{ width, height, data: Uint32Array }` בסדר `0xRRGGBBAA` |
| `frame` | מונה פריימים; יש להגדיל לאחר שינוי `source.data` |
| `width` / `height` | גודל התיבה בתאים ובשורות |
| `fit` | `contain` (ברירת מחדל) או `fill` |
| `pixelAspect` | הרוחב המוצג חלקי הגובה של פיקסל מקור אחד (ברירת מחדל `1`) |
| `palette` | פלטת `PackedColor[]` אופציונלית לכימות הצבעים לפיה |
| `sample` | מסנן לתצוגה החלופית בחצאי בלוקים: `nearest` (ברירת מחדל) או `average` |
| `renderMode` | `auto` (ברירת מחדל: ספרייט כשיש תמיכה, חצאי בלוקים `▀` במקומות אחרים) או `halfblock` |

<!-- s:2164b4fe56 -->
`renderMode="auto"` מצייר ספרייט מפוקסל ב-Chromium, וב-Firefox לפי כללי העיצוב של המסוף שלו (ללא מדידת ביצועים), ומשתמש בחצאי בלוקים `▀` כחלופה ב-Safari, בטרמינלים, בעותקי טקסט פשוט ובדפים עם [`runtime = "server"`](/docs/server-rendering). יש להעביר `renderMode="halfblock"` כדי לצייר חצאי בלוקים בכל מקום.

<!-- s:5d2bbbc47b -->
כדי לצייר פיקסלים ללא React, יש לייבא את `drawPixels` מתוך `@textjs/core/experimental` יחד עם `DrawPixelsOptions`, `PixelSource`, `PixelFit`, `PixelSample`, `PixelRenderMode`, `PixelEncoding` ו-`PixelRect`. האפשרות `encoding: "rgba"` שומרת על יותר מ-256 צבעים ועל שקיפות אלפא הדרגתית בתמונות סטטיות, ו-`fallback` מצייר תאים מותאמים בכל מקום שבו אי אפשר להציג את הספרייט. לפרטים על ניהול גרסאות של ייצואים ניסיוניים, ראו [שינויים שוברי תאימות](/docs/support-policy#breaking-changes).
