<!-- s:8f3fd7167d -->
ההרחבה של Text.js ל-VS Code מציגה את פריים המסוף לצד הקוד. היא משקפת את האפליקציה שרצה באמצעות `text dev`, או מרנדרת את הקובץ הפתוח עצמו כששום אפליקציה לא רצה. היא מוסיפה גם יצירת שלדים ל-App Router, קטעי קוד וקישורים לקודי שגיאה מסוג `TX###`.

<!-- s:98304b8243 -->
התקנה

<!-- s:80e247d2f7 -->
יש להתקין את [Text.js](https://marketplace.visualstudio.com/items?itemName=textjs.vscode-textjs) מתוך Visual Studio Marketplace. ב-VS Code, יש לפתוח את תצוגת ההרחבות (`⌘⇧X`) ולחפש `textjs.vscode-textjs`, או להריץ:

<!-- s:fd2344ec36 -->
ההרחבה מופעלת בכל תיקייה שמכילה אפליקציית Text.js: קובץ `text.config.ts`, או חבילה שתלויה ב-`@textjs/app` ויש בה ספריית `app/`. גם מאגרי monorepo עם כמה אפליקציות נתמכים.

<!-- s:74f1530aa8 -->
תצוגה מקדימה חיה

<!-- s:d9807ea49d -->
יש לפתוח `page.tsx`,‏ `layout.tsx` או רכיב ולהפעיל את **Text.js: Open Preview** (`⌘K V`), או ללחוץ על כפתור התצוגה המקדימה בשורת הכותרת של העורך. החלונית מציירת את הפריים באותה מעטפת DevTools ובאותם תאי Menlo כמו מסוף הדפדפן.

<!-- s:2f69f76b80 -->
התצוגה המקדימה מקבלת את הפריימים מאחד משני מקורות. התג בסרגל הכלים מציג איזה מהם פעיל:

<!-- s:f81cef21bf -->
| מקור | מתי | מה מוצג |
| :-- | :-- | :-- |
| **Live** | `text dev` פועל והאפליקציה פתוחה בכרטיסייה בדפדפן | האפליקציה האמיתית, עם המצב, הנתונים וגודל הרשת שלה |
| **Headless** | אין שרת פיתוח, או שאין כרטיסייה פתוחה | הקובץ הפתוח, שההרחבה מרנדרת בגודל החלונית |

<!-- s:f40888c2bb -->
`auto` (ברירת המחדל) משתמש ב-Live כשאפשר וב-Headless במקרים אחרים. אפשר לקבע אחד מהם דרך התג או באמצעות `textjs.preview.mode`.

<!-- s:fd587df6f1 -->
מקלדת

<!-- s:9ce66a1aa7 -->
יש ללחוץ על המסוף כדי לשלוח מקשים לאפליקציה: חצים, `Tab`, קיצורי מקשים, הקלדה והדבקה פועלים כולם, כמו בדפדפן. כדי להפסיק, יש ללחוץ מחוץ למסוף. קיצורי מקשים של העורך כמו `⌘P` ו-`⌘⇧P` עדיין נשלחים ל-VS Code. גלילה מעל המסוף שולחת אירועי גלגלת.

<!-- s:0910b5fd48 -->
בשדה הכתובת אפשר להקליד נתיב, כמו `/deployments/dpl_a1`, כדי לנווט בכל אחד מהמקורות.

<!-- s:4507d73bb4 -->
מצב Live

<!-- s:787b87d328 -->
כשתצוגה מקדימה פתוחה, שרת הפיתוח מבקש מהכרטיסיות המחוברות להזרים את הפריימים שלהן. הכרטיסיות שולחות רק את השורות שהשתנו, ומפסיקות לשלוח כשהתצוגה המקדימה נסגרת, כך שאפליקציה ללא תצוגה מקדימה פתוחה אינה נושאת בעלות כלשהי. שמירת קובץ עוברת דרך Fast Refresh, והתצוגה המקדימה מתעדכנת יחד עם הכרטיסייה.

<!-- s:86ae14b746 -->
יש להפעיל את **Follow** (`textjs.preview.followEditor`) כדי להעביר את כרטיסיית הדפדפן לנתיב של קובץ ה-`page.tsx` שבעריכה.

<!-- s:68839106d6 -->
כרטיסיות ברקע לא מקבלות פריימים של אנימציה, ולכן בדרך כלל הן משהות את הפריימים שלהן עד שהן שוב גלויות. כשתצוגה מקדימה צופה בכרטיסייה ברקע, הכרטיסייה מציירת פריים ברגע שמגיע קלט, כך שהקלדה בתצוגה המקדימה עדיין גורמת לעדכון. אנימציות בכרטיסייה ברקע מתעדכנות בערך פעם בשנייה. כדי לשמור על תנועה חלקה שלהן, יש להציב את האפליקציה בחלון משלה.

<!-- s:1ae6e7077f -->
מצב Headless

<!-- s:1cddf967be -->
ההרחבה מפעילה תוכנית הרצה קטנה בפרויקט. היא טוענת קובצי נתיבים דרך Vite ו-`@textjs/app` של הפרויקט עצמו, כך שכינויים, TypeScript ו-JSX מתנהגים כמו ב-`text dev`. היא מעגנת את App Router בנתיב של הקובץ הפתוח, עם ה-layout שלו, באמצעות היסטוריה בזיכרון:

<!-- s:23d9451fef -->
| קובץ | תצוגה מקדימה |
| :-- | :-- |
| `app/page.tsx` | `/` |
| `app/(shop)/items/[id]/page.tsx` | `/items/id` (מקטעים דינמיים משתמשים בשם שלהם) |
| `app/blog/[[...slug]]/layout.tsx` | `/blog` |
| `components/Card.tsx` | הייצוא המוגדר כברירת מחדל, או הייצוא הראשון בשם PascalCase, ללא props |

<!-- s:f111cbfc61 -->
קריאות `fetch("/api/...")` לאותו מקור מפעילות את מטפלי ה-`route.ts` בתוך התהליך, כמו ב-[`text run`](/docs/terminal). הרשת מותאמת לגודל החלונית, ושמירת כל קובץ באפליקציה מרנדרת אותה מחדש. שגיאות מופיעות מעל הפריים, עם קישורים לדפי ה-`TX###` שלהן.

אמון בסביבת העבודה

<!-- s:ddcdd0b053 -->
התצוגה המקדימה ושרת הפיתוח מריצים את קוד הפרויקט (הגדרות Vite,‏ `text.config.*` ורכיבים). במצב מוגבל ההרחבה מציעה רק קטעי קוד, יצירת שלדים וקישורי שגיאות, ומתעלמת מ-`textjs.preview.runtime`,‏ `textjs.devServer.command` ו-`textjs.devServer.url` שבהגדרות סביבת העבודה. כדי להפעיל את התצוגה המקדימה, יש לתת אמון בסביבת העבודה. קבצים מחוץ לתיקיות של סביבת העבודה לעולם אינם מוצגים בתצוגה מקדימה.

<!-- s:5ae438610c -->
אופן הפעולה

<!-- s:857bac4692 -->
`text dev` מספק שלוש נקודות קצה לעורכים. הן עונות רק לחיבורי loopback שממוענים למארח loopback (`localhost`, `127.0.0.1`, `[::1]`), ורק לבקשות ללא `Origin` או עם המקור של שרת הפיתוח עצמו. בקשות חוצות אתרים ובקשות `no-cors` מדפדפנים נדחות:

<!-- s:2345c81baf -->
| נקודת קצה | |
| :-- | :-- |
| `GET /__textjs/status` | שורש הפרויקט, כרטיסיות מחוברות, גודל הרשת והנתיב הנוכחי |
| `GET /__textjs/frames` | אירועים שנשלחים מהשרת: אירוע `frame` אחד לכל שינוי, מקודד כהפרשים בין שורות |
| `POST /__textjs/input` | מקש, הדבקה, טקסט מ-IME או ממקש מת (`text`), גלגלת או ניווט עבור הכרטיסייה. נדרשים JSON והכותרת `x-textjs-mirror: 1`, כך שאתרים אחרים לא יכולים לשלוח הקשות |

<!-- s:6693972af6 -->
כרטיסיות שולחות פריימים לשרת הפיתוח דרך שקע ה-HMR של Vite, שדורש אסימון ייחודי לכל שרת. פורמט התקשורת מיוצא מתוך `@textjs/app/frame-protocol` (`FrameEncoder`, `FrameDecoder`, `parseInputMessage`) לצורך בניית מציג עצמאי. שום חלק מזה אינו קיים בפלט של `text build`.
