מתאמים

<!-- s:04908c6c09 -->
| מתאם | פלט | הרצה |
| :-- | :-- | :-- |
| *(ללא)* | `dist/` + `dist/.text/server` | `text start` (Node) |
| `static` | `dist/` | כל שירות אירוח סטטי |
| `bun` | `dist/server.js` | `bun dist/server.js` |
| `vercel` | `.vercel/output` | Vercel (Build Output API v3) |
| `cloudflare` | `dist/` + `_worker.js` | Cloudflare Pages |

<!-- s:7e755a5c9f -->
אפשר להגדיר את המתאם גם באמצעות `TEXTJS_ADAPTER`. כאשר `text build` רץ ב-Vercel (`VERCEL=1`) או ב-Cloudflare Pages (`CF_PAGES=1`), המתאם המתאים נבחר אוטומטית.

<!-- s:9d8df946e5 -->
מתאמי השרת (`bun`, `vercel` ו-`cloudflare`) מפעילים את אותו רצף עיבוד כמו `text start`: [middleware](/docs/middleware), `rewrites`, [מטפלי נתיב](/docs/route-handlers) עם [מטמון הנתיבים](/docs/caching), משאבים סטטיים, ואז מסמך המסוף עבור כתובות URL של דפים. לקוחות טרמינל כמו curl מקבלים במקום זאת את הפריים הראשון של הדף כטקסט ANSI. ב-`vercel` וב-`cloudflare` זה חל על דפים סטטיים בלבד (ראו [curl ולקוחות טרמינל](/docs/curl)). מתאמי השרת מגישים קבצים ששמם כולל גיבוב תחת `/assets/` עם `Cache-Control: public, max-age=31536000, immutable`.

אירוח סטטי

<!-- s:9ebd0d2866 -->
יש להשתמש בו בשירותי אירוח ללא שרת, כמו GitHub Pages, S3 או CDN. מטפלי נתיב מסוג `GET` עם `dynamic = "force-static"` או `revalidate` עוברים רינדור מראש לקבצים: `app/api/feed.json/route.ts` הופך ל-`dist/api/feed.json`. עותק של `index.html` נכתב אל `404.html` כדי שקישורים עמוקים יפתחו את אפליקציית המסוף. שירותי אירוח סטטיים לא יכולים להבחין בין curl לדפדפן, ולכן curl מקבל את דף ה-HTML.

<!-- s:1e90536a2a -->
הבנייה נכשלת ומפרטת את כל הסיבות אם האפליקציה צריכה שרת: `middleware.ts`, [נתיבים מרונדרים בצד השרת](/docs/server-rendering), מטפלי נתיב דינמיים, מטפלי נתיב עם מקטעים דינמיים, או מתודות שאינן `GET`. יש להגדיר `rewrites` בשירות האירוח במקום זאת.

Vercel

<!-- s:b9d1e3b495 -->
אפשר גם לדחוף למאגר Git שמחובר ל-Vercel: הבנייה מריצה את `text build`, מזהה את Vercel וכותבת את `.vercel/output`.

<!-- s:3ee6894582 -->
| פלט | תוכן |
| :-- | :-- |
| `static/` | תוצר הבנייה של הלקוח (תחת `basePath`) |
| `functions/_textjs/server.func` | פונקציית Node.js 22 אחת שמשרתת כל מטפל נתיב, עם הזרמה |
| `functions/_middleware.func` | Edge Routing Middleware: `middleware.ts`, ונתיבים קנוניים לכל אפליקציה |
| `config.json` | כותרות משאבים, כללי התאמה של middleware, שכתובים, נתיבי מטפלים ומסמך המסוף |

<!-- s:3f3ba93b7d -->
ה-edge middleware משתמש בפרוטוקול `x-middleware-next` / `x-middleware-rewrite`, ולכן דריסות כותרות ושכתובים מתבצעים בנתב של Vercel לפני ההגעה לפונקציה או ל-CDN. כל כללי ההתאמה חולקים תבנית `src` אחת של נתיב. בקשות שאף כלל התאמה לא מכסה מדלגות על ה-middleware, אלא אם ייתכן שהנתיב שלהן אינו בצורה קנונית (קידודי אחוזים, תווים שמנתח URL מקודד, `//`, מקטעי `.` או `..`, לוכסן בסוף). לאחר מכן ה-middleware מתאים את הנתיב הקנוני, בודק `has` / `missing`, ומשכתב את הבקשה לנתיב הזה כדי ש-Vercel ינתב אותה באותו אופן. אפליקציות ללא `middleware.ts` מקבלות את אותה פונקציית edge, שמבצעת רק את השכתוב. מכיוון שכל בנייה כוללת פונקציית Edge, יש לפרוס מחשבון Vercel מחובר: פריסות אנונימיות (`vercel deploy --temporary`) לא מקבלות פונקציות Edge.

<!-- s:b5af065e25 -->
פונקציית המטפל היא פנימית. כל נתיב מטפל מעביר לה את הנתיב התואם בכותרת הבקשה `x-textjs-path`. הכותרת הזאת מוסרת מכל בקשה לפני ואחרי middleware, וה-edge middleware לעולם אינו מעביר כותרת כזאת (מהלקוח או מ-`middleware.ts`), כך שרק נתיבי המטפלים יכולים להגדיר אותה. בקשות אל `/_textjs/*` מחזירות `404` בלי להריץ את הפונקציה, לפני ואחרי middleware ושכתובים. הנתיבים שנוצרים מותאמים תוך הבחנה בין אותיות גדולות לקטנות, כמו כללי ההתאמה והשכתובים בכל שירות אירוח אחר.

<!-- s:5e18b8a450 -->
בדיקות המתאם מריצות את הפלט הזה מול אמולציה מקומית של הנתב של Vercel. ההתנהגות שלו בהתאמת `src`, בלכידות `dest`, בהמרות כותרות ובנתיבי `status` נבדקה מול פריסות אמיתיות; Edge middleware לא נבדק כך, משום שאי אפשר לפרוס אותו באופן אנונימי.

Cloudflare Pages

<!-- s:6109800459 -->
הפלט משתמש במצב המתקדם של Pages:

<!-- s:9f0923168f -->
| קובץ | מטרה |
| :-- | :-- |
| `_worker.js` | Middleware, שכתובים, מטפלי נתיב ומסמך המסוף |
| `_routes.json` | שולח כל בקשה ל-worker. ללא middleware או `basePath`, הנתיב `/assets/*` נשאר ב-CDN הסטטי של Pages |
| `_headers` | שמירה בלתי משתנה במטמון עבור `/assets/*` (נוספת לסוף הקובץ הקיים) |
| `404.html` | גורם ל-Pages להשיב לקבצים חסרים עם `404` במקום עם האפליקציה (נשמר אם כבר קיים) |

<!-- s:9bc2b010d1 -->
`.text/` (חבילות שרת ומניפסטים של הבנייה) מוסרת מ-`dist/`, משום ש-Pages מפרסם את הספרייה כפי שהיא.

<!-- s:1200dbc88d -->
יש להפעיל את דגל התאימות `nodejs_compat` בפרויקט Pages (Settings → Runtime) או ב-`wrangler.toml`; מטמון הנתונים משתמש ב-`AsyncLocalStorage`. קבצים סטטיים מוגשים דרך הקישור `ASSETS`, ואימות מחדש ברקע משתמש ב-`ctx.waitUntil()`.

<!-- s:0bb76cfebb -->
עם middleware, כל בקשה מפעילה את ה-worker, כולל משאבים ששמם כולל גיבוב, כדי שה-middleware יראה כל נתיב שדרכו אפשר להגיע לקובץ. כל בקשה שמפעילה את ה-worker היא הפעלה אחת של Functions ונספרת במכסת הבקשות של Workers. בטעינת דף, מדובר במסמך ובכל קובץ שהוא מביא (2 עבור אפליקציית בדיקה קטנה עם חבילת JavaScript אחת; יותר עבור אפליקציות עם יותר קבצים). בתוכנית Workers Free, לאחר מיצוי המכסה היומית Pages מגיש קבצים סטטיים ללא ה-worker, וכך מדלג על middleware. אם middleware מגן על משהו ב-`dist/`, יש להגדיר את Settings → Runtime → Fail open / closed לערך **Fail closed**.

סייגים

<!-- s:f45e3fb003 -->
- `proxy` ב-`text.config.ts` רץ רק ב-`text dev` וב-`text start`; המתאמים לא כוללים אותו. יש להשתמש ב-`rewrites`, שכל מתאם שרת תומך בהם.
- לכל מופע serverless יש מטמון משלו בזיכרון. ראו [שמירה במטמון](/docs/caching#platform-notes).
- `rewrites` שמשתמשים בקבוצות גולמיות של ביטויים רגולריים מתורגמים לנתיבי Vercel במידת האפשר; פרמטרים בעלי שם (`:slug`, `:path*`) מתורגמים במדויק.
