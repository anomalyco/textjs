<!-- s:5b67b32177 -->
שמירת תגובות של מטפלי נתיב ונתונים במטמון, ולאחר מכן אימות מחדש לפי תזמון או לפי דרישה. רשומות מיושנות מוגשות מיד בזמן שרענון יחיד פועל ברקע.

<!-- s:be697310c8 -->
מטפלי נתיב

<!-- s:e85fc29fe2 -->
מטפלי נתיב מסוג `GET` הם דינמיים כברירת מחדל. כדי להפעיל שמירה במטמון, יש להשתמש בהגדרות מקטע הנתיב:

<!-- s:e4ccf65c67 -->
| ייצוא | התנהגות |
| :-- | :-- |
| *(ללא)* | הפעלה בכל בקשה |
| `dynamic = "force-static"` | שמירה במטמון עד לאימות מחדש |
| `revalidate = N` | שמירה במטמון; התיישנות לאחר `N` שניות |
| `revalidate = 0` או `dynamic = "force-dynamic"` | הפעלה בכל בקשה |

<!-- s:274c053db6 -->
ערכים אחרים של `dynamic` נכשלים עם `TX031`. זה כולל את `"error"` של Next.js, מכיוון ש-Text.js לא יכול לזהות מתי מטפל קורא את הבקשה.

<!-- s:0fae4045f6 -->
מטפלים שנשמרים במטמון מקבלים רשומה אחת לכל שם נתיב, וה-`request` שלהם נראה כפי שהיה נראה בזמן הבנייה: ללא מחרוזת שאילתה, כותרות, קובצי cookie או גוף בקשה. יש לקרוא אותם במטפל דינמי במקום זאת. רק `GET` ו-`HEAD` נשמרים במטמון. תגובות עם קוד מצב `5xx`, כותרת `Set-Cookie` או `Cache-Control: private` / `no-store` מוחזרות אך לעולם אינן נשמרות.

<!-- s:b618d4732f -->
כותרות

<!-- s:c0a6cf7351 -->
תגובות שנשמרו במטמון כוללות:

<!-- s:b5f8cfecb4 -->
| כותרת | ערך |
| :-- | :-- |
| `x-textjs-cache` | `MISS`, `HIT` או `STALE` |
| `Cache-Control` | `s-maxage=N, stale-while-revalidate=<1 year − N>`, או `s-maxage=31536000` עבור `force-static` |

<!-- s:c1fb73c64a -->
כאשר [middleware](/docs/middleware) מגדיר קובצי cookie, משכתב את הבקשה או דורס את כותרות הבקשה, הכותרת שנוצרת הופכת ל-`private, no-cache, no-store, max-age=0, must-revalidate`, כך שמטמונים משותפים לעולם אינם משתמשים שוב בהחלטה שהתקבלה עבור מבקר מסוים. כותרת `Cache-Control` שהמטפל הגדיר נשמרת.

<!-- s:ae27ba22c7 -->
ב-`text dev`, הגדרות המקטע חלות אך דבר אינו נשמר, ולכן כל בקשה מפעילה את המטפל.

<!-- s:64841df645 -->
מטמון נתונים

<!-- s:2187e2262b -->
כדי לשמור פונקציה אסינכרונית כלשהי במטמון, יש להשתמש ב-`unstable_cache` מתוך `@textjs/app/cache`:

<!-- s:4c26e099ff -->
המפתח מורכב מחלקי המפתח ומהארגומנטים, המקודדים לפי ערך (ארגומנטים מסוג `undefined` ו-`null`, `Map`, `Set`, `Date` ו-`URL` נשארים מובחנים). ללא חלקי מפתח, קוד המקור של הפונקציה והמקום שבו נוצרה מזהים אותה; יש להעביר חלקי מפתח בכל פעם שהפונקציה לוכדת ערכים מההיקף החיצוני, למשל כשהיא נוצרת לכל בקשה או בתוך לולאה. התוצאות עוברות סריאליזציה ל-JSON, כך שכל קריאה מחזירה עותק חדש (ואובייקטים מסוג `Date` חוזרים כמחרוזות); תוצאה שאי אפשר לבצע לה סריאליזציה גורמת לזריקת חריגה. `cache(fn, { key, tags, revalidate })` מקבל את אותן ההגדרות כאובייקט אפשרויות.

<!-- s:608eee0e9b -->
בתוך מטפל נתיב שנשמר במטמון, רשומות הנתונים מעבירות לנתיב את התגיות שלהן ואת ערך ה-`revalidate` הקצר ביותר שלהן: אימות מחדש של `"posts"` מרענן גם את `/api/posts`. קריאת נתונים עם `revalidate: 0` הופכת את הנתיב לדינמי.

<!-- s:5537f337ee -->
הגשת ערך מיושן בזמן אימות מחדש

<!-- s:7d23e84252 -->
לאחר שגיל הרשומה חורג מ-`revalidate`:

<!-- s:d4dd1966dd -->
1. הבקשה הבאה מקבלת מיד את הערך המיושן (`STALE`).
2. רענון יחיד פועל ברקע; בקשות מקבילות חולקות אותו.
3. אם הרענון זורק חריגה, הערך המיושן ממשיך להיות מוגש והשגיאה נרשמת ביומן.

<!-- s:e6db7819cc -->
ב-Vercel וב-Cloudflare, רענונים ברקע נרשמים באמצעות `waitUntil()`. רשומות שגילן עולה על שנה תמיד מחושבות מחדש בחזית.

<!-- s:5854b096d2 -->
אימות מחדש לפי דרישה

<!-- s:686aa7f2f3 -->
| קריאה | ביטול תוקף |
| :-- | :-- |
| `revalidateTag("posts")` | כל מה שמתויג ב-`posts`; הבקשה הבאה מחשבת מחדש |
| `revalidateTag("posts", "max")` | סימון כמיושן; הבקשה הבאה מקבלת את הערך המיושן בזמן הרענון |
| `revalidatePath("/api/feed")` | הנתיב הזה |
| `revalidatePath("/api/posts/[id]")` | כל נתיב של נתיב דינמי |
| `revalidatePath("/api", "layout")` | כל מה שתחת `/api` |

<!-- s:b132bd50eb -->
שתיהן מחזירות promise. במאגר שבזיכרון ביטול התוקף מיידי; יש להמתין לו באמצעות `await` כאשר [מאגר מותאם אישית](#custom-cache-stores) הוא אסינכרוני.

<!-- s:2aab4b4d00 -->
מאגרי מטמון מותאמים אישית

<!-- s:7bee24a364 -->
מאגר ברירת המחדל הוא LRU בזיכרון (1,000 רשומות, כ-50 MB) לכל מופע שרת. כדי לשתף מטמון בין מופעים, יש להפנות את `cacheHandler` למודול שמייצא `CacheStore` כייצוא ברירת מחדל:

<!-- s:593c57fca5 -->
הרשומות הן JSON רגיל. `setCacheStore(store)` מתקין במקום זאת מאגר בזמן הריצה.

הערות לגבי פלטפורמות

<!-- s:5418a08901 -->
- לכל מופע serverless (פונקציות Vercel, סביבות Cloudflare isolates) יש מטמון משלו בזיכרון. `Cache-Control: s-maxage` מאפשר גם ל-CDN של הפלטפורמה לשמור תגובות במטמון; אימות מחדש לפי דרישה אינו מנקה את מטמון ה-CDN. יש להשתמש ב-`cacheHandler` משותף כאשר `revalidateTag` חייב להגיע לכל מופע.
- Cloudflare דורש את הדגל `nodejs_compat` (המטמון משתמש ב-`AsyncLocalStorage`). ראו [פריסה](/docs/deploying).
