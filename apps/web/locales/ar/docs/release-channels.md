يُوزّع Text.js عبر ثلاثة وسوم توزيع في npm. تُحدّث إصدارات جميع الحزم (`@textjs/app`، `@textjs/react`، `@textjs/core`، `@textjs/font`، `@textjs/opencode`، `create-text-app` و `eslint-plugin-textjs`) بالتزامن، لذا يصف رقم إصدار واحد إطار العمل بأكمله.

<!-- s:a2c3664770 -->
القنوات

<!-- s:6b5c5ba172 -->
| القناة | وسم التوزيع | الإصدار | التثبيت |
| :-- | :-- | :-- | :-- |
| المستقرة | `latest` | `1.0.x` | `bun add @textjs/app` |
| التجريبية | `canary` | `1.0.x-canary.N` | `bun add @textjs/app@canary` |
| الدعم طويل الأمد | `lts`، `v1-lts` | يُنشر عند صدور `2.0.0` | `bun add @textjs/app@lts` |

<!-- s:27e8b81dc6 -->
استخدم القناة المستقرة في بيئة الإنتاج. استخدم القناة التجريبية لتجربة الإصلاحات والميزات يوم وصولها إلى `dev`. عند توفر سلسلة إصدارات ذات دعم طويل الأمد، استخدمها إذا كنت ترقي مرة واحدة في السنة.

<!-- s:abc686bd76 -->
القناة المستقرة

<!-- s:df32c144c0 -->
تتبع الإصدارات المستقرة [الإصدارات الدلالية](https://semver.org): تصلح الإصدارات التصحيحية الأخطاء، وتضيف الإصدارات الفرعية ميزات متوافقة مع الإصدارات السابقة، وقد تكسر الإصدارات الرئيسية توافق واجهات API بعد فترة إهمال. يُرقّى إصدار تجريبي اجتاز مجموعة الاختبارات الكاملة إلى إصدار مستقر، ويُنشر مع إثبات مصدر من npm.

<!-- s:7307c50761 -->
القناة التجريبية

<!-- s:db409040ca -->
تُفحص الأنواع وتُجرى الاختبارات لكل عملية دفع إلى `dev` في المستودع الرسمي، ثم تُنشر بوصفها الإصدار التصحيحي التالي مع اللاحقة `-canary.N`:

<!-- s:d8b8cffefe -->
| `latest` | عملية الدفع إلى `dev` | الإصدار المنشور |
| :-- | :-- | :-- |
| `1.0.0` | الأولى | `1.0.1-canary.0` |
| `1.0.0` | الثانية | `1.0.1-canary.1` |
| `1.0.1` | التالية | `1.0.2-canary.0` |

<!-- s:dd9c67b1f5 -->
تتابع قيمة `N` من أعلى إصدار تجريبي موجود على npm، لذا لا تتكرر الأرقام أبدًا. لا تُسجّل الإصدارات التجريبية في المستودع. أضف `[skip canary]` إلى رسالة الإيداع لتخطي النشر.

<!-- s:762894d754 -->
الإصدارات التجريبية هي نواتج بناء الفرع `dev`، الذي تُدمج فيه جميع طلبات السحب. قد تغيّر واجهات API غير الصادرة أو تزيلها دون إشعار. ثبّت رقم إصدار تجريبي محدد إذا كنت تعتمد على أحدها.

إعداد إصدار

<!-- s:a3217d58a6 -->
يرفع المشرفون إصدارات جميع حزم مساحة العمل بالتزامن باستخدام نصوص الإصدار البرمجية:

<!-- s:614a1ea872 -->
يعيد الأمر `release:version` كتابة كل ملف `package.json` وثوابت الإصدار التي تعكسه (`VERSION` و `rendererVersion` الخاص بآلية التوفيق)، ويرفض التشغيل عند اختلاف إصدارات الحزم، ويطبع الخيار `--dry-run` الخطة. يبني الأمر `release:publish` الحزم ويجهّزها للنشر (مع حل مراجع `workspace:*`)، ويطبّق `publishConfig`، ويرفض وضع إصدار تمهيدي على `latest` أو إصدار مستقر على `canary`، ويتخطى الإصدارات الموجودة بالفعل على npm.
