<!-- s:88013af27d -->
يشغّل middleware الشيفرة قبل اكتمال الطلب. ويمكنه إعادة التوجيه، وإعادة الكتابة، وتعيين الترويسات وملفات تعريف الارتباط، أو إرجاع استجابة بنفسه.

<!-- s:895d99d1b5 -->
اصطلاح التسمية

<!-- s:9e6d75b727 -->
أنشئ `middleware.ts` في جذر المشروع (أو `src/`)، بجوار `app/`. صدّر دالة `middleware` (أو تصديرًا افتراضيًا) وكائن `config` اختياريًا.

<!-- s:a4d39cdaaf -->
يعمل middleware قبل [معالجات المسارات](/docs/route-handlers) والملفات الثابتة وصفحات وحدة التحكم، عند تشغيل `text dev` و `text start` ومع كل [محوّل نشر](/docs/deploying) للخادم. ويستخدم واجهتي الويب `Request` و `Response`، لذا يعمل الملف نفسه على Node و Bun و Vercel Edge و Cloudflare Workers.

<!-- s:dda0880da2 -->
مطابقة المسارات

<!-- s:1e1ec8c339 -->
بدون `config.matcher`، يعمل middleware لكل طلب. تستخدم أنماط المطابقة الصياغة نفسها المستخدمة في Next.js:

<!-- s:473d472bc8 -->
| نمط المطابقة | المسارات المطابقة |
| :-- | :-- |
| `/about` | `/about` و `/about/` |
| `/blog/:slug` | `/blog/hello` |
| `/docs/:path*` | `/docs`، `/docs/a/b` |
| `/a/:rest+` | `/a/b`، وليس `/a` |
| `/user/:id(\\d+)` | `/user/42`، وليس `/user/ada` |
| `/((?!api/).*)` | كل شيء باستثناء `/api/*` |

<!-- s:256aeeefbc -->
أضف شروطًا باستخدام `has` و `missing` (ترويسة أو ملف تعريف ارتباط أو استعلام أو مضيف):

<!-- s:d756420343 -->
تنطبق أنماط المطابقة على اسم المسار دون `basePath`. في `text dev`، لا تشغّل طلبات الوحدات الخاصة بأداة Vite (`/@vite/*` وملفات المصدر) middleware مطلقًا.

<!-- s:75cd7297e6 -->
يحدّد كل مضيف اسم مسار موحّدًا قبل تشغيل middleware، ويستخدمه للمطابقة و `request.nextUrl` والبحث عن المسار والمعالج والملف. تُفك ترميزات النسبة المئوية ويُعاد ترميز المسار بالطريقة التي يكتبه بها `new URL()`، وتُحل المقاطع `.` و `..`، وتُزال الشرطات المائلة المتكررة والختامية. يصل `/ad%6din//users/` إلى middleware بصيغة `/admin/users`، بينما يبقى `/café` بصيغة `/caf%C3%A9`. يطابق النمط المكتوب بشرطة مائلة ختامية، مثل `/admin/`، المسار `/admin`. تتلقى الطلبات التي يحتوي مسارها على شرطة مائلة أو شرطة مائلة عكسية مرمّزة (`%2F`، `%5C`)، أو محرف تحكم أو ترميز نسبة مئوية غير صالح، الحالة `400`. تراعي المسارات حالة الأحرف: لا يطابق `/Admin` المسار `/admin`، ولا تُقدّم الملفات الثابتة إلا بأسمائها المطابقة تمامًا.

<!-- s:3f5746eb4e -->
طابق عناوين URL التي يُقدّم الملف من خلالها، لا اسم الملف وحده. تقدّم Cloudflare Pages الملف `report.html` على `/report` أيضًا، لذا لا يحمي نمط مطابقة `/report.html` المسار `/report`. أدرج كليهما، `matcher: ["/report", "/report.html"]`، أو احتفظ بالملفات المحمية في دليل وطابقه، مثل `/reports/:path*` للملفات في `public/reports/`.

NextResponse

<!-- s:880215c229 -->
| واجهة API | التأثير |
| :-- | :-- |
| `NextResponse.next()` | المتابعة إلى المسار |
| `NextResponse.redirect(url, status?)` | `307` افتراضيًا؛ يجب أن يكون `url` مطلقًا |
| `NextResponse.rewrite(url)` | تقديم مسار آخر؛ تمرير الطلبات إلى الأصول الخارجية عبر وكيل |
| `NextResponse.json(body, init?)` | الاستجابة بصيغة JSON |
| `new Response(...)` | الاستجابة بأي محتوى |

<!-- s:a8292924c3 -->
لا تُرجع شيئًا للمتابعة دون تغيير. تقبل `next()` و `rewrite()` الكائن `{ status }` لتغيير حالة الاستجابة النهائية. لا تتحكم في التوجيه إلا الاستجابات المنشأة باستخدام `NextResponse.next()` / `NextResponse.rewrite()`: تُرسل أي استجابة `Response` أخرى، بما فيها تلك التي تُرجعها `fetch()`، إلى العميل كما هي مع إزالة ترويسات `x-middleware-*` منها.

<!-- s:583e778785 -->
يستثني `request.nextUrl` القيمة `basePath` من `pathname`، بينما تتضمنها خاصية `href` والدالة `toString()`. للبقاء داخل التطبيق، انسخه: `const url = request.nextUrl.clone(); url.pathname = "/login"; return NextResponse.redirect(url);`.

الترويسات

<!-- s:37748fa2c3 -->
مرّر `request.headers` لتغيير ما تتلقاه المعالجات اللاحقة، و `headers` لإضافة ترويسات الاستجابة:

<!-- s:60bf4677c2 -->
تُضاف ترويسات استجابة middleware إلى الاستجابة النهائية ما لم يعيّن معالج المسار الترويسة نفسها.

<!-- s:ef657b8fe3 -->
ملفات تعريف الارتباط

<!-- s:5d3635224b -->
يقرأ `request.cookies` ترويسة `Cookie`؛ ويكتب `response.cookies` ترويسة `Set-Cookie`.

<!-- s:4a7b6bbf62 -->
تكون ملفات تعريف الارتباط المعيّنة في استجابة `next()` أو `rewrite()` متاحة أيضًا لمعالج المسار في الطلب نفسه.

ملاحظات

<!-- s:971c06c875 -->
- تُعرض الصفحات المعروضة على العميل في المتصفح، لذا تغيّر إعادة الكتابة إلى صفحة أخرى الملف الذي يُقدّم، لا المسار الذي يعرضه تطبيق وحدة التحكم. تعمل إعادة الكتابة إلى معالجات المسارات والملفات الثابتة والأصول الخارجية كما هو متوقع.
- يستطيع middleware قراءة جسم الطلب؛ وتظل معالجات المسارات تتلقاه. لا يُمس جسم الطلبات التي يستثنيها نمط المطابقة مطلقًا.
- يتضمن `request.url` دائمًا أصل الخادم: تُوحّد أهداف الطلبات مثل `//other.host/x` لتبدأ بشرطة مائلة واحدة.
- لا يستطيع [المحوّل الثابت](/docs/deploying#static) تشغيل middleware.
