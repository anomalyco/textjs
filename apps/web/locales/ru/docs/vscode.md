<!-- s:8f3fd7167d -->
Расширение Text.js для VS Code показывает кадр консоли рядом с кодом. Оно зеркалирует приложение, запущенное через `text dev`, или само рендерит открытый файл, если ничего не запущено. Оно также добавляет создание заготовок App Router, сниппеты и ссылки для кодов ошибок `TX###`.

<!-- s:98304b8243 -->
Установка

<!-- s:80e247d2f7 -->
Установите [Text.js](https://marketplace.visualstudio.com/items?itemName=textjs.vscode-textjs) из Visual Studio Marketplace. В VS Code откройте раздел «Расширения» (`⌘⇧X`) и найдите `textjs.vscode-textjs` или выполните:

<!-- s:fd2344ec36 -->
Расширение активируется в любой папке с приложением Text.js: файлом `text.config.ts` или пакетом, который зависит от `@textjs/app` и содержит каталог `app/`. Монорепозитории с несколькими приложениями тоже поддерживаются.

<!-- s:74f1530aa8 -->
Предпросмотр в реальном времени

<!-- s:d9807ea49d -->
Откройте `page.tsx`, `layout.tsx` или компонент и выполните **Text.js: Open Preview** (`⌘K V`) либо нажмите кнопку предпросмотра в строке заголовка редактора. Панель рисует кадр с тем же оформлением DevTools и ячейками со шрифтом Menlo, что и консоль браузера.

<!-- s:2f69f76b80 -->
Предпросмотр получает кадры из одного из двух источников. Значок на панели инструментов показывает активный источник:

<!-- s:f81cef21bf -->
| Источник | Когда | Что вы видите |
| :-- | :-- | :-- |
| **Live** | Запущен `text dev`, и приложение открыто во вкладке браузера | Настоящее приложение с его состоянием, данными и размером сетки |
| **Headless** | Нет сервера разработки или открытой вкладки | Открытый файл, который расширение рендерит по размеру панели |

<!-- s:f40888c2bb -->
`auto` (по умолчанию) использует Live, когда это возможно, и Headless в остальных случаях. Закрепите любой из режимов через значок или настройку `textjs.preview.mode`.

<!-- s:fd587df6f1 -->
Клавиатура

<!-- s:9ce66a1aa7 -->
Щёлкните по консоли, чтобы направить ввод с клавиатуры в приложение: стрелки, `Tab`, сочетания клавиш, ввод текста и вставка работают как в браузере. Щёлкните за пределами консоли, чтобы остановить передачу ввода. Сочетания клавиш редактора, такие как `⌘P` и `⌘⇧P`, по-прежнему обрабатывает VS Code. Прокрутка над консолью отправляет события колеса мыши.

<!-- s:0910b5fd48 -->
В адресном поле можно ввести маршрут, например `/deployments/dpl_a1`, для перехода в любом из источников.

<!-- s:4507d73bb4 -->
Режим Live

<!-- s:787b87d328 -->
Пока предпросмотр открыт, сервер разработки запрашивает поток кадров у подключённых вкладок. Вкладки отправляют только изменённые строки и прекращают отправку при закрытии предпросмотра, поэтому приложение без открытого предпросмотра не несёт дополнительных затрат. Сохранение файла проходит через Fast Refresh, и предпросмотр обновляется вместе с вкладкой.

<!-- s:86ae14b746 -->
Включите **Follow** (`textjs.preview.followEditor`), чтобы вкладка браузера переходила на маршрут файла `page.tsx`, который вы редактируете.

<!-- s:68839106d6 -->
Фоновые вкладки не получают кадров анимации, поэтому обычно сохраняют текущий кадр, пока снова не станут видимыми. Пока предпросмотр следит за вкладкой, фоновая вкладка рисует кадр сразу после поступления ввода, поэтому ввод текста в предпросмотре по-прежнему вызывает обновление. Анимации в фоновой вкладке обновляются примерно раз в секунду. Поместите приложение в отдельное окно, чтобы сохранить их плавность.

<!-- s:1ae6e7077f -->
Режим Headless

<!-- s:1cddf967be -->
Расширение запускает небольшую программу в вашем проекте. Она загружает файлы маршрутов через Vite и `@textjs/app` самого проекта, поэтому псевдонимы, TypeScript и JSX работают так же, как в `text dev`. Она монтирует App Router на маршруте открытого файла вместе с его макетами, используя историю в памяти:

<!-- s:23d9451fef -->
| Файл | Предпросмотр |
| :-- | :-- |
| `app/page.tsx` | `/` |
| `app/(shop)/items/[id]/page.tsx` | `/items/id` (динамические сегменты используют своё имя) |
| `app/blog/[[...slug]]/layout.tsx` | `/blog` |
| `components/Card.tsx` | Экспорт по умолчанию или первый экспорт в PascalCase, без пропсов |

<!-- s:f111cbfc61 -->
Вызовы `fetch("/api/...")` к тому же источнику выполняют обработчики `route.ts` внутри процесса, как при [`text run`](/docs/terminal). Сетка подстраивается под размер панели, а сохранение любого файла приложения запускает повторный рендеринг. Ошибки показываются над кадром со ссылками на соответствующие страницы `TX###`.

<!-- s:36cd3f2bb4 -->
Команды

<!-- s:d542a683ff -->
| Команда | Описание |
| :-- | :-- |
| Text.js: Start Dev Server | Запускает ваш скрипт `dev` (или `text dev`) в терминале |
| Text.js: Stop Dev Server | Останавливает сервер разработки, запущенный из VS Code |
| Text.js: Open Preview | Открывает предпросмотр в реальном времени для активного файла |
| Text.js: Open in Browser Console | Открывает текущий маршрут на сервере разработки. Затем [откройте консоль браузера](/docs/installation#open-the-console) |
| Text.js: New Page | `app/<route>/page.tsx` с метаданными и типизированными `params` |
| Text.js: New Layout | `app/<route>/layout.tsx` |
| Text.js: New Route Handler | `app/<route>/route.ts` с `GET` и `POST` |
| Text.js: New Loading UI / Error Boundary / Not Found Page | `loading.tsx`, `error.tsx`, `not-found.tsx` |

<!-- s:87b5f49afb -->
Команды создания заготовок доступны и в контекстном меню папок в проводнике. Они принимают сегменты [App Router](/docs/routing), такие как `settings`, `blog/[slug]`, `docs/[...path]` и `(marketing)/about`, и не позволяют разместить `page` и `route.ts` в одном сегменте. В проектах JavaScript (без `tsconfig.json`) создаются файлы `.jsx` и `.js`.

Коды ошибок

<!-- s:5e9e2a4649 -->
Наведите указатель на код `TX###` в любом месте: в исходном коде, журналах, панели «Выходные данные» или вставленной трассировке стека. Подсказка показывает его заголовок, сообщение и пакет со ссылкой на его страницу на textjs.org. Каждый код также служит ссылкой (щелчок с `⌘`).

<!-- s:b67d013d7e -->
Строка состояния

<!-- s:be63ef7ae2 -->
Элемент `▼` показывает состояние сервера разработки и размер сетки консоли, например `▼ :3000  120×36`. Вкладки сообщают серверу разработки свой размер при каждом изменении, даже если предпросмотр не открыт. Щёлкните по элементу, чтобы открыть основные команды.

<!-- s:5b827aed4d -->
Настройки

<!-- s:457ec968c0 -->
| Настройка | По умолчанию | Описание |
| :-- | :-- | :-- |
| `textjs.preview.mode` | `auto` | `auto`, `live` или `headless` |
| `textjs.preview.followEditor` | `false` | Режим Live: переход на редактируемый маршрут |
| `textjs.preview.fontSize` | `12` | Размер шрифта ячейки (DevTools использует 12) |
| `textjs.preview.runtime` | | Бинарный файл Node.js для предпросмотра без браузера (по умолчанию: из комплекта VS Code) |
| `textjs.devServer.url` | | URL сервера разработки (по умолчанию: поиск на портах 3000–3010). Используются только loopback-адреса с `http://` |
| `textjs.devServer.command` | | Команда для Start Dev Server |

<!-- s:ea5e740ef1 -->
Доверие к рабочей области

<!-- s:ddcdd0b053 -->
Предпросмотр и сервер разработки выполняют код вашего проекта (его конфигурацию Vite, `text.config.*` и компоненты). В ограниченном режиме расширение предлагает только сниппеты, создание заготовок и ссылки на ошибки, а настройки рабочей области `textjs.preview.runtime`, `textjs.devServer.command` и `textjs.devServer.url` игнорирует. Укажите, что доверяете рабочей области, чтобы включить предпросмотр. Файлы за пределами папок рабочей области никогда не открываются в предпросмотре.

<!-- s:5ae438610c -->
Принцип работы

<!-- s:857bac4692 -->
`text dev` предоставляет три эндпоинта для редакторов. Они отвечают только на loopback-соединения, адресованные loopback-хосту (`localhost`, `127.0.0.1`, `[::1]`), и только на запросы без `Origin` или с источником самого сервера разработки. Межсайтовые запросы браузеров и запросы `no-cors` отклоняются:

<!-- s:2345c81baf -->
| Эндпоинт | |
| :-- | :-- |
| `GET /__textjs/status` | Корень проекта, подключённые вкладки, размер сетки и текущий маршрут |
| `GET /__textjs/frames` | События от сервера: одно событие `frame` на изменение, закодированное как разности строк |
| `POST /__textjs/input` | Клавиша, вставка, текст от IME или «мёртвой» клавиши (`text`), колесо мыши или навигация для вкладки. Требует JSON и заголовок `x-textjs-mirror: 1`, поэтому другие сайты не могут отправлять нажатия клавиш |

<!-- s:6693972af6 -->
Вкладки отправляют кадры серверу разработки через HMR-сокет Vite, который требует отдельный токен для каждого сервера. Формат передачи экспортируется из `@textjs/app/frame-protocol` (`FrameEncoder`, `FrameDecoder`, `parseInputMessage`), если вы хотите создать собственное средство просмотра. Ничего из этого нет в результате `text build`.
