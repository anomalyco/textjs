<!-- s:88013af27d -->
Middleware выполняет код до завершения запроса. Он может перенаправлять запросы, переписывать пути, задавать заголовки и cookie или самостоятельно возвращать ответ.

<!-- s:895d99d1b5 -->
Соглашение

<!-- s:9e6d75b727 -->
Создайте `middleware.ts` в корне проекта (или в `src/`), рядом с `app/`. Экспортируйте функцию `middleware` (или используйте экспорт по умолчанию) и необязательный `config`.

<!-- s:a4d39cdaaf -->
Middleware выполняется перед [обработчиками маршрутов](/docs/route-handlers), выдачей статических файлов и страниц консоли при запуске `text dev`, `text start` и с любым серверным [адаптером развёртывания](/docs/deploying). Он использует веб-API `Request` и `Response`, поэтому один и тот же файл работает на Node, Bun, Vercel Edge и Cloudflare Workers.

<!-- s:dda0880da2 -->
Сопоставление путей

<!-- s:1e1ec8c339 -->
Без `config.matcher` middleware выполняется для каждого запроса. Шаблоны сопоставления используют тот же синтаксис, что и Next.js:

<!-- s:473d472bc8 -->
| Шаблон | Совпадения |
| :-- | :-- |
| `/about` | `/about` и `/about/` |
| `/blog/:slug` | `/blog/hello` |
| `/docs/:path*` | `/docs`, `/docs/a/b` |
| `/a/:rest+` | `/a/b`, но не `/a` |
| `/user/:id(\\d+)` | `/user/42`, но не `/user/ada` |
| `/((?!api/).*)` | Всё, кроме `/api/*` |

<!-- s:256aeeefbc -->
Добавьте условия с помощью `has` и `missing` (заголовок, cookie, параметр запроса или хост):

<!-- s:d756420343 -->
Шаблоны применяются к пути без `basePath`. В `text dev` собственные запросы модулей Vite (`/@vite/*`, исходные файлы) никогда не запускают middleware.

<!-- s:75cd7297e6 -->
Каждый хост определяет единый канонический путь до запуска middleware и использует его для сопоставления, `request.nextUrl` и поиска маршрута, обработчика и файла. Процентные последовательности декодируются, а путь кодируется заново так, как его записывает `new URL()`; сегменты `.` и `..` разрешаются, а повторяющиеся и завершающие косые черты удаляются. `/ad%6din//users/` поступает в middleware как `/admin/users`, а `/café` остаётся `/caf%C3%A9`. Шаблон с завершающей косой чертой, например `/admin/`, соответствует `/admin`. Запросы, в пути которых есть закодированная прямая или обратная косая черта (`%2F`, `%5C`), управляющий символ или некорректное процентное кодирование, получают `400`. Маршруты чувствительны к регистру: `/Admin` не соответствует `/admin`, а статические файлы выдаются только по их точному имени.

<!-- s:3f5746eb4e -->
Сопоставляйте URL, по которым выдаётся файл, а не только его имя. Cloudflare Pages выдаёт `report.html` и по адресу `/report`, поэтому шаблон для `/report.html` не защищает `/report`. Укажите оба адреса, `matcher: ["/report", "/report.html"]`, или храните защищённые файлы в каталоге и сопоставляйте его, например `/reports/:path*` для файлов в `public/reports/`.

NextResponse

<!-- s:880215c229 -->
| API | Действие |
| :-- | :-- |
| `NextResponse.next()` | Переход к маршруту |
| `NextResponse.redirect(url, status?)` | `307` по умолчанию; `url` должен быть абсолютным |
| `NextResponse.rewrite(url)` | Выдача другого пути; внешние источники проксируются |
| `NextResponse.json(body, init?)` | Ответ в формате JSON |
| `new Response(...)` | Ответ с любым содержимым |

<!-- s:a8292924c3 -->
Не возвращайте ничего, чтобы продолжить без изменений. `next()` и `rewrite()` принимают `{ status }` для изменения статуса итогового ответа. Только ответы, созданные через `NextResponse.next()` / `NextResponse.rewrite()`, управляют маршрутизацией: любой другой `Response`, включая возвращённый из `fetch()`, отправляется клиенту без изменений, но с удалёнными заголовками `x-middleware-*`.

<!-- s:583e778785 -->
`request.nextUrl` исключает `basePath` из `pathname`, а его `href` и `toString()` включают его. Чтобы остаться внутри приложения, клонируйте его: `const url = request.nextUrl.clone(); url.pathname = "/login"; return NextResponse.redirect(url);`.

Заголовки

<!-- s:37748fa2c3 -->
Передайте `request.headers`, чтобы изменить заголовки, которые получат последующие обработчики, и `headers`, чтобы добавить заголовки ответа:

<!-- s:60bf4677c2 -->
Заголовки ответа из middleware добавляются к итоговому ответу, если обработчик маршрута не задаёт тот же заголовок.

<!-- s:ef657b8fe3 -->
Cookie

<!-- s:5d3635224b -->
`request.cookies` читает заголовок `Cookie`; `response.cookies` записывает `Set-Cookie`.

<!-- s:4a7b6bbf62 -->
Cookie, заданные в ответе `next()` или `rewrite()`, доступны и обработчику маршрута в том же запросе.

Примечания

<!-- s:971c06c875 -->
- Страницы с клиентским рендерингом рендерятся в браузере, поэтому переписывание пути на другую страницу меняет выдаваемый файл, а не маршрут, который рендерит консольное приложение. Переписывание путей на обработчики маршрутов, статические файлы и внешние источники работает ожидаемым образом.
- Middleware может читать тело запроса; обработчики маршрутов по-прежнему получают его. Тело запросов, исключённых шаблоном сопоставления, никогда не затрагивается.
- `request.url` всегда содержит источник сервера: адреса запросов вроде `//other.host/x` нормализуются до одной начальной косой черты.
- [Статический адаптер](/docs/deploying#static) не может выполнять middleware.
