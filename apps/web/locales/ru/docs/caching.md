<!-- s:5b67b32177 -->
Кешируйте ответы обработчиков маршрутов и данные, затем ревалидируйте их по таймеру или по требованию. Устаревшие записи возвращаются сразу, пока в фоне выполняется одно обновление.

<!-- s:be697310c8 -->
Обработчики маршрутов

<!-- s:e85fc29fe2 -->
Обработчики маршрутов `GET` по умолчанию динамические. Включите кеширование в конфигурации сегмента маршрута:

<!-- s:e4ccf65c67 -->
| Экспорт | Поведение |
| :-- | :-- |
| *(нет)* | Выполняется при каждом запросе |
| `dynamic = "force-static"` | Кешируется до ревалидации |
| `revalidate = N` | Кешируется; устаревает через `N` секунд |
| `revalidate = 0` или `dynamic = "force-dynamic"` | Выполняется при каждом запросе |

<!-- s:274c053db6 -->
Другие значения `dynamic` вызывают ошибку `TX031`. В их числе `"error"` из Next.js, поскольку Text.js не может определить, когда обработчик читает запрос.

<!-- s:0fae4045f6 -->
Для кешируемых обработчиков создаётся одна запись на каждый путь, а их `request` выглядит так же, как во время сборки: без строки запроса, заголовков, cookie и тела. Читайте их в динамическом обработчике. Кешируются только `GET` и `HEAD`. Ответы со статусом `5xx`, заголовком `Set-Cookie` или `Cache-Control: private` / `no-store` возвращаются, но никогда не сохраняются.

<!-- s:b618d4732f -->
Заголовки

<!-- s:c0a6cf7351 -->
Кешированные ответы содержат:

<!-- s:b5f8cfecb4 -->
| Заголовок | Значение |
| :-- | :-- |
| `x-textjs-cache` | `MISS`, `HIT` или `STALE` |
| `Cache-Control` | `s-maxage=N, stale-while-revalidate=<1 year − N>` или `s-maxage=31536000` для `force-static` |

<!-- s:c1fb73c64a -->
Когда [middleware](/docs/middleware) устанавливает cookie, переписывает путь или переопределяет заголовки запроса, сгенерированный заголовок становится `private, no-cache, no-store, max-age=0, must-revalidate`, поэтому общие кеши никогда не воспроизводят решение, принятое для отдельного посетителя. Заголовок `Cache-Control`, заданный обработчиком, сохраняется.

<!-- s:ae27ba22c7 -->
В `text dev` конфигурация сегмента применяется, но ничего не сохраняется, поэтому каждый запрос запускает обработчик.

<!-- s:64841df645 -->
Кеш данных

<!-- s:2187e2262b -->
Кешируйте любую асинхронную функцию с помощью `unstable_cache` из `@textjs/app/cache`:

<!-- s:4c26e099ff -->
Ключ состоит из частей ключа и аргументов, закодированных по значению (аргументы `undefined` и `null`, `Map`, `Set`, `Date` и `URL` остаются различимыми). Если части ключа не заданы, функцию идентифицируют её исходный код и место создания; передавайте части ключа, когда функция захватывает значения в замыкании, например при создании для каждого запроса или в цикле. Результаты сериализуются в JSON, поэтому каждый вызов возвращает новую копию (а объекты `Date` возвращаются в виде строк); если результат нельзя сериализовать, выбрасывается исключение. `cache(fn, { key, tags, revalidate })` принимает те же настройки в виде объекта параметров.

<!-- s:608eee0e9b -->
Внутри кешируемого обработчика маршрута записи данных передают маршруту свои теги и наименьшее значение `revalidate`: ревалидация `"posts"` обновляет и `/api/posts`. Вызов данных с `revalidate: 0` делает маршрут динамическим.

<!-- s:5537f337ee -->
Выдача устаревших данных при ревалидации

<!-- s:7d23e84252 -->
Когда возраст записи превышает `revalidate`:

<!-- s:d4dd1966dd -->
1. Следующий запрос немедленно получает устаревшее значение (`STALE`).
2. В фоне выполняется одно обновление; параллельные запросы используют его совместно.
3. Если обновление выбрасывает исключение, устаревшее значение продолжает возвращаться, а ошибка записывается в журнал.

<!-- s:e6db7819cc -->
На Vercel и Cloudflare фоновые обновления регистрируются через `waitUntil()`. Записи старше года всегда пересчитываются в основном потоке.

<!-- s:5854b096d2 -->
Ревалидация по требованию

<!-- s:686aa7f2f3 -->
| Вызов | Что инвалидируется |
| :-- | :-- |
| `revalidateTag("posts")` | Всё с тегом `posts`; следующий запрос запускает пересчёт |
| `revalidateTag("posts", "max")` | Помечает данные как устаревшие; следующий запрос получает устаревшие данные, пока выполняется обновление |
| `revalidatePath("/api/feed")` | Указанный путь |
| `revalidatePath("/api/posts/[id]")` | Каждый путь динамического маршрута |
| `revalidatePath("/api", "layout")` | Всё внутри `/api` |

<!-- s:b132bd50eb -->
Обе функции возвращают промис. Для хранилища в памяти инвалидация происходит немедленно; используйте `await`, если [пользовательское хранилище](#custom-cache-stores) асинхронное.

<!-- s:2aab4b4d00 -->
Пользовательские хранилища кеша

<!-- s:7bee24a364 -->
Хранилище по умолчанию — LRU в памяти (1000 записей, около 50 МБ) для каждого экземпляра сервера. Чтобы использовать общий кеш для нескольких экземпляров, укажите в `cacheHandler` модуль, который экспортирует `CacheStore` по умолчанию:

Записи хранятся в обычном JSON. Вместо этого `setCacheStore(store)` устанавливает хранилище во время выполнения.

Примечания по платформам

<!-- s:5418a08901 -->
- У каждого serverless-экземпляра (функции Vercel, изолята Cloudflare) собственный кеш в памяти. `Cache-Control: s-maxage` позволяет CDN платформы тоже кешировать ответы; ревалидация по требованию не очищает CDN. Используйте общий `cacheHandler`, если `revalidateTag` должен затрагивать каждый экземпляр.
- Cloudflare требует флаг `nodejs_compat` (кеш использует `AsyncLocalStorage`). См. [Развёртывание](/docs/deploying).
