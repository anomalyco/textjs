<!-- s:c351b288ae -->
`text mcp` запускает ваш каталог `app/` без графического интерфейса, внутри процесса, и предоставляет к нему доступ по [протоколу Model Context Protocol](https://modelcontextprotocol.io), чтобы агенты для написания кода могли использовать его без DevTools. Агент перемещается по маршрутам, нажимает клавиши, читает кадры как обычный текст и вызывает обработчики маршрутов.

<!-- s:c66b3eaae7 -->
Для `text mcp` нужен Bun. При запуске через Node он перезапускает себя через Bun, если `bun` есть в вашем `PATH`, а иначе завершается с ошибкой `TX019`. Клиенты MCP запускают его за вас, поэтому вручную вы запускаете его редко.

<!-- s:0ecddf15e1 -->
Настройка

<!-- s:91bda9ef42 -->
Каждый клиент запускает `text mcp` из каталога вашего проекта. Используйте `bunx --bun`, чтобы файлы маршрутов выполнялись как TypeScript.

Инструменты

<!-- s:93ae76f73d -->
| Инструмент | Описание |
| :-- | :-- |
| `list_routes` | Страницы и обработчики маршрутов в `app/`, а также текущее местоположение |
| `navigate` | Добавление или замена пути, переход `back` / `forward` |
| `read_frame` | Кадр в виде текста с маршрутом, размером, фокусом и курсором. `styles: true` добавляет цвета и атрибуты для каждого span |
| `press` | Сочетания клавиш: `"down"`, `"ctrl+k"`, `"shift+tab"`, `"tab tab enter"`, `"down*3"` |
| `type` | Ввод текста с нажатием клавиши для каждого символа (до 2000; для большего объёма используйте `paste`). `submit: true` нажимает Enter после ввода |
| `paste` | Одно событие вставки, как `⌘V` |
| `scroll` | Прокрутка колёсиком мыши на `rows` (и `cols`). `<ScrollBox>` прокручивается колёсиком без клавиатурного фокуса |
| `resize` | Установка размера сетки в столбцах и строках |
| `inspect_tree` | Дерево компонентов с границами на экране и всеми id элементов, способных получить фокус |
| `find` | Границы каждого совпадения и компонент под ним |
| `wait_for` | Ожидание появления или исчезновения текста либо перехода приложения в состояние покоя |
| `logs` | Перехваченный вывод `console.*` и ошибки React |
| `fetch` | Вызов обработчика `route.ts` внутри процесса. Тела читаются до `maxBytes`; потоки событий читаются в течение `streamMs`, затем отменяются |
| `reload` | Повторный импорт приложения после изменения файлов |

<!-- s:526235e5c5 -->
Инструменты ввода возвращают новый кадр, поэтому агенту не нужен отдельный вызов `read_frame` после каждой клавиши. Текущий кадр и список маршрутов доступны и как ресурсы `text://frame` и `text://routes`.

<!-- s:45e18bfa25 -->
Кадры и состояние покоя

<!-- s:f2e8fe0f06 -->
Прежде чем прочитать кадр, любой инструмент ждёт перехода приложения в состояние покоя: нет запланированного кадра, нет выполняющегося `fetch`, а за последние 50 мс не было ни коммита, ни кадра. Поэтому агент видит результат своего ввода, а не кадр посреди обновления.

<!-- s:fbad6f5c1a -->
`<Spinner>` или график, обновляющийся раз в секунду, всё равно считается находящимся в покое между обновлениями, поэтому страницы с анимацией остаются читаемыми. Приложение, которое рендерится чаще, чем раз в 50 мс, никогда не переходит в состояние покоя. Через 1,5 с чтение прекращает ожидание (`settleMs` меняет этот срок), выводит последний кадр и помечает его как `busy`. `wait_for` без текста ждёт состояния покоя со своим значением `quietMs` и возвращает ошибку, если покой так и не наступает.

<!-- s:c5250c2f7a -->
Координаты задаются в ячейках с отсчётом от нуля: `x` — столбец, `y` — строка. Широкие символы, такие как CJK и эмодзи, занимают два столбца.

<!-- s:7ff82431c5 -->
Ошибки и журналы

<!-- s:6e07cf8702 -->
stdout передаёт данные протокола. Вывод `console.*` вашего приложения, посторонние вызовы `process.stdout.write` и ошибки React вместо этого попадают в `logs` с нумерацией, чтобы агент мог запросить только новые записи через `since`. Если с момента последнего чтения были записаны ошибки, заголовок следующего кадра сообщает об этом.

<!-- s:9102068439 -->
Сбои возвращаются как ошибки инструментов и не приводят к аварийному завершению. Инструмент, превысивший время ожидания, отменяется до запуска следующего вызова, поэтому медленный вызов никогда не вводит текст в кадр следующего вызова. Ошибки с кодом Text.js сохраняют его, например `TX007` для неизвестной клавиши. Если приложение не загружается, каждый инструмент объясняет причину. Исправьте файл и вызовите `reload`.

Принцип работы

<!-- s:7c71219a13 -->
`text mcp` запускает ваше приложение так же, как [`text run`](/docs/terminal): все модули маршрутов импортируются заранее, App Router использует историю в памяти, а вызовы `fetch("/api/…")` к тому же источнику запускают ваши обработчики внутри процесса. Кадры отправляются во внеэкранную сетку ячеек вместо терминала. Отрендеренные на сервере страницы (`export const runtime = "server"`) и их компоненты `async function` рендерятся внутри процесса, как в `text dev`, и кадр считывается после их завершения.

<!-- s:c965dcc0e4 -->
`reload` размонтирует приложение, удаляет все модули проекта из кеша модулей Bun (включая файлы вне `app/`), повторно сканирует `app/` и монтирует приложение в текущем местоположении.

Ограничения

<!-- s:910af21777 -->
- Приложение работает в Bun, а не в браузере. `window` и `document` не определены, как и в `text run`.
- Каждый сервер запускает одно приложение с одной сеткой. Каждый клиент MCP запускает собственный сервер.
- `text mcp` запускает собственную копию приложения без графического интерфейса. Он не может подключиться к вкладке браузера, открытой через `text dev`.
