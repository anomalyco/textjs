<!-- s:04615ef523 -->
`text build` создаёт переносимый каталог `dist/`. Адаптер преобразует его в формат, который ожидает платформа.

<!-- s:087f8d3137 -->
Адаптеры

<!-- s:04908c6c09 -->
| Адаптер | Результат | Среда запуска |
| :-- | :-- | :-- |
| *(нет)* | `dist/` + `dist/.text/server` | `text start` (Node) |
| `static` | `dist/` | Любой статический хостинг |
| `bun` | `dist/server.js` | `bun dist/server.js` |
| `vercel` | `.vercel/output` | Vercel (Build Output API v3) |
| `cloudflare` | `dist/` + `_worker.js` | Cloudflare Pages |

<!-- s:7e755a5c9f -->
Адаптер можно задать и через `TEXTJS_ADAPTER`. Когда `text build` запускается на Vercel (`VERCEL=1`) или Cloudflare Pages (`CF_PAGES=1`), соответствующий адаптер выбирается автоматически.

<!-- s:d671e1ae31 -->
Чтобы добавить приложение на другой сайт одним тегом script, соберите его с `--embed`. Это поддерживают все адаптеры (см. [Встраивание](/docs/embedding)).

<!-- s:9d8df946e5 -->
Серверные адаптеры (`bun`, `vercel` и `cloudflare`) выполняют ту же цепочку обработки, что и `text start`: [middleware](/docs/middleware), `rewrites`, [обработчики маршрутов](/docs/route-handlers) с [кешем маршрутов](/docs/caching), статические ресурсы, затем документ консоли для URL страниц. Терминальные клиенты, такие как curl, вместо этого получают первый кадр страницы в виде текста ANSI. На `vercel` и `cloudflare` это работает только для статических страниц (см. [curl и терминальные клиенты](/docs/curl)). Серверные адаптеры отдают файлы с хешами в `/assets/` с заголовком `Cache-Control: public, max-age=31536000, immutable`.

<!-- s:1a5ee098c6 -->
Статический хостинг

<!-- s:9ebd0d2866 -->
Используйте его для хостингов без сервера, таких как GitHub Pages, S3 или CDN. Для обработчиков маршрутов `GET` с `dynamic = "force-static"` или `revalidate` выполняется пререндеринг в файлы: `app/api/feed.json/route.ts` превращается в `dist/api/feed.json`. Копия `index.html` записывается в `404.html`, чтобы прямые ссылки открывали консольное приложение. Статические хостинги не могут отличить curl от браузера, поэтому curl получает HTML-страницу.

<!-- s:1e90536a2a -->
Сборка завершается ошибкой с перечислением всех причин, если приложению нужен сервер: `middleware.ts`, [отрендеренные на сервере маршруты](/docs/server-rendering), динамические обработчики маршрутов, обработчики маршрутов с динамическими сегментами или методы, отличные от `GET`. Вместо этого настройте `rewrites` на хостинге.

<!-- s:2c3ddc9047 -->
Bun

<!-- s:d451f14e30 -->
Адаптер `bun` записывает единый автономный сервер, которому не нужен `node_modules` во время выполнения. Он читает `PORT` (по умолчанию `3000`) и `HOSTNAME` (по умолчанию `0.0.0.0`) и никогда не отдаёт `server.js` или `.text/`. Это долгоживущий процесс, поэтому он, как и `text start`, обслуживает [отрендеренные на сервере маршруты](/docs/server-rendering) (`export const runtime = "server"`) и их активные сессии. Vercel

<!-- s:b9d1e3b495 -->
Или отправьте изменения в Git-репозиторий, подключённый к Vercel: сборка запускает `text build`, обнаруживает Vercel и записывает `.vercel/output`.

<!-- s:3ee6894582 -->
| Результат | Содержимое |
| :-- | :-- |
| `static/` | Клиентская сборка (в `basePath`) |
| `functions/_textjs/server.func` | Одна функция Node.js 22, обслуживающая все обработчики маршрутов, с потоковой передачей |
| `functions/_middleware.func` | Edge Routing Middleware: `middleware.ts` и канонические пути для каждого приложения |
| `config.json` | Заголовки ресурсов, правила сопоставления middleware, перезаписи, маршруты обработчиков и документ консоли |

<!-- s:3f3ba93b7d -->
Edge-middleware использует протокол `x-middleware-next` / `x-middleware-rewrite`, поэтому переопределение заголовков и перезапись происходят в маршрутизаторе Vercel до обращения к функции или CDN. Все правила сопоставления используют один шаблон маршрута `src`. Запросы, не подходящие ни под одно правило, пропускают middleware, кроме случаев, когда их путь может быть не в канонической форме (процентное кодирование, символы, кодируемые парсером URL, `//`, сегменты `.` или `..`, завершающая косая черта). Тогда middleware сопоставляет канонический путь, проверяет `has` / `missing` и перезаписывает запрос на этот путь, чтобы Vercel маршрутизировал его так же. Приложения без `middleware.ts` получают ту же edge-функцию, которая выполняет только перезапись. Поскольку каждая сборка включает функцию Edge, выполняйте развёртывание из учётной записи Vercel, в которую вы вошли: анонимные развёртывания (`vercel deploy --temporary`) не поддерживают функции Edge.

<!-- s:b5af065e25 -->
Функция обработчика внутренняя. Каждый маршрут обработчика передаёт ей совпавший путь в заголовке запроса `x-textjs-path`. Этот заголовок удаляется из каждого запроса до и после middleware, а edge-middleware никогда не пересылает его (ни от клиента, ни из `middleware.ts`), поэтому задать его могут только маршруты обработчиков. Запросы к `/_textjs/*` возвращают `404` без запуска функции, до и после middleware и перезаписей. Сгенерированные маршруты сопоставляются с учётом регистра, как и правила сопоставления и перезаписи на всех остальных хостингах.

<!-- s:5e18b8a450 -->
Тесты адаптера проверяют этот результат сборки с локальной эмуляцией маршрутизатора Vercel. Его поведение при сопоставлении `src`, захватах `dest`, преобразовании заголовков и маршрутах `status` проверено на реальных развёртываниях; Edge-middleware не проверялось, поскольку его нельзя развернуть анонимно.

<!-- s:14e7957486 -->
Cloudflare Pages

<!-- s:6109800459 -->
Результат сборки использует расширенный режим Pages:

<!-- s:f72ec91f11 -->
| Файл | Назначение |
| :-- | :-- |
| `_worker.js` | Middleware, перезаписи, обработчики маршрутов и документ консоли. Каталог (`index.js` и `yoga.wasm`), если обработчик маршрута использует Yoga |
| `_routes.json` | Направляет каждый запрос в worker. Без middleware и `basePath` путь `/assets/*` обслуживается статическим CDN Pages |
| `_headers` | Неизменяемое кэширование для `/assets/*` (дописывается к вашим правилам) |
| `404.html` | Заставляет Pages отвечать на запросы отсутствующих файлов кодом `404` вместо приложения (сохраняется, если у вас уже есть этот файл) |

<!-- s:9bc2b010d1 -->
`.text/` (серверные бандлы и манифесты сборки) удаляется из `dist/`, поскольку Pages публикует каталог как есть.

<!-- s:1200dbc88d -->
Включите флаг совместимости `nodejs_compat` в проекте Pages (Settings → Runtime) или в `wrangler.toml`; кеш данных использует `AsyncLocalStorage`. Статические файлы отдаются через привязку `ASSETS`, а фоновая ревалидация использует `ctx.waitUntil()`.

<!-- s:398bcc3496 -->
При наличии middleware каждый запрос запускает worker, включая запросы ресурсов с хешем в имени, чтобы middleware видел все пути, по которым доступен файл. Каждый запрос, запускающий worker, считается одним вызовом Functions и учитывается в вашей квоте запросов Workers. При загрузке страницы это документ и каждый загружаемый им файл (3 для небольшого тестового приложения: документ, один JavaScript-бандл и `yoga-[hash].wasm`; больше для приложений с большим числом файлов). На тарифе Workers Free после исчерпания дневной квоты Pages отдаёт статические файлы без worker, пропуская middleware. Если middleware защищает что-либо в `dist/`, установите для Settings → Runtime → Fail open / closed значение **Fail closed**.

<!-- s:24c3dfe433 -->
WebAssembly

<!-- s:72ec3f110c -->
Приложения Text.js загружают Yoga, движок макетов, из `assets/yoga-[hash].wasm` (72 КБ, 29 КБ с gzip). `text build` предзагружает его на каждой странице. Серверные бандлы и `text run` используют встроенную копию из `yoga-layout`. Исключение — worker Cloudflare: когда обработчик маршрута использует Yoga, в `dist/_worker.js/` хранится `yoga.wasm` рядом с `index.js`.

<!-- s:0ca00aa2eb -->
- Отдавайте файлы `.wasm` в сжатом виде, как и JavaScript. Vercel сжимает `application/wasm` по умолчанию; для nginx нужно добавить `application/wasm` в `gzip_types`. Если ваш хостинг сжимает JavaScript, но не `.wasm`, страницы загружают примерно на 32 КБ больше, чем со встроенной копией.
- Отправляйте `Content-Type: application/wasm`, чтобы браузер компилировал файл во время загрузки. С другим типом он компилируется после загрузки.
- Кэшируйте его так же, как другие файлы с хешем в имени в `assets/` (`Cache-Control: public, max-age=31536000, immutable`). Это безопасно, поскольку имя меняется вместе с содержимым. Не используйте `immutable` для путей без хеша.
- Если вы задаёте Content Security Policy, добавьте `'wasm-unsafe-eval'` в `script-src`, а источник файла (обычно `'self'`) в `connect-src`.
- Если неизвестные пути перенаправляются на `index.html`, исключите `/assets/` из этой перезаписи. Иначе запрос отсутствующего файла вернёт HTML, а `initYoga()` завершится с ошибкой `TX032`.

Обновление

<!-- s:e8733a2bfb -->
Исправления безопасности в `@textjs/app` попадают в развёрнутое приложение только после повторной сборки и развёртывания:

<!-- s:c74adc728a -->
- Vercel: разверните новый `.vercel/output`.
- Cloudflare Pages: разверните новый `dist/` с `_worker.js` и `_routes.json`.
- Bun: разверните весь новый `dist/` (`server.js`, ресурсы и бандлы активных сессий) и перезапустите сервер.
- `text start`: запустите `text build` и перезапустите сервер.

<!-- s:8047727085 -->
Старые развёртывания остаются доступны по собственным URL (например, URL предварительного просмотра Vercel и Cloudflare Pages). Удалите их или ограничьте доступ к ним средствами защиты платформы.

Отрендеренные на сервере маршруты

<!-- s:049ef31493 -->
[Отрендеренные на сервере маршруты](/docs/server-rendering) хранят сессию для каждой открытой вкладки, поэтому им нужен долгоживущий сервер: `text start` или адаптер `bun`. Адаптеры `static`, `vercel` и `cloudflare` завершают сборку ошибкой `TX030`, когда страница экспортирует `runtime = "server"`.

Ограничения

<!-- s:f45e3fb003 -->
- `proxy` в `text.config.ts` работает только в `text dev` и `text start`; адаптеры его не включают. Используйте `rewrites`, которые поддерживает каждый серверный адаптер.
- Каждый serverless-экземпляр имеет собственный кеш в памяти. См. [Кеширование](/docs/caching#platform-notes).
- `rewrites`, использующие группы регулярных выражений напрямую, преобразуются в маршруты Vercel по мере возможности; именованные параметры (`:slug`, `:path*`) преобразуются точно.
