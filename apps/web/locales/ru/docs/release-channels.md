Text.js выпускается с тремя dist-тегами npm. Версии всех пакетов (`@textjs/app`, `@textjs/react`, `@textjs/core`, `@textjs/font`, `@textjs/opencode`, `create-text-app` и `eslint-plugin-textjs`) обновляются синхронно, поэтому один номер версии описывает весь фреймворк.

<!-- s:a2c3664770 -->
Каналы

<!-- s:6b5c5ba172 -->
| Канал | dist-tag | Версия | Установка |
| :-- | :-- | :-- | :-- |
| Стабильный | `latest` | `1.0.x` | `bun add @textjs/app` |
| Canary | `canary` | `1.0.x-canary.N` | `bun add @textjs/app@canary` |
| LTS | `lts`, `v1-lts` | Публикуется после выхода `2.0.0` | `bun add @textjs/app@lts` |

<!-- s:27e8b81dc6 -->
Используйте стабильный канал в продакшене. Используйте canary, чтобы пробовать исправления и возможности в день их появления в `dev`. Когда появится ветка LTS, используйте её, если обновляетесь раз в год.

<!-- s:abc686bd76 -->
Стабильный канал

<!-- s:df32c144c0 -->
Стабильные релизы следуют [семантическому версионированию](https://semver.org): патч-релизы исправляют ошибки, минорные релизы добавляют обратно совместимые возможности, мажорные релизы могут нарушать совместимость API после периода устаревания. Стабильный релиз создаётся из canary, прошедшего полный набор тестов, и публикуется с подтверждением происхождения npm.

<!-- s:7307c50761 -->
Canary

<!-- s:db409040ca -->
Каждая отправка изменений в `dev` в официальном репозитории проходит проверку типов и тесты, затем публикуется как следующая патч-версия с суффиксом `-canary.N`:

<!-- s:d8b8cffefe -->
| `latest` | Отправка в `dev` | Опубликованная версия |
| :-- | :-- | :-- |
| `1.0.0` | первая | `1.0.1-canary.0` |
| `1.0.0` | вторая | `1.0.1-canary.1` |
| `1.0.1` | следующая | `1.0.2-canary.0` |

<!-- s:dd9c67b1f5 -->
`N` продолжает нумерацию с наибольшего номера canary, уже опубликованного в npm, поэтому номера никогда не повторяются. Версии canary не фиксируются в репозитории. Добавьте `[skip canary]` в сообщение коммита, чтобы пропустить релиз.

<!-- s:762894d754 -->
Canary — это сборки `dev`, ветки, в которую сливаются все пул-реквесты. Они могут изменять или удалять ещё не выпущенные API без предупреждения. Закрепите точную версию canary, если зависите от неё.

Подготовка релиза

<!-- s:a3217d58a6 -->
Сопровождающие синхронно повышают версии всех пакетов рабочего пространства с помощью скриптов релиза:

<!-- s:614a1ea872 -->
`release:version` перезаписывает каждый `package.json` и соответствующие константы версий (`VERSION`, `rendererVersion` согласователя), отказывается запускаться, если версии пакетов разошлись, а `--dry-run` выводит план. `release:publish` собирает пакеты, упаковывает их (разрешая `workspace:*`), применяет `publishConfig`, не позволяет опубликовать предварительную версию с тегом `latest` или стабильную версию с тегом `canary` и пропускает версии, уже существующие в npm.
