`useKeyState` (экспериментальный)

<!-- s:a63d1753a1 -->
`@textjs/react/experimental` экспортирует `useKeyState` для отслеживания удерживаемых физических клавиш по `KeyboardEvent.code` (`"KeyW"`, `"ArrowUp"`, `"ControlLeft"`). Опрос `keys.isDown(code)` или чтение `keys.pressed` не вызывает повторный рендеринг React. Передайте функцию обратного вызова, чтобы реагировать на нажатия и отпускания клавиш по мере их возникновения.

<!-- s:d9e1465ae0 -->

`usePageFocus`

<!-- s:8dae4284ef -->
`usePageFocus()` возвращает признак того, находится ли страница в фокусе. Нажатия клавиш поступают в приложение, только пока страница в фокусе. Это то же значение, что и `useViewport().focused`, но повторный рендеринг происходит только при изменении фокуса.

<!-- s:e1075d4220 -->
Когда страница не в фокусе, а в приложении есть обработчик `useInput` или `usePaste`, хук `useKeyState` или элемент, на который можно перевести фокус клавишей Tab, последняя строка кадра консоли становится янтарной полосой с текстом «Щёлкните по странице, чтобы использовать клавиатуру». Обработчики с пометкой [`ambient`](#useinput) не учитываются. Подсказка не появляется в терминале, в тестах и во встроенных зеркалах. При каждом появлении подсказка мигает около 6 секунд, если в системе не включено уменьшение движения. Чтобы самостоятельно определять, когда она отображается, задайте `focusHint: false` в `text.config.ts` или `createConsoleRoot` и отрендерите `<FocusHint>`:

Загрузка при намерении открыть консоль (экспериментальная возможность)

<!-- s:97014ecad1 -->
`@textjs/core/experimental` экспортирует `onConsoleIntent` для страниц, которые скачивают приложение для консоли только по желанию посетителя. Он вызывает вашу функцию один раз, передавая причину:

<!-- s:444b1ebdd7 -->
| Причина | Когда |
| :-- | :-- |
| `dock` | DevTools закреплены в окне браузера при загрузке страницы или закрепляются позже. Text.js определяет это по размеру окна |
| `shortcut` | Посетитель нажимает F12 или Ctrl+Shift+J, I, C или K либо ⌘⌥J, I, C или K на Mac. Браузер по-прежнему открывает DevTools |
| `engage` | Щелчок основной кнопкой по элементу, соответствующему `engageSelector`, нажатие Enter или Space на кнопке `[data-textjs-engage]` или выбор размера в `<ViewportControl>` до запуска приложения. Щелчки по ссылкам, кнопкам и полям форм внутри соответствующего элемента не учитываются, если у них тоже нет `data-textjs-engage` |
| `session` | Одно из перечисленных событий уже произошло в этой вкладке, поэтому при перезагрузке приложение запускается сразу |
| `manual` | Вы вызвали `trigger()` у возвращённого объекта |

<!-- s:894b97fac4 -->
DevTools, открытые в отдельном окне через меню браузера, не влияют на размер окна. Такие посетители запускают приложение через элемент `engage`, а `session` сохраняет запуск при перезагрузках в этой вкладке.

<!-- s:06cdcf713e -->
На сенсорных экранах ничего не срабатывает автоматически. Вызывайте `trigger()` из собственного элемента управления.

<!-- s:d7006796c2 -->
| Параметр | Описание |
| :-- | :-- |
| `engageSelector` | Элементы, запускающие приложение по щелчку (по умолчанию `[data-textjs-engage], [data-textjs-focus-pad], text-console`). При `false` обработчики событий не добавляются |
| `persist` | Сохранение намерения для вкладки в `sessionStorage` под ключом `CONSOLE_INTENT_KEY` (по умолчанию `true`) |
| `prefetch` | Вызов не более одного раза, когда указатель или фокус попадает на элемент `engageSelector` |
| `idlePrefetch` | Дополнительный вызов `prefetch`, когда браузер простаивает после `load` (по умолчанию `false`) |

<!-- s:4460da3205 -->
`prefetch` никогда не запускается на сенсорных экранах, при включённой экономии трафика или при соединении медленнее 4G. `canPrefetchConsole()` возвращает результат той же проверки. Метод `dispose()` возвращённого объекта удаляет все обработчики событий.

<!-- s:9128a9d98f -->
`<ViewportControl>` работает ещё до создания корня консоли. Выбор размера сохраняет его, вызывает событие `engage`, чтобы `onConsoleIntent` запустил приложение, и применяет размер после установки `root`. О версионировании экспериментальных экспортов см. в разделе [Несовместимые изменения](/docs/support-policy#breaking-changes).
