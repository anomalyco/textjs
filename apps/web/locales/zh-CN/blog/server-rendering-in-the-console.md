Text.js 0.4 为页面增加了第二个渲染位置。默认情况下，页面的 React 树在浏览器标签页中运行。导出 `runtime = "server"` 的页面则在服务器上运行，浏览器接收其帧。

<!-- s:1a12ccffbb -->
`Load` 是一个 `async function` 组件。在服务器上，它会挂起到最近的 `<Suspense>` 或 `loading.tsx`，直到其 promise 完成，并且可以直接读取文件、数据库和 `node:*` 模块。异步组件负责加载数据，不能使用 Hook。周围的常规组件仍可使用 Hook、焦点、`useInput`、`<Link>` 和 `useRouter()`，这些功能在两种运行时中的行为相同。

<!-- s:f6c454b214 -->
浏览器下载的内容

<!-- s:6764f4bb25 -->
服务端渲染的页面不会下发 React、Yoga 或你的路由。浏览器加载一个 gzip 压缩后约 21 kB 的帧播放器，其中包含一个 `CellBuffer`，以及客户端渲染器使用的同一个 `CssConsoleDriver`。它同样以 15 fps 的节奏播放帧，因此服务端渲染的帧产生的 `console.log` 调用与客户端相同。

<!-- s:c1c4090983 -->
协议

<!-- s:20c7e299b3 -->
每个标签页都在服务器上建立独立会话，包含一个 React 根节点、一份内存中的路由历史记录和一个单元格缓冲区。一个端点承载双向通信：

<!-- s:0cce1c98cc -->
服务器只发送自该连接收到上一帧以来哈希值发生变化的行。每一行以连续文本片段的形式发送，样式引用一个只追加的样式表。宽字素、表情符号簇和半透明颜色都会完整传输。

<!-- s:bff22f361e -->
帧之间至少间隔 66 ms，每一帧都会与套接字最后接受的内容进行差异比较。当慢速连接无法继续排出数据时，中间状态会被跳过，下一帧直接跳到最新状态。

<!-- s:f0809ea8c7 -->
如果流断开，播放器会在 `x-textjs-live` 请求头中携带会话 ID 重新连接，并从一个新的关键帧恢复同一会话，保留原有状态。会话 ID 是保存在内存中的 192 位随机值，从不放入 URL。没有连接的会话会停止渲染，并在 30 秒后卸载。

<!-- s:2c75bd5d29 -->
两个端点都拒绝跨站请求，每个输入事件都会按固定模式校验。一个会话每次 POST 最多接受 64 个事件，每秒约接受 240 个事件。

仅限服务端的模块以 `*.server.ts` 命名。如果下发到浏览器的代码导入了这类模块，或导入了 `node:*` 内置模块，构建就会失败，并指出导入方。

部分预渲染

<!-- s:9142a7d770 -->
部分预渲染无需服务器即可工作。`text build` 现在会为每个静态路由渲染一次，并将首帧作为一个小型传统 `<script>` 内联到路由的 HTML 中，因此控制台会在任何模块加载之前绘制。

<!-- s:d51b081ec7 -->
外壳包含所有同步渲染的内容。仍在等待的 `<Suspense>` 边界会显示其回退内容，异步组件也包含在内，而 `fetch()` 在外壳渲染期间始终不会完成。

<!-- s:33ba4145a3 -->
JavaScript 启动后，客户端渲染器或帧播放器会流式传输实际帧。由于 0.4 也采用追加帧而非清空的方式，执行水合的渲染器会以 `initialClear: false` 启动，在外壳下方输出日志，其幕布会在同一次 DevTools 绘制中将外壳移出视野。控制台仅由外壳清空一次。

<!-- s:f6986897ee -->
外壳按配置的 `viewport` 尺寸渲染，默认为 `120 × 36`，因为构建时无法知道访客的控制台尺寸。启用 `viewport.responsive` 后，第一个实时帧会调整尺寸以适应停靠的控制台。动态路由不渲染外壳，在 `text.config.ts` 中设置 `ppr: false` 可关闭预渲染。

<!-- s:c61865edfd -->
选择运行时

<!-- s:aa5baec7ef -->
客户端运行时仍是默认选项。按键输入在同一任务中完成绘制，应用可部署到任何静态托管服务。服务端运行时适合读取私有数据的仪表盘和管理视图，也适合那些你不希望将其依赖打包到浏览器中的路由。一个应用可以混用两种运行时，在两者之间导航时，会将目标 URL 作为新文档加载。
