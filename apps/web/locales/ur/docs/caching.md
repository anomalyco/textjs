روٹ ہینڈلر کے ریسپانس اور ڈیٹا کیش کریں، پھر ٹائمر پر یا ضرورت کے مطابق انہیں ری ویلیڈیٹ کریں۔ جب بیک گراؤنڈ میں ایک ریفریش چل رہا ہو تو پرانی انٹریز فوراً فراہم ہوتی ہیں۔

<!-- s:be697310c8 -->
روٹ ہینڈلرز

<!-- s:e85fc29fe2 -->
`GET` روٹ ہینڈلرز ڈیفالٹ طور پر ڈائنامک ہوتے ہیں۔ کیشنگ فعال کرنے کے لیے روٹ سیگمنٹ کی کنفگ استعمال کریں:

<!-- s:e4ccf65c67 -->
| ایکسپورٹ | رویہ |
| :-- | :-- |
| *(کوئی نہیں)* | ہر ریکویسٹ پر چلتا ہے |
| `dynamic = "force-static"` | ری ویلیڈیٹ ہونے تک کیش میں رہتا ہے |
| `revalidate = N` | کیش میں رہتا ہے؛ `N` سیکنڈ بعد پرانا ہو جاتا ہے |
| `revalidate = 0` یا `dynamic = "force-dynamic"` | ہر ریکویسٹ پر چلتا ہے |

<!-- s:274c053db6 -->
`dynamic` کی دوسری ویلیوز `TX031` کے ساتھ ناکام ہوتی ہیں۔ ان میں Next.js کی `"error"` بھی شامل ہے، کیونکہ Text.js معلوم نہیں کر سکتا کہ ہینڈلر کب ریکویسٹ پڑھتا ہے۔

<!-- s:0fae4045f6 -->
کیش شدہ ہینڈلرز کو ہر پاتھ نیم کے لیے ایک انٹری ملتی ہے، اور ان کی `request` ویسی ہوتی ہے جیسی بلڈ کے وقت ہوتی: کوئری اسٹرنگ، ہیڈرز، کوکیز یا باڈی کے بغیر۔ انہیں ڈائنامک ہینڈلر میں پڑھیں۔ صرف `GET` اور `HEAD` کیش ہوتے ہیں۔ `5xx` اسٹیٹس، `Set-Cookie` ہیڈر، یا `Cache-Control: private` / `no-store` والے ریسپانس واپس آتے ہیں مگر کبھی اسٹور نہیں ہوتے۔

<!-- s:b618d4732f -->
ہیڈرز

<!-- s:c0a6cf7351 -->
کیش شدہ ریسپانس میں یہ شامل ہوتے ہیں:

<!-- s:b5f8cfecb4 -->
| ہیڈر | ویلیو |
| :-- | :-- |
| `x-textjs-cache` | `MISS`، `HIT` یا `STALE` |
| `Cache-Control` | `s-maxage=N, stale-while-revalidate=<1 year − N>`، یا `force-static` کے لیے `s-maxage=31536000` |

<!-- s:c1fb73c64a -->
جب [مڈل ویئر](/docs/middleware) ریکویسٹ کے لیے کوکیز سیٹ کرتا ہے، ری رائٹ کرتا ہے یا ریکویسٹ ہیڈرز اوور رائڈ کرتا ہے تو بننے والا ہیڈر `private, no-cache, no-store, max-age=0, must-revalidate` ہو جاتا ہے، اس لیے مشترکہ کیش کسی وزیٹر کے لیے مخصوص فیصلے کو کبھی دوبارہ استعمال نہیں کرتے۔ ہینڈلر کا سیٹ کردہ `Cache-Control` ہیڈر برقرار رہتا ہے۔

<!-- s:ae27ba22c7 -->
`text dev` میں سیگمنٹ کنفگ لاگو ہوتی ہے مگر کچھ اسٹور نہیں ہوتا، اس لیے ہر ریکویسٹ ہینڈلر کو چلاتی ہے۔

<!-- s:64841df645 -->
ڈیٹا کیش

<!-- s:2187e2262b -->
کسی بھی async فنکشن کو کیش کرنے کے لیے `@textjs/app/cache` سے `unstable_cache` استعمال کریں:

<!-- s:4c26e099ff -->
کلید میں کلید کے حصے اور آرگیومنٹس شامل ہوتے ہیں، جن کی انکوڈنگ ویلیو کے لحاظ سے ہوتی ہے (`undefined` اور `null`، `Map`، `Set`، `Date` اور `URL` آرگیومنٹس الگ الگ رہتے ہیں)۔ کلید کے حصوں کے بغیر، فنکشن کا سورس اور اس کی تخلیق کی جگہ اس کی شناخت کرتے ہیں؛ جب بھی فنکشن بیرونی ویلیوز کو کلوزر میں رکھتا ہو تو کلید کے حصے پاس کریں، مثلاً جب وہ ہر ریکویسٹ پر یا کسی لوپ میں بنتا ہو۔ نتائج JSON میں سیریلائز ہوتے ہیں، اس لیے ہر کال ایک نئی کاپی واپس کرتی ہے (اور `Date` آبجیکٹس اسٹرنگز کے طور پر واپس آتے ہیں)؛ جو نتیجہ سیریلائز نہ ہو سکے وہ ایرر تھرو کرتا ہے۔ `cache(fn, { key, tags, revalidate })` یہی ترتیبات ایک آپشنز آبجیکٹ کے طور پر لیتا ہے۔

<!-- s:608eee0e9b -->
کیش شدہ روٹ ہینڈلر کے اندر، ڈیٹا انٹریز اپنے ٹیگز اور اپنی سب سے مختصر `revalidate` مدت روٹ تک پہنچاتی ہیں: `"posts"` کو ری ویلیڈیٹ کرنے سے `/api/posts` بھی ریفریش ہوتا ہے۔ `revalidate: 0` والی ڈیٹا کال روٹ کو ڈائنامک بنا دیتی ہے۔

<!-- s:5537f337ee -->
ری ویلیڈیشن کے دوران پرانی ویلیو

<!-- s:7d23e84252 -->
جب کسی انٹری کی عمر `revalidate` سے زیادہ ہو جائے:

<!-- s:d4dd1966dd -->
1. اگلی ریکویسٹ کو پرانی ویلیو فوراً ملتی ہے (`STALE`)۔
2. بیک گراؤنڈ میں ایک ریفریش چلتا ہے؛ بیک وقت آنے والی ریکویسٹس اسے شیئر کرتی ہیں۔
3. اگر ریفریش ایرر تھرو کرے تو پرانی ویلیو فراہم ہوتی رہتی ہے اور ایرر لاگ ہوتا ہے۔

<!-- s:e6db7819cc -->
Vercel اور Cloudflare پر، بیک گراؤنڈ ریفریش `waitUntil()` کے ساتھ رجسٹر ہوتے ہیں۔ ایک سال سے زیادہ پرانی انٹریز ہمیشہ فور گراؤنڈ میں دوبارہ کمپیوٹ ہوتی ہیں۔

<!-- s:5854b096d2 -->
ضرورت کے مطابق ری ویلیڈیشن

<!-- s:686aa7f2f3 -->
| کال | ان ویلیڈیٹ ہونے والا ڈیٹا |
| :-- | :-- |
| `revalidateTag("posts")` | `posts` ٹیگ والا تمام ڈیٹا؛ اگلی ریکویسٹ دوبارہ کمپیوٹ کرتی ہے |
| `revalidateTag("posts", "max")` | اسے پرانا نشان زد کرتی ہے؛ ریفریش کے دوران اگلی ریکویسٹ کو پرانا ڈیٹا ملتا ہے |
| `revalidatePath("/api/feed")` | وہ پاتھ |
| `revalidatePath("/api/posts/[id]")` | ڈائنامک روٹ کا ہر پاتھ |
| `revalidatePath("/api", "layout")` | `/api` کے تحت تمام ڈیٹا |

<!-- s:b132bd50eb -->
دونوں ایک پرامس واپس کرتے ہیں۔ اِن میموری اسٹور کے ساتھ ان ویلیڈیشن فوری ہوتی ہے؛ جب [کسٹم اسٹور](#custom-cache-stores) غیر ہم وقت ہو تو اس پر `await` استعمال کریں۔

<!-- s:2aab4b4d00 -->
کسٹم کیش اسٹورز

<!-- s:7bee24a364 -->
ڈیفالٹ اسٹور ہر سرور انسٹینس کے لیے ایک اِن میموری LRU ہے (1,000 انٹریز، تقریباً 50 MB)۔ انسٹینسز کے درمیان کیش شیئر کرنے کے لیے، `cacheHandler` کو ایسے ماڈیول کی طرف پوائنٹ کریں جو `CacheStore` کو ڈیفالٹ ایکسپورٹ کرتا ہو:

<!-- s:593c57fca5 -->
انٹریز سادہ JSON ہوتی ہیں۔ اس کے بجائے `setCacheStore(store)` رن ٹائم پر اسٹور انسٹال کرتا ہے۔

<!-- s:fe2404de51 -->
پلیٹ فارم سے متعلق معلومات

<!-- s:5418a08901 -->
- ہر سرورلیس انسٹینس (Vercel فنکشنز، Cloudflare آئسولیٹس) کا اپنا اِن میموری کیش ہوتا ہے۔ `Cache-Control: s-maxage` پلیٹ فارم کے CDN کو بھی ریسپانس کیش کرنے دیتا ہے؛ ضرورت کے مطابق ری ویلیڈیشن CDN کو صاف نہیں کرتی۔ جب `revalidateTag` کو ہر انسٹینس تک پہنچنا ہو تو مشترکہ `cacheHandler` استعمال کریں۔
- Cloudflare کے لیے `nodejs_compat` فلیگ ضروری ہے (کیش `AsyncLocalStorage` استعمال کرتا ہے)۔ [ڈیپلائے کرنا](/docs/deploying) دیکھیں۔
