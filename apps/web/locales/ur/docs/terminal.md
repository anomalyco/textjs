`text run`

<!-- s:36358c3ead -->
`text run`، `app/` کی ہر فائل امپورٹ کرتا ہے، App Router کو اِن میموری ہسٹری کے ساتھ ماؤنٹ کرتا ہے اور اسے پوری اسکرین پر رینڈر کرتا ہے۔ `<Link>`، `useRouter()`، `notFound()` اور `redirect()` بغیر کسی تبدیلی کے کام کرتے ہیں۔

<!-- s:75b65c161d -->
ایک ہی اوریجن کی `fetch("/api/...")` کالز آپ کے `route.ts` ہینڈلرز اسی پروسیس میں چلاتی ہیں، بالکل ویسے جیسے `text dev` انہیں سَرو کرتا ہے۔ دیگر URLs نیٹ ورک پر جاتے ہیں۔

`renderToTerminal`

<!-- s:1bcde87690 -->
ایک کمپوننٹ یا آپ کی اپنی CLI کے لیے:

<!-- s:e62e62bfaa -->
`useApp().exit()` اَن ماؤنٹ کرتا ہے اور ٹرمینل بحال کرتا ہے۔

<!-- s:082b75dda7 -->
| آپشن | تفصیل |
| :-- | :-- |
| `stdin` / `stdout` | ڈیفالٹ `process.stdin` / `process.stdout` |
| `cols` / `rows` | مقررہ سائز (ڈیفالٹ: ٹرمینل کے مطابق) |
| `altScreen` | باہر نکلنے پر اسکرول بیک کی بحالی (ڈیفالٹ `true`) |
| `mouse` | وہیل اسکرولنگ (ڈیفالٹ `true`) |
| `exitOnCtrlC` | ڈیفالٹ `true` |
| `fps` | فریم کی حد (ڈیفالٹ `60`) |
| `patchConsole` | باہر نکلنے تک `console.*` روکنا (ڈیفالٹ `true`) |
| `theme` / `transparent` | `createConsoleRoot` کی طرح |

ہر فریم کا قطار بہ قطار موازنہ ہوتا ہے۔ صرف تبدیل شدہ قطاریں لکھی جاتی ہیں، جن کے گرد synchronized-output مارکرز ہوتے ہیں تاکہ ان کی سپورٹ رکھنے والے ٹرمینلز کبھی ادھورا رینڈر شدہ فریم نہ دکھائیں۔ غیر فعال ایپس کچھ نہیں لکھتیں۔

اِن پٹ

<!-- s:4a9817d820 -->
را موڈ stdin کو پارس کر کے وہی ایونٹس بنائے جاتے ہیں جو براؤزر پیدا کرتا ہے: موڈیفائرز کے ساتھ ایرو اور فنکشن کیز، `Alt` کے امتزاج، بریکٹڈ پیسٹ، SGR ماؤس وہیل اور kitty کی بورڈ پروٹوکول۔ اگر آپ کو کہیں اور ان کی ضرورت ہو تو `TerminalInputParser` اور `parseTerminalInput` ایکسپورٹ کیے گئے ہیں۔
