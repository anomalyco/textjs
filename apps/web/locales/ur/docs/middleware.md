طریقۂ کار

<!-- s:9e6d75b727 -->
پروجیکٹ کی روٹ (یا `src/`) میں، `app/` کے ساتھ `middleware.ts` فائل بنائیں۔ ایک `middleware` فنکشن (یا ڈیفالٹ ایکسپورٹ) اور اختیاری `config` ایکسپورٹ کریں۔

<!-- s:a4d39cdaaf -->
مڈل ویئر `text dev`، `text start` اور ہر سرور [ڈیپلائے اڈاپٹر](/docs/deploying) پر [روٹ ہینڈلرز](/docs/route-handlers)، اسٹیٹک فائلوں اور کونسول صفحات سے پہلے چلتا ہے۔ یہ Web کے `Request` اور `Response` استعمال کرتا ہے، اس لیے یہی فائل Node، Bun، Vercel Edge اور Cloudflare Workers پر چلتی ہے۔

پاتھ میچ کرنا

<!-- s:1e1ec8c339 -->
`config.matcher` کے بغیر، مڈل ویئر ہر درخواست کے لیے چلتا ہے۔ میچرز Next.js والا سنٹیکس استعمال کرتے ہیں:

<!-- s:473d472bc8 -->
| میچر | میچ ہونے والے پاتھ |
| :-- | :-- |
| `/about` | `/about` اور `/about/` |
| `/blog/:slug` | `/blog/hello` |
| `/docs/:path*` | `/docs`، `/docs/a/b` |
| `/a/:rest+` | `/a/b`، مگر `/a` نہیں |
| `/user/:id(\\d+)` | `/user/42`، مگر `/user/ada` نہیں |
| `/((?!api/).*)` | `/api/*` کے سوا سب کچھ |

<!-- s:256aeeefbc -->
`has` اور `missing` سے شرائط شامل کریں (ہیڈر، کوکی، کوئری یا ہوسٹ):

<!-- s:d756420343 -->
میچرز `basePath` کے بغیر پاتھ نیم پر لاگو ہوتے ہیں۔ `text dev` میں، Vite کی اپنی ماڈیول درخواستیں (`/@vite/*`، سورس فائلیں) کبھی مڈل ویئر نہیں چلاتیں۔

<!-- s:75cd7297e6 -->
ہر ہوسٹ مڈل ویئر چلنے سے پہلے ایک معیاری پاتھ نیم طے کرتا ہے، اور اسے میچنگ، `request.nextUrl` اور روٹ، ہینڈلر اور فائل کی تلاش کے لیے استعمال کرتا ہے۔ پرسنٹ ایسکیپس ڈی کوڈ ہوتے ہیں اور پاتھ دوبارہ اسی طرح ان کوڈ ہوتا ہے جیسے `new URL()` اسے لکھتا ہے، `.` اور `..` حصے حل ہوتے ہیں، اور دہرائے گئے اور آخر میں موجود سلیش ہٹا دیے جاتے ہیں۔ `/ad%6din//users/` مڈل ویئر تک `/admin/users` کی صورت میں پہنچتا ہے، جبکہ `/café` کی صورت `/caf%C3%A9` ہی رہتی ہے۔ آخر میں سلیش کے ساتھ لکھا گیا میچر، جیسے `/admin/`، `/admin` سے میچ ہوتا ہے۔ جن درخواستوں کے پاتھ میں ان کوڈ شدہ سلیش یا بیک سلیش (`%2F`، `%5C`)، کنٹرول کریکٹر یا غلط پرسنٹ ان کوڈنگ ہو، انہیں `400` ملتا ہے۔ روٹس میں بڑے اور چھوٹے حروف کا فرق ہوتا ہے: `/Admin`، `/admin` سے میچ نہیں ہوتا، اور اسٹیٹک فائلیں صرف ان کے عین نام پر پیش ہوتی ہیں۔

<!-- s:3f5746eb4e -->
ان URLs کو میچ کریں جن پر فائل پیش ہوتی ہے، صرف اس کے فائل نام کو نہیں۔ Cloudflare Pages، `report.html` کو `/report` پر بھی پیش کرتا ہے، اس لیے `/report.html` کا میچر `/report` کو محفوظ نہیں کرتا۔ دونوں درج کریں، `matcher: ["/report", "/report.html"]`، یا محفوظ فائلیں ایک ڈائریکٹری میں رکھیں اور اسے میچ کریں، جیسے `public/reports/` کی فائلوں کے لیے `/reports/:path*`۔

NextResponse

<!-- s:880215c229 -->
| API | اثر |
| :-- | :-- |
| `NextResponse.next()` | روٹ کی طرف آگے بڑھنا |
| `NextResponse.redirect(url, status?)` | ڈیفالٹ طور پر `307`؛ `url` کا مطلق ہونا ضروری ہے |
| `NextResponse.rewrite(url)` | دوسرا پاتھ پیش کرنا؛ بیرونی اوریجنز کو پراکسی کرنا |
| `NextResponse.json(body, init?)` | JSON کے ساتھ جواب دینا |
| `new Response(...)` | کسی بھی چیز کے ساتھ جواب دینا |

<!-- s:a8292924c3 -->
بغیر تبدیلی آگے بڑھنے کے لیے کچھ واپس نہ کریں۔ `next()` اور `rewrite()` حتمی جواب کا اسٹیٹس بدلنے کے لیے `{ status }` قبول کرتے ہیں۔ صرف `NextResponse.next()` / `NextResponse.rewrite()` سے بنے جواب روٹنگ کی سمت طے کرتے ہیں: کوئی بھی دوسرا `Response`، بشمول `fetch()` سے واپس آنے والا جواب، اپنے `x-middleware-*` ہیڈرز ہٹانے کے بعد جوں کا توں کلائنٹ کو بھیج دیا جاتا ہے۔

<!-- s:583e778785 -->
`request.nextUrl` اپنے `pathname` سے `basePath` کو خارج کرتا ہے، جبکہ اس کے `href` اور `toString()` میں یہ شامل ہوتا ہے۔ ایپ کے اندر رہنے کے لیے اسے کلون کریں: `const url = request.nextUrl.clone(); url.pathname = "/login"; return NextResponse.redirect(url);`۔

ہیڈرز

<!-- s:37748fa2c3 -->
بعد کے ہینڈلرز کو ملنے والی معلومات بدلنے کے لیے `request.headers` پاس کریں، اور جواب کے ہیڈرز شامل کرنے کے لیے `headers` پاس کریں:

<!-- s:60bf4677c2 -->
مڈل ویئر کے جواب کے ہیڈرز حتمی جواب میں شامل ہوتے ہیں، جب تک روٹ ہینڈلر وہی ہیڈر سیٹ نہ کرے۔

کوکیز

`next()` یا `rewrite()` کے جواب پر سیٹ کی گئی کوکیز اسی درخواست میں روٹ ہینڈلر کو بھی نظر آتی ہیں۔

نوٹس

<!-- s:971c06c875 -->
- کلائنٹ پر رینڈر ہونے والے صفحات براؤزر میں رینڈر ہوتے ہیں، اس لیے دوسرے صفحے پر ری رائٹ کرنے سے پیش ہونے والی فائل بدلتی ہے، وہ روٹ نہیں جسے کونسول ایپ رینڈر کرتی ہے۔ روٹ ہینڈلرز، اسٹیٹک فائلوں اور بیرونی اوریجنز کے لیے ری رائٹس توقع کے مطابق کام کرتی ہیں۔
- مڈل ویئر درخواست کی باڈی پڑھ سکتا ہے؛ روٹ ہینڈلرز کو پھر بھی یہ ملتی ہے۔ میچر جن درخواستوں کو خارج کرتا ہے ان کی باڈی کو کبھی نہیں چھیڑا جاتا۔
- `request.url` میں ہمیشہ سرور کا اوریجن ہوتا ہے: `//other.host/x` جیسے درخواست کے ٹارگٹس کو شروع میں ایک سلیش والی شکل دی جاتی ہے۔
- [اسٹیٹک اڈاپٹر](/docs/deploying#static) مڈل ویئر نہیں چلا سکتا۔
