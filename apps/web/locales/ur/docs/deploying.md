| :-- | :-- | :-- |

اڈاپٹر `TEXTJS_ADAPTER` سے بھی لیا جا سکتا ہے۔ جب `text build` کمانڈ Vercel (`VERCEL=1`) یا Cloudflare Pages (`CF_PAGES=1`) پر چلتی ہے تو متعلقہ اڈاپٹر خودکار طور پر منتخب ہوتا ہے۔

<!-- s:d671e1ae31 -->
ایک اسکرپٹ ٹیگ سے ایپ کو دوسری سائٹ میں شامل کرنے کے لیے، `--embed` کے ساتھ بلڈ کریں۔ ہر اڈاپٹر اسے سپورٹ کرتا ہے ([ایمبیڈ کرنا](/docs/embedding) دیکھیں)۔

<!-- s:9d8df946e5 -->
سرور اڈاپٹرز (`bun`، `vercel` اور `cloudflare`) وہی پائپ لائن چلاتے ہیں جو `text start` چلاتا ہے: [مڈل ویئر](/docs/middleware)، `rewrites`، [روٹ کیش](/docs/caching) کے ساتھ [روٹ ہینڈلرز](/docs/route-handlers)، اسٹیٹک اثاثے، پھر صفحے کے URLs کے لیے کونسول ڈاکیومنٹ۔ curl جیسے ٹرمینل کلائنٹس کو اس کے بجائے صفحے کا پہلا فریم ANSI متن کی صورت میں ملتا ہے۔ `vercel` اور `cloudflare` پر یہ صرف اسٹیٹک صفحات کے لیے ہے ([curl اور ٹرمینل کلائنٹس](/docs/curl) دیکھیں)۔ سرور اڈاپٹرز `/assets/` کے تحت ہیش شدہ فائلیں `Cache-Control: public, max-age=31536000, immutable` کے ساتھ پیش کرتے ہیں۔

اسٹیٹک

<!-- s:9ebd0d2866 -->
اسے سرور کے بغیر ہوسٹس، جیسے GitHub Pages، S3 یا CDN کے لیے استعمال کریں۔ `dynamic = "force-static"` یا `revalidate` والے `GET` روٹ ہینڈلرز کی پری رینڈرنگ فائلوں میں ہوتی ہے: `app/api/feed.json/route.ts` سے `dist/api/feed.json` بنتی ہے۔ `index.html` کی ایک نقل `404.html` میں لکھی جاتی ہے تاکہ ڈیپ لنکس کونسول ایپ کھولیں۔ اسٹیٹک ہوسٹس curl اور براؤزر میں فرق نہیں کر سکتے، اس لیے curl کو HTML صفحہ ملتا ہے۔

<!-- s:1e90536a2a -->
اگر ایپ کو سرور درکار ہو تو بلڈ ہر وجہ درج کرکے ناکام ہوتا ہے: `middleware.ts`، [سرور پر رینڈر شدہ روٹس](/docs/server-rendering)، ڈائنامک روٹ ہینڈلرز، ڈائنامک سیگمنٹس والے روٹ ہینڈلرز، یا `GET` کے علاوہ میتھڈز۔ اس کے بجائے ہوسٹ پر `rewrites` کنفیگر کریں۔

Bun

<!-- s:d451f14e30 -->
`bun` اڈاپٹر ایک مکمل، خود کفیل سرور لکھتا ہے جسے رن ٹائم پر `node_modules` کی ضرورت نہیں ہوتی۔ یہ `PORT` (ڈیفالٹ `3000`) اور `HOSTNAME` (ڈیفالٹ `0.0.0.0`) پڑھتا ہے، اور کبھی `server.js` یا `.text/` پیش نہیں کرتا۔ یہ طویل عرصے تک چلنے والا پروسیس ہے، اس لیے `text start` کی طرح [سرور پر رینڈر شدہ روٹس](/docs/server-rendering) (`export const runtime = "server"`) اور ان کے لائیو سیشنز بھی ہوسٹ کرتا ہے۔ اسے کنٹینر میں استعمال کریں:

Vercel

<!-- s:b9d1e3b495 -->
یا Vercel سے منسلک Git ریپوزٹری میں پش کریں: بلڈ `text build` چلاتا ہے، Vercel کی شناخت کرتا ہے اور `.vercel/output` لکھتا ہے۔

<!-- s:3ee6894582 -->
| آؤٹ پٹ | مواد |
| :-- | :-- |
| `static/` | کلائنٹ بلڈ (`basePath` کے تحت) |
| `functions/_textjs/server.func` | ایک Node.js 22 فنکشن جو اسٹریمنگ کے ساتھ ہر روٹ ہینڈلر پیش کرتا ہے |
| `functions/_middleware.func` | Edge روٹنگ مڈل ویئر: `middleware.ts`، اور ہر ایپ کے کینونیکل پاتھ |
| `config.json` | اثاثوں کے ہیڈرز، مڈل ویئر میچرز، ری رائٹس، ہینڈلر روٹس اور کونسول ڈاکیومنٹ |

<!-- s:3f3ba93b7d -->
ایج مڈل ویئر `x-middleware-next` / `x-middleware-rewrite` پروٹوکول استعمال کرتا ہے، اس لیے فنکشن یا CDN تک پہنچنے سے پہلے Vercel کے راؤٹر میں ہیڈر اوور رائیڈز اور ری رائٹس ہوتے ہیں۔ تمام میچرز ایک ہی روٹ `src` پیٹرن استعمال کرتے ہیں۔ جن درخواستوں سے کوئی میچر نہیں ملتا وہ مڈل ویئر چھوڑ دیتی ہیں، سوائے اس صورت کے جب ان کا پاتھ شاید کینونیکل شکل میں نہ ہو (پرسنٹ ایسکیپس، URL پارسر کے انکوڈ کیے جانے والے حروف، `//`، `.` یا `..` سیگمنٹس، آخر میں سلیش)۔ پھر مڈل ویئر کینونیکل پاتھ کو میچ کرتا ہے، `has` / `missing` جانچتا ہے، اور درخواست کو اس پاتھ پر ری رائٹ کرتا ہے تاکہ Vercel اسے اسی طرح روٹ کرے۔ `middleware.ts` کے بغیر ایپس کو بھی وہی ایج فنکشن ملتا ہے، جو صرف ری رائٹ کرتا ہے۔ چونکہ ہر بلڈ میں ایک Edge فنکشن شامل ہوتا ہے، اس لیے لاگ اِن Vercel اکاؤنٹ سے ڈیپلائے کریں: گمنام ڈیپلائمنٹس (`vercel deploy --temporary`) Edge فنکشنز قبول نہیں کرتیں۔

<!-- s:b5af065e25 -->
ہینڈلر فنکشن اندرونی ہے۔ ہر ہینڈلر روٹ میچ شدہ پاتھ اسے `x-textjs-path` درخواست ہیڈر میں دیتا ہے۔ یہ ہیڈر مڈل ویئر سے پہلے اور بعد میں ہر درخواست سے ہٹا دیا جاتا ہے، اور ایج مڈل ویئر کبھی ایسا ہیڈر آگے نہیں بھیجتا (کلائنٹ یا `middleware.ts` سے)، اس لیے صرف ہینڈلر روٹس اسے سیٹ کر سکتے ہیں۔ `/_textjs/*` کی درخواستیں مڈل ویئر اور ری رائٹس سے پہلے اور بعد میں، فنکشن چلائے بغیر `404` لوٹاتی ہیں۔ بنائے گئے روٹس بڑے اور چھوٹے حروف کے فرق کے ساتھ میچ ہوتے ہیں، جیسے ہر دوسرے ہوسٹ پر میچرز اور ری رائٹس ہوتے ہیں۔

<!-- s:5e18b8a450 -->
اڈاپٹر کے ٹیسٹس یہ آؤٹ پٹ Vercel کے راؤٹر کی مقامی ایمولیشن پر چلاتے ہیں۔ `src` میچنگ، `dest` کیپچرز، ہیڈر ٹرانسفارمز اور `status` روٹس کے لیے اس کا رویہ حقیقی ڈیپلائمنٹس پر جانچا گیا؛ Edge مڈل ویئر نہیں جانچا گیا، کیونکہ اسے گمنام طور پر ڈیپلائے نہیں کیا جا سکتا۔

Cloudflare Pages

آؤٹ پٹ Pages کا ایڈوانسڈ موڈ استعمال کرتا ہے:

| فائل | مقصد |
| :-- | :-- |

Pages پروجیکٹ میں (ترتیبات → رن ٹائم) یا `wrangler.toml` فائل میں `nodejs_compat` کمپیٹیبلٹی فلیگ فعال کریں؛ ڈیٹا کیش `AsyncLocalStorage` استعمال کرتا ہے۔ اسٹیٹک فائلیں `ASSETS` بائنڈنگ سے پیش ہوتی ہیں، اور بیک گراؤنڈ ری ویلیڈیشن `ctx.waitUntil()` استعمال کرتی ہے۔

<!-- s:398bcc3496 -->
مڈل ویئر کے ساتھ، ہیش شدہ اثاثوں سمیت ہر ریکویسٹ ورکر چلاتی ہے، تاکہ مڈل ویئر ہر وہ پاتھ دیکھ سکے جس سے کسی فائل تک پہنچا جا سکتا ہے۔ ورکر چلانے والی ہر ریکویسٹ ایک Functions کال ہے اور آپ کے Workers ریکویسٹ کوٹے میں شمار ہوتی ہے۔ صفحہ لوڈ ہونے پر، اس میں ڈاکیومنٹ اور اس کی حاصل کردہ ہر فائل شامل ہے (ایک چھوٹی ٹیسٹ ایپ کے لیے 3: ڈاکیومنٹ، ایک JavaScript بنڈل اور `yoga-[hash].wasm`؛ زیادہ فائلوں والی ایپس کے لیے زیادہ)۔ Workers Free پلان پر، روزانہ کا کوٹا ختم ہونے کے بعد Pages اسٹیٹک فائلیں ورکر کے بغیر فراہم کرتا ہے، جس سے مڈل ویئر نہیں چلتا۔ اگر مڈل ویئر `dist/` میں کسی چیز کی حفاظت کرتا ہے تو Settings → Runtime → Fail open / closed کو **Fail closed** پر سیٹ کریں۔

WebAssembly

<!-- s:72ec3f110c -->
Text.js ایپس لے آؤٹ انجن Yoga کو `assets/yoga-[hash].wasm` سے لوڈ کرتی ہیں (72 kB، gzip کے ساتھ 29 kB)۔ `text build` ہر صفحے سے اسے پری لوڈ کرتا ہے۔ سرور بنڈلز اور `text run`، `yoga-layout` کی اِن لائن کاپی استعمال کرتے ہیں۔ Cloudflare ورکر اس سے مستثنیٰ ہے: جب کوئی روٹ ہینڈلر Yoga استعمال کرتا ہے تو `dist/_worker.js/` ڈائریکٹری میں `index.js` کے ساتھ `yoga.wasm` موجود ہوتی ہے۔

<!-- s:0ca00aa2eb -->
- `.wasm` فائلیں کمپریس کر کے فراہم کریں، جیسے آپ JavaScript فراہم کرتے ہیں۔ Vercel ڈیفالٹ طور پر `application/wasm` کو کمپریس کرتا ہے؛ nginx کو `gzip_types` میں `application/wasm` چاہیے۔ اگر آپ کا ہوسٹ JavaScript کو کمپریس کرتا ہے لیکن `.wasm` کو نہیں، تو صفحات اِن لائن کاپی کے مقابلے میں تقریباً 32 kB زیادہ ڈاؤن لوڈ کرتے ہیں۔
- `Content-Type: application/wasm` بھیجیں، تاکہ براؤزر فائل ڈاؤن لوڈ کرتے وقت ہی اسے کمپائل کرے۔ دوسری ٹائپ کے ساتھ، یہ ڈاؤن لوڈ کے بعد کمپائل کرتا ہے۔
- اسے `assets/` کی دوسری ہیش شدہ فائلوں کی طرح کیش کریں (`Cache-Control: public, max-age=31536000, immutable`)۔ یہ محفوظ ہے کیونکہ مواد کے ساتھ نام بدل جاتا ہے۔ ہیش کے بغیر پاتھس کے لیے `immutable` استعمال نہ کریں۔
- اگر آپ Content Security Policy سیٹ کرتے ہیں تو `script-src` میں `'wasm-unsafe-eval'` اور `connect-src` میں فائل کا اوریجن (عموماً `'self'`) شامل کریں۔
- اگر نامعلوم پاتھس کے لیے `index.html` استعمال ہوتا ہے تو اس ری رائٹ سے `/assets/` کو خارج کریں۔ ورنہ گم شدہ فائل HTML لوٹاتی ہے اور `initYoga()`، `TX032` کے ساتھ ناکام ہوتا ہے۔

`text start` کمانڈ `127.0.0.1` سے بائنڈ ہوتی ہے اور لوپ بیک سے بائنڈ رہنے تک صرف `localhost`، `*.localhost` اور IP ایڈریس والے ہوسٹس کو جواب دیتی ہے (DNS ری بائنڈنگ سے تحفظ)۔ دوسرے ہوسٹس کو `TX028` کے ساتھ `403` ملتا ہے۔ پبلک ترتیبات `text.config.ts` فائل میں رکھیں:

<!-- s:43bd5471c8 -->
`origin` یا `trustProxy` کے بغیر، `request.url` کی تشکیل تصدیق شدہ `Host` ہیڈر سے `http` پر ہوتی ہے۔

<!-- s:689cebe287 -->
احتیاطی نکات

<!-- s:f45e3fb003 -->
- `text.config.ts` میں `proxy` صرف `text dev` اور `text start` میں چلتا ہے؛ اڈاپٹرز میں یہ شامل نہیں ہوتا۔ `rewrites` استعمال کریں، جس کی ہر سرور اڈاپٹر سپورٹ کرتا ہے۔
- ہر سرورلیس انسٹینس کا اپنا اِن میموری کیش ہوتا ہے۔ [کیشنگ](/docs/caching#platform-notes) دیکھیں۔
- خام ریگولر ایکسپریشن گروپس استعمال کرنے والے `rewrites` کو جہاں تک ممکن ہو Vercel روٹس میں بدلا جاتا ہے؛ نام والے پیرامیٹرز (`:slug`، `:path*`) عین مطابق ہوتے ہیں۔
