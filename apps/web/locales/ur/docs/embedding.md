<!-- s:7e7d3cb07e -->
`text build --embed` آپ کی ایپ کو اس طرح بلڈ کرتا ہے کہ دوسری سائٹ اسے ایک اسکرپٹ ٹیگ سے شامل کر سکے، مثلاً مارکیٹنگ صفحہ، دستاویزات کی سائٹ، WordPress یا Webflow صفحہ، یا React 18 ایپ۔ DevTools کھولنے والے وزیٹرز کو آپ کی ایپ کونسول میں ملتی ہے۔ دوسرے وزیٹرز صرف `embed.js` ڈاؤن لوڈ کرتے ہیں (gzip کے ساتھ تقریباً 3 kB)، الا یہ کہ صفحے پر `<text-console>` موجود ہو۔

<!-- s:2aa1d07d89 -->
ایمبیڈز تجرباتی ہیں۔ `text build --embed`، `embed` آپشن، `<text-console>` اور `@textjs/app/experimental` کے ایکسپورٹس مائنر ریلیز میں بدل سکتے ہیں۔ [مطابقت توڑنے والی تبدیلیاں](/docs/support-policy#breaking-changes) دیکھیں۔

سائٹ میں ایپ شامل کرنا

<!-- s:f296ccaeef -->
ایپ بلڈ کریں:

<!-- s:2198c52791 -->
`dist/` کو کسی بھی اسٹیٹک ہوسٹ یا CDN پر اپ لوڈ کریں، یا اسے سائٹ کے `public/` فولڈر میں کاپی کریں، پھر سائٹ کے صفحات میں ایک ٹیگ شامل کریں:

<!-- s:aa94ef1985 -->
`embed.js` اپنی دوسری فائلیں اپنے URL کے لحاظ سے لوڈ کرتا ہے، اس لیے `dist/` کسی بھی پاتھ یا اوریجن سے کام کرتا ہے۔ اس میں صرف `embed.js` اور `assets/` ہوتے ہیں، کوئی `index.html` یا `404.html` نہیں جو سائٹ کی اپنی فائلوں کی جگہ لے سکے۔ [سرور پر رینڈر شدہ روٹس](#server-rendered-routes)، روٹ ہینڈلرز یا مڈل ویئر والی ایپ کو محض اسٹیٹک اپ لوڈ کے بجائے سرور درکار ہوتا ہے۔ `vercel` اور `cloudflare` اڈاپٹرز روٹ ہینڈلرز اور مڈل ویئر چلاتے ہیں، اور سرور پر رینڈر شدہ روٹس کو `text start` یا `bun` اڈاپٹر درکار ہوتا ہے۔

<!-- s:5c139759a2 -->
وزیٹرز کو ایپ کی جگہ دکھانے کے لیے صفحے میں کہیں بھی [`<text-console>`](#text-console) شامل کریں۔ `data-textjs-engage` والا کوئی بھی ایلیمنٹ دبانے پر ایپ شروع کرتا ہے:

<!-- s:6a70ec16e1 -->
اسے مقامی طور پر آزمانے کے لیے `text dev --embed` چلائیں۔ یہ ہر درخواست پر نئے پہلے فریم کے ساتھ `/embed.js` فراہم کرتا ہے، اور `/` پر ایک پیش نظارہ صفحہ (`standalone` کے ساتھ `/__textjs/embed`) فراہم کرتا ہے جو اسے دوسری سائٹ کی طرح لوڈ کرتا ہے۔ کسی دوسرے مقامی پورٹ پر موجود سائٹ بھی `http://localhost:3000/embed.js` لوڈ کر سکتی ہے۔

<!-- s:37f210b46a -->
کنفیگریشن

<!-- s:aa9630bf92 -->
`text build --embed`، `text.config.ts` فائل میں `embed: true` کے برابر ہے۔ ڈیفالٹس بدلنے کے لیے ایک آبجیکٹ پاس کریں:

<!-- s:fbe8efc9f4 -->
| آپشن | ڈیفالٹ | تفصیل |
| :-- | :-- | :-- |
| `initialPath` | `"/"` | وہ روٹ جس پر کونسول کھلتا ہے۔ `/` سے شروع ہونا ضروری ہے |
| `globalName` | `"text"` | وہ گلوبل جس کے تحت ایپ شروع ہونے پر اپنا کونسول API انسٹال کرتی ہے۔ `false` سے کوئی گلوبل انسٹال نہیں ہوتا |
| `initialClear` | `false` | پہلے فریم سے پہلے صفحے کا کونسول صاف کریں۔ ڈیفالٹ طور پر، صفحے کے پہلے کے لاگز ایپ کے اوپر رہتے ہیں |
| `standalone` | `false` | ایپ کے اپنے صفحات (`index.html`) بھی بلڈ کریں، جیسے `text build`، `embed` کے بغیر کرتا ہے |
| `allowOrigins` | `[]` | وہ سائٹس جن کے صفحات اس سرور سے سرور پر رینڈر شدہ روٹس چلا سکتے ہیں۔ [سرور پر رینڈر شدہ روٹس](#server-rendered-routes) دیکھیں |
| `credentials` | `false` | کوکیز اور `Authorization` ہٹانے کے بجائے `allowOrigins` سے آنے والی لائیو سیشن درخواستوں کے ساتھ اس سرور کے لیے براؤزر کریڈینشلز بھیجیں۔ عین اوریجنز درکار ہیں |

<!-- s:12a3d28167 -->
`viewport.width × viewport.height` (ڈیفالٹ 120 × 36) پہلے فریم کا سائز ہے۔ `title`، `hints` اور `action`، `<text-console>` کے ڈیفالٹس ہیں۔ `ppr: false` کے ساتھ، یا جب `middleware.ts`، `initialPath` سے میچ کر سکتی ہو، `embed.js` میں پری رینڈر شدہ پہلا فریم نہیں ہوتا، کیونکہ کوئی بھی `embed.js` ڈاؤن لوڈ کر سکتا ہے۔ ایپ کے پینٹ ہونے تک مرر خالی رہتا ہے۔

طرز عمل

<!-- s:1fe89ec57c -->
- **[کونسول استعمال کرنے کے ارادے](/docs/hooks-and-repl#loading-on-console-intent-experimental) تک کچھ اور لوڈ نہیں ہوتا۔** `embed.js` پری رینڈر شدہ پہلا فریم لاگ کرتا ہے، پھر انتظار کرتا ہے۔ ایپ تب لوڈ ہوتی ہے جب DevTools ڈاک ہو (لوڈ ہوتے وقت یا بعد میں)، جب وزیٹر صفحے پر DevTools کا شارٹ کٹ دبائے (F12، Ctrl+Shift+J، I، C یا K، یا Mac پر ⌘⌥J، I، C یا K)، یا جب وہ `<text-console>` یا `[data-textjs-engage]` ایلیمنٹ دبائے۔ اس کے بعد اسی ٹیب میں ری لوڈ کرنے پر یہ فوراً شروع ہو جاتی ہے۔ اپنی الگ ونڈو میں DevTools صفحے کا سائز نہیں بدلتا، اس لیے اسے مینو سے کھولنے والے وزیٹرز کو پہلا فریم تب تک نظر آتا ہے جب تک وہ ان ایلیمنٹس میں سے کسی کو نہ دبائیں۔
- **ٹچ اسکرینز پر ایپ شروع نہیں ہوتی۔** `(hover: none) and (pointer: coarse)` سے میچ کرنے والے ڈیوائس پر `embed.js` کچھ لاگ نہیں کرتا اور کوئی لسنر شامل نہیں کرتا۔ یہ صرف مرر کے لیے `<text-console>` کی فائل لوڈ کرتا ہے۔
- **کیز تبھی ایپ تک پہنچتی ہیں جب وزیٹر اسے فعال کرے۔** اسے فعال کرنے کے لیے وہ `<text-console>` یا `[data-textjs-engage]` ایلیمنٹ دباتے ہیں، یا DevTools سے فوکس واپس لانے کے لیے صفحے پر کلک کرتے ہیں (لنک، بٹن یا فیلڈ پر نہیں)۔ صفحے کی اپنی فیلڈز یا `[data-textjs-bypass]` ایلیمنٹ میں ٹائپ کیا ہوا متن کبھی ایپ تک نہیں پہنچتا، اور وہیل ہمیشہ صفحے کو اسکرول کرتا ہے۔
- **صفحے کا URL، ہسٹری اور عنوان کبھی نہیں بدلتے۔** روٹس، `<Link>` اور `useRouter()` کونسول کے اندر نیویگیٹ کرتے ہیں۔ کلائنٹ پر رینڈر شدہ ایپس میں مکمل URLs نئے ٹیب میں کھلتے ہیں۔
- **صفحے پر موجود Text.js ایپ کو ترجیح ملتی ہے۔** اس کے شروع ہونے پر چلتا ہوا ایمبیڈ ان ماؤنٹ ہو جاتا ہے، کیز پڑھنا بند کر دیتا ہے اور اپنا گلوبل ہٹا دیتا ہے۔ جب کوئی دوسری ایپ کونسول استعمال کر رہی ہو تو لوڈ ہونے والا ایمبیڈ ایک وارننگ لاگ کرتا ہے اور شروع نہیں ہوتا۔
- **ایمبیڈ اپنا React 19 بنڈل کرتا ہے۔** اس میں `react-dom` یا بیئر امپورٹس نہیں ہوتے، اس لیے صفحے کا React ورژن، `react` کا امپورٹ میپ اور React DevTools اس پر اثر نہیں ڈالتے۔

`<text-console>`

<!-- s:7156621f10 -->
`embed.js`، `<text-console>` کی تعریف کرتا ہے اور اس کی فائل صرف تب لوڈ کرتا ہے جب صفحے پر ایسا ایلیمنٹ موجود ہو۔ یہ Shadow DOM استعمال کرتا ہے، اس لیے صفحے کی CSS اس کے اندر نہیں پہنچتی، اور `style-src 'self'` پالیسی میں تبدیلی درکار نہیں ہوتی۔

<!-- s:9ceead3eca -->
ایٹری بیوٹس کے بغیر یہ ایک سطر کی بار ہے۔ یہ کونسول کھولنے کا براؤزر شارٹ کٹ دکھاتی ہے، پھر کلک کرنے کو کہتی ہے، پھر ایپ کی کیز دکھاتی ہے، جو ایپ تک پہنچنے پر روشن ہوتی ہیں۔ Safari میں پہلا مرحلہ Safari کی ترتیبات میں “ویب ڈیولپرز کے لیے فیچرز دکھائیں” فعال کرنے کو کہتا ہے۔

<!-- s:899e0c7fe3 -->
`mirror` کے ساتھ یہ صفحے پر ایپ کا فریم دکھاتا ہے: کسی اور چیز کے لوڈ ہونے سے پہلے پری رینڈر شدہ پہلا فریم، پھر چلتی ہوئی ایپ۔ اسے دبانے سے ایپ شروع ہوتی ہے اور وزیٹر کی کیز اس تک پہنچتی ہیں، اس لیے ایپ DevTools بند ہونے پر بھی کام کرتی ہے۔ `chrome` مرر کے گرد DevTools ونڈو بناتا ہے اور `mirror` بھی فعال کرتا ہے۔

<!-- s:fefcb3e495 -->
| ایٹری بیوٹ | تفصیل |
| :-- | :-- |
| `mirror` | ایپ کے فریم دکھائیں |

| `title` | بار کا عنوان (ڈیفالٹ: `text.config.ts` میں `title`) |
| `hints` | دکھانے والی کیز، جیسے `"← →:switch region, Enter:open"` (ڈیفالٹ: `text.config.ts` میں `hints`) |
| `action` | پہلے کیا کرنا ہے، جو “یہاں کلک کریں اور …” کے طور پر دکھتا ہے (ڈیفالٹ: `text.config.ts` میں `action`، یا پہلا اشارہ دبائیں) |

ٹچ اسکرینز پر مرر ایپ شروع کیے بغیر پہلا فریم دکھاتا ہے، اور بار چھپی رہتی ہے۔ ایلیمنٹ کا متن انگریزی میں ہے۔

اس کی جگہ محفوظ کرنا

<!-- s:0f4e2c234d -->
`text build --embed` آپ کی ایپ کی گرڈ کے لیے CSS کی ایک سطر پرنٹ کرتا ہے۔ اسے صفحے کی اسٹائل شیٹ میں پیسٹ کریں۔ یہ ایلیمنٹ کی فائل لوڈ ہونے سے پہلے `<text-console>` کا سائز مقرر کرتی ہے، اس لیے فائل آنے پر صفحے پر کچھ نہیں ہلتا۔ ڈیفالٹ 120 × 36 گرڈ کے لیے سطر یہ ہے:

<!-- s:a2d2741417 -->
بار کی اونچائی 58 px ہے۔ مرر اپنی قدرتی چوڑائی تک (120 کالم پر 885 px) گرڈ کا تناسب برقرار رکھتا ہے، اور `chrome` مزید 43 px شامل کرتا ہے۔ سائز فونٹس پر منحصر نہیں ہے۔ `@textjs/app/experimental` کا `reserveCss(cols, rows)` یہی سطر لوٹاتا ہے۔

<!-- s:a1260c10c3 -->
صفحے کے ابتدائی نظر آنے والے حصے میں مرر عموماً صفحے کا سب سے بڑا ایلیمنٹ ہوتا ہے، اس لیے یہ صفحے کا Largest Contentful Paint (LCP) مقرر کرتا ہے۔ اس کا پہلا فریم پہلے `embed.js` اور پھر ایلیمنٹ کی فائل لوڈ ہونے کے بعد بنتا ہے۔ باقی صفحہ اسی طرح پینٹ ہوتا ہے جیسے ایمبیڈ کے بغیر ہوتا۔ صفحے میں مزید نیچے موجود مرر LCP پر اثر نہیں ڈالتا۔ اپنی مؤخر اسکرپٹس والے صفحے، مثلاً React ایپ میں، `<script type="module" async src="…">` ان کا انتظار کیے بغیر `embed.js` چلاتا ہے، اس لیے ابتدائی نظر آنے والے حصے میں مرر جلد بنتا ہے۔

اسٹائلنگ

<!-- s:834fbf40e6 -->
مرر کو درمیان میں رکھنے کے لیے اسے آٹو اِن لائن مارجنز دیں:

<!-- s:6dde2b2766 -->
یہ ڈیفالٹ طور پر گہرا ہوتا ہے۔ ہلکے رنگوں کے لیے `color-scheme: light` سیٹ کریں، یا وہ دو رنگ سیٹ کریں جنہیں ملا کر باقی شیڈز بنتے ہیں۔ `::part(frame)` خود فریم کو اسٹائل کرتا ہے۔ `chrome`، DevTools کا اپنا پس منظر برقرار رکھتا ہے۔

سرور پر رینڈر شدہ روٹس

<!-- s:eb293d9fb4 -->
جب `initialPath` ایسا روٹ ہو جس میں `export const runtime = "server"` ہو، تو `embed.js` کلائنٹ رن ٹائم کے بجائے فریم پلیئر لوڈ کرتا ہے۔ یہ اسی سرور سے فریم اسٹریم کرتا ہے جہاں سے `embed.js` آیا تھا، اس لیے `text start` یا `bun` اڈاپٹر چلائیں۔ دوسرے اڈاپٹرز سے بلڈ ناکام ہوتا ہے۔ [سرور رینڈرنگ](/docs/server-rendering) دیکھیں۔

<!-- s:e2bdd4dbb7 -->
دوسری سائٹ کا صفحہ لائیو سیشن صرف تب کھول سکتا ہے جب اس کا اوریجن `allowOrigins` میں ہو:

<!-- s:6ec7048857 -->
- سیشن صرف اسی اوریجن کو جواب دیتا ہے جس نے اسے کھولا ہو۔
- ڈیفالٹ طور پر Text.js دوسری سائٹس کے سیشنز کی کوکیز اور `Authorization` ہیڈر ہٹا دیتا ہے، اس لیے [مڈل ویئر](/docs/middleware) کو سائن آؤٹ شدہ وزیٹر نظر آتا ہے۔ `credentials: true` انہیں برقرار رکھتا ہے، اور اسے عین اوریجنز درکار ہوتے ہیں۔ براؤزر انہیں تب بھیجتا ہے جب صفحے اور سرور کا رجسٹر ہونے والا ڈومین مشترک ہو (`www.example.com` اور `console.example.com`) اور کوکی سرور کا احاطہ کرتی ہو (`Domain=example.com`، یا `console.example.com` پر سیٹ ہو)۔ دوسری سائٹس سے یہ صرف `SameSite=None; Secure` کے ساتھ سیٹ کردہ کوکیز بھیجتا ہے، اور تھرڈ پارٹی کوکیز بلاک کرنے والے براؤزر کوئی کوکی نہیں بھیجتے۔
- لائیو سیشن کنیکٹ ہوتے ہی، اور دوبارہ کنیکٹ ہونے پر، `/__textjs/live` کو `OPTIONS` پری فلائٹس بھیجتا ہے۔ پری فلائٹس میں کوکیز یا `Authorization` نہیں ہوتے، اس لیے اس پاتھ سے میچ کرنے والے مڈل ویئر کو سائن اِن کے بغیر `OPTIONS` درخواستیں گزرنے دینی چاہئیں۔
- ریورس پراکسی یا CDN کے پیچھے `server.trustProxy` سیٹ کریں ([پراکسی کے پیچھے](/docs/deploying#behind-a-proxy) دیکھیں)۔ اس کے بغیر ہر وزیٹر کا پتہ پراکسی کا پتہ ہوتا ہے، اس لیے سب پر فی کلائنٹ سیشن کی ایک ہی حد لاگو ہوتی ہے۔

<!-- s:f739524722 -->
`text dev`، `localhost`، `127.0.0.1` اور `[::1]` پر کسی بھی پورٹ کے صفحات `allowOrigins` کے بغیر قبول کرتا ہے، الا یہ کہ `credentials` سیٹ ہو۔

ہوسٹنگ

<!-- s:4bef54c1c0 -->
`text start` اور `bun`، `vercel` اور `cloudflare` اڈاپٹرز ان ہیڈرز کے ساتھ ایمبیڈ بلڈ فراہم کرتے ہیں۔ `static` اڈاپٹر انہیں `_headers` میں لکھتا ہے، جسے Cloudflare Pages اور Netlify پڑھتے ہیں۔ کسی بھی دوسرے ہوسٹ، مثلاً اسٹوریج بکٹ یا سائٹ کے اپنے `public/` فولڈر پر انہیں خود سیٹ کریں:

<!-- s:be81a4c5ec -->
| پاتھ | ہیڈرز |
| :-- | :-- |
| `/embed.js` | `Cache-Control: public, max-age=0, must-revalidate` |
| `/assets/*` | `Cache-Control: public, max-age=31536000, immutable` |
| دونوں، جب سائٹ دوسرے اوریجن پر ہو | `Access-Control-Allow-Origin: *` اور `Cross-Origin-Resource-Policy: cross-origin` |

<!-- s:21eb7dc287 -->
براؤزر ماڈیول اسکرپٹس اور WebAssembly کو CORS کے ساتھ حاصل کرتے ہیں، اس لیے دوسرے اوریجن کی فائلوں کو `Access-Control-Allow-Origin` درکار ہوتا ہے۔ `yoga-[hash].wasm` کو کمپریس کر کے `application/wasm` کے طور پر فراہم کریں ([WebAssembly](/docs/deploying#webassembly) دیکھیں)۔

<!-- s:1bb976fcdc -->
ڈیپلائیز

<!-- s:01b888e293 -->
ہر بار صفحہ لوڈ ہونے پر `embed.js` کی دوبارہ توثیق ہوتی ہے، اس لیے نئے وزیٹرز کو نیا ڈیپلائے فوراً ملتا ہے۔ جس ٹیب نے پچھلا `embed.js` لوڈ کیا تھا، وہ وزیٹر کے کونسول کھولنے پر پچھلی بلڈ کی فائلیں ہی امپورٹ کرتا ہے، چاہے کئی گھنٹے گزر چکے ہوں۔ پچھلے ڈیپلائے کا `assets/` آن لائن رکھیں: حذف کرنے کے ساتھ سنک کرنے کے بجائے نئی فائلیں پرانی فائلوں پر کاپی کریں، اور ایک یا دو دن بعد پرانی فائلیں ہٹائیں۔ کسی بلڈ کو پن کرنے کے لیے، اس کا `assets/embed-[hash].js` ٹیگ میں رکھیں۔ اس بلڈ کی فائلیں بھی آن لائن رہنی چاہییں۔

<!-- s:b748b07652 -->
جب فائلیں موجود نہ ہوں، تو `embed.js` ایک انتباہ لاگ کرتا ہے جو وزیٹر کو دوبارہ لوڈ کرنے کا کہتا ہے، اور خود صفحے کو شروع یا دوبارہ لوڈ نہیں کرتا۔

مواد کی سیکیورٹی پالیسی

<!-- s:de8e30a920 -->
`embed.js` کو ان لائن اسکرپٹس یا اسٹائلز کی ضرورت نہیں ہے۔ میزبان صفحے کی پالیسی میں یہ شامل کریں، اور جب `dist/` اسی اوریجن پر ہو تو اوریجن کی جگہ `'self'` رکھیں:

<!-- s:2da4077ce0 -->
| ڈائریکٹو | قدر | استعمال |
| :-- | :-- | :-- |
| `script-src` | `https://console.example.com` | `embed.js` اور اس کے چنکس |
| `script-src` | `'wasm-unsafe-eval'` | کلائنٹ پر رینڈر شدہ ایپس میں Yoga |
| `connect-src` | `https://console.example.com` | `yoga-[hash].wasm`، اور سرور پر رینڈر شدہ روٹس کے لیے `/__textjs/live` |
| `img-src` | `data:` | صرف ایسا `<text-console mirror>` جس کی ایپ `<Image>` یا `<Pixels>` ڈرا کرتی ہو |

<!-- s:4ce5dcc4cb -->
ایپ خود لوڈ کرنا

<!-- s:03e56a60b4 -->
جو صفحات ایپ کو اپنے طریقے سے لوڈ کرتے ہیں، ان کے لیے `@textjs/app/experimental` وہ حصے ایکسپورٹ کرتا ہے جن سے `embed.js` بنا ہے:

<!-- s:238cbf53ee -->
| ایکسپورٹ | تفصیل |
| :-- | :-- |
| `startEmbed(paint, boot, src, element?)` | وہ عمل جو `embed.js` چلاتا ہے: پہلا فریم لاگ کریں، کونسول استعمال کرنے کے ارادے کا انتظار کریں، پھر `boot` کال کریں |
| `bootEmbedClient(options)` | اِن میموری روٹنگ اور صفحے کے لیے مشروط کی بورڈ اِن پٹ کے ساتھ کلائنٹ پر رینڈر شدہ ایپ شروع کریں |
| `bootEmbedPlayer(options)` | سرور پر رینڈر شدہ روٹ کے لیے فریم پلیئر شروع کریں |
| `createHostInput(options)` | کی بورڈ اِن پٹ جو اوپر دیے گئے اصولوں پر عمل کرتا ہے |
| `createTextConsoleMount(config)` | `<text-console>` کے لیے `mount(element, shell?)` فنکشن لوٹاتا ہے |
| `reserveCss(cols, rows)` | وہ CSS جو `<text-console>` کی جگہ محفوظ رکھتی ہے |

<!-- s:f15b990353 -->
`ENGAGE_SELECTOR` اور `BYPASS_SELECTOR` ان ایلیمنٹس کے سلیکٹرز ہیں جو ایپ شروع کرتے ہیں اور ان ایلیمنٹس کے جو اپنی کیز اپنے پاس رکھتے ہیں۔
