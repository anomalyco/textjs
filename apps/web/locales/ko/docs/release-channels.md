<!-- s:b808ed6cd6 -->
Text.js는 npm dist-tag 3개로 배포해요. 모든 패키지(`@textjs/app`, `@textjs/react`, `@textjs/core`, `@textjs/font`, `@textjs/opencode`, `create-text-app`, `eslint-plugin-textjs`)의 버전을 함께 올리므로, 버전 번호 하나가 프레임워크 전체를 나타내요.

<!-- s:a2c3664770 -->
채널

<!-- s:6b5c5ba172 -->
| 채널 | dist-tag | 버전 | 설치 |
| :-- | :-- | :-- | :-- |
| 안정 | `latest` | `1.0.x` | `bun add @textjs/app` |
| 카나리 | `canary` | `1.0.x-canary.N` | `bun add @textjs/app@canary` |
| LTS | `lts`, `v1-lts` | `2.0.0` 출시 후 배포 | `bun add @textjs/app@lts` |

<!-- s:27e8b81dc6 -->
프로덕션에서는 안정 버전을 사용하세요. 수정 사항과 기능이 `dev`에 반영된 날 바로 사용해 보려면 카나리 버전을 사용하세요. LTS 계열이 생기면, 1년에 한 번 업그레이드하는 경우 LTS를 사용하세요.

<!-- s:abc686bd76 -->
안정 버전

<!-- s:df32c144c0 -->
안정 릴리스는 [유의적 버전](https://semver.org)을 따라요: 패치 버전은 버그를 수정하고, 마이너 버전은 하위 호환 기능을 추가하며, 메이저 버전은 사용 중단 예고 기간 후 API 호환성을 깨뜨릴 수 있어요. 안정 릴리스는 전체 테스트 모음을 통과한 카나리 버전에서 승격되며, npm 출처 증명과 함께 배포돼요.

<!-- s:7307c50761 -->
카나리

<!-- s:db409040ca -->
공식 저장소의 `dev`에 푸시할 때마다 타입 검사와 테스트를 거쳐 `-canary.N` 접미사가 붙은 다음 패치 버전으로 배포돼요:

<!-- s:d8b8cffefe -->
| `latest` | `dev` 푸시 | 배포 버전 |
| :-- | :-- | :-- |
| `1.0.0` | 첫 번째 | `1.0.1-canary.0` |
| `1.0.0` | 두 번째 | `1.0.1-canary.1` |
| `1.0.1` | 다음 | `1.0.2-canary.0` |

<!-- s:dd9c67b1f5 -->
`N`은 npm에 이미 배포된 가장 높은 카나리 번호에서 이어지므로 번호가 반복되지 않아요. 카나리 버전은 저장소에 커밋하지 않아요. 릴리스를 건너뛰려면 커밋 메시지에 `[skip canary]`를 추가하세요.

<!-- s:762894d754 -->
카나리는 모든 풀 리퀘스트가 병합되는 브랜치인 `dev`의 빌드예요. 미출시 API가 사전 안내 없이 변경되거나 제거될 수 있어요. 카나리 버전에 의존한다면 정확한 버전을 고정하세요.

<!-- s:6999c4e986 -->
출처 증명

<!-- s:18722b1d6c -->
릴리스는 GitHub Actions에서 `npm publish --provenance`로 배포하며, 각 타르볼을 빌드한 정확한 커밋과 워크플로에 연결해요. 패키지를 검증하려면 다음 명령을 실행하세요:

<!-- s:57d2e7b18d -->
릴리스 만들기

<!-- s:a3217d58a6 -->
유지 관리자는 릴리스 스크립트로 모든 워크스페이스 패키지의 버전을 함께 올려요:

<!-- s:614a1ea872 -->
`release:version`은 각 `package.json`과 해당 버전을 반영하는 상수(`VERSION`, 리컨실러의 `rendererVersion`)를 다시 쓰고, 패키지 간 버전이 달라지면 실행을 거부하며, `--dry-run`은 실행 계획을 출력해요. `release:publish`는 빌드하고, 패키징하고(`workspace:*` 해석), `publishConfig`를 적용하고, 프리릴리스를 `latest`에 게시하거나 안정 버전을 `canary`에 게시하는 것을 거부하고, npm에 이미 있는 버전은 건너뛰어요.

<!-- s:ec6955472a -->
각 릴리스 계열의 유지 관리 기간은 [지원 정책](/docs/support-policy)을 참고하세요.
