`text run`은 같은 앱을 터미널에서 실행해요. 레이아웃, 컴포넌트, 키맵과 라우트 핸들러를 공유하고, 출력에는 `%c` CSS 스팬 대신 트루컬러 ANSI를 사용해요.

<!-- s:eed3d00ac7 -->
`text run`

<!-- s:7cd876942b -->
스크립트를 추가하고 실행하세요:

<!-- s:ad1db08664 -->
`text run`은 `app/`의 모든 파일을 가져오고, 메모리 내 히스토리로 App Router를 마운트해 전체 화면에 그려요. `<Link>`, `useRouter()`, `notFound()`, `redirect()`는 그대로 작동하고, 동일 출처의 `fetch("/api/…")` 호출은 같은 프로세스에서 라우트 핸들러를 실행해요. `Ctrl+C`는 앱을 종료하고 스크롤 기록을 복원해요. Bun이 필요해요.

<!-- s:86d6034750 -->
`q`로 종료

<!-- s:f06966bd5c -->
터미널 사용자는 `q`로 종료하기를 기대해요. `useApp().exit()`는 앱을 언마운트하고 터미널을 복원해요. 브라우저에서는 콘솔 앱을 언마운트해요.

<!-- s:62111506f4 -->
나만의 CLI

`bun cli.tsx`로 실행하세요. `DeploymentsPage`는 행 데이터를 가져오므로 `text run`이 필요해요.

차이점

터미널은 더 빠르게 다시 그리며(약 15fps 대신 최대 60fps), 도킹된 콘솔 대신 창 크기에 맞춰 그리드 크기를 정해요. 이미지에는 URL 대신 픽셀 데이터가 필요해요. 이 대시보드를 포함한 나머지는 모두 같은 코드를 사용해요.
