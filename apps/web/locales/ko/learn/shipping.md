`text build`는 정적 클라이언트를 생성하고, 라우트 핸들러가 있으면 `text start`용 서버도 생성해요.

<!-- s:b09ff23eb8 -->
빌드

<!-- s:34d9f1bf54 -->
`text start`는 빌드 결과를 제공하고 라우트 핸들러를 실행해요. Bun 1.2+ 또는 Node.js 22+가 있는 모든 호스트에서 실행돼요.

<!-- s:5f36ef31f1 -->
Metadata

<!-- s:c6b213e15a -->
루트 레이아웃에서 브라우저 탭 제목을 설정하세요. 페이지에서 이 값을 재정의할 수 있어요.

<!-- s:0467501ecc -->
정적 호스팅

<!-- s:f5f06a38ae -->
라우트 핸들러가 없으면 빌드 결과는 일반 정적 사이트예요. 각 정적 라우트에는 별도의 HTML 파일이 생성돼요. `/deployments/[id]` 같은 동적 라우트는 `index.html`로 제공돼요.

<!-- s:c33282e322 -->
Vercel과 Cloudflare Pages에서는 `text build`가 플랫폼을 감지하고 해당 폴백을 직접 작성해요. 다른 정적 호스트에는 리라이트가 필요해요. Netlify에서는 `public/`에 `_redirects` 파일을 추가하세요:

<!-- s:ec502dd4e6 -->
Netlify는 규칙을 적용하기 전에 기존 파일을 먼저 제공하므로 에셋과 프리렌더링된 라우트는 영향을 받지 않아요.
